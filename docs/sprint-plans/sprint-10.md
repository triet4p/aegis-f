# Sprint 10 — Complete Mobile UI, UX and User Experience Redesign

## Sprint Goal

Replace the entire current frontend experience with a coherent, polished, mobile-first product. The owner reports that the current UI is unattractive and hard to use: stacking functional cards is not an acceptable information architecture. Use clearly labelled feature icons that open focused screens, understandable navigation and task-specific flows. This is a complete UI/UX redesign, not a color/theme refresh or another layer of cards over the existing screens. Preserve the increasingly stable backend and all supported user capabilities.

## Acceptance Criteria

- Every existing user-facing surface is inventoried and redesigned: entry/navigation, dashboard and ledger drill-down, capture/chat/history/event/link flows, draft queue/detail/confirmation, manual entry/correction, categories/rules, provider/model/skills settings and notification/privacy settings. No legacy screen is left behind merely because it is secondary or rarely visited.
- Labelled feature icons open dedicated screens with a clear purpose and primary action. Provide an explicit screen hierarchy, predictable Back/Up and system-back behavior, state restoration and discoverable secondary destinations. Do not force multiple unrelated workflows into a vertically stacked card dashboard. Contextual cards/lists are allowed when they serve a specific task; icon-only mystery navigation is not.
- Owner clarification: **one screen, one clearly defined task and one primary action**, across the whole app. Avoid stacking unrelated functional components even when each block looks polished. Home is primarily a task launcher; note entry saves a note, AI Chat handles conversation, inbox selects work, draft detail reviews one draft, and reports inspect financial scope with drill-down. Secondary workflows open focused child screens or contextual sheets. Maintain a screen-purpose / primary-action / secondary-route matrix and demonstrate the separation in the prototype, not just in prose; a scrollable list of homogeneous task items is not prohibited.
- Research examines MoMo, VietinBank iPay and additional relevant mobile products using cited, dated, publicly accessible sources and screenshots where lawful. Distinguish observed behavior from inference and unavailable authenticated screens. Adopt useful navigation, hierarchy and interaction patterns, not logos, proprietary assets, payment/banking capabilities or unrelated super-app clutter.
- A complete design specification and linked interaction prototype cover all inventoried destinations and key states before feature-screen implementation. Exact destination count and visual system are decided through S10.1, not constrained by the former four-screen architecture.
- Visual consistency includes typography, spacing, color/contrast, icons, touch targets, amounts/status hierarchy, forms, charts, loading/error/empty/offline states and destructive/confirmation feedback. Support system insets, keyboard, scrolling, larger text, accessibility labels and non-color status cues on the actual phone.
- All supported capabilities and backend invariants survive the redesign. Exact VND totals, provenance, conflict-first review, hosted-versus-user category origin, revision checks, explicit financial confirmation, reversible links, masking/consent and offline manual paths remain authoritative. No new backend product features are implied.
- Users can discover and complete core tasks without developer knowledge or navigating raw operational/debug panels. Advanced configuration remains reachable but does not dominate everyday screens. Persisted and unsaved state, applied effects, cancellation and recovery feedback are truthful.
- Owner refinement for S10.1: AI must have a dedicated, discoverable conversation screen with incrementally streamed assistant replies, not only an action on the quick-note composer. Keep local note saving distinct from starting AI, retain conversation/history navigation, and specify visible waiting/streaming/tool-working/completed/stopped/error states, composer/Stop behavior, scrolling and keyboard handling. The prototype demonstrates streaming with clearly identified synthetic responses; production egress still requires the existing explicit consent, masking and application authority. No hidden reasoning or raw internal tool transcript is exposed as chat content.
- Actual rendered phone evidence and observed interactions prove the redesign. Compare the same seeded tasks before/after using observed taps, navigation mistakes and completion outcomes; report observer/worker overhead and do not claim human speedup without human evidence. Numeric usability targets require measurement conditions and approval, not invented gates.
