# Sprint 10 — Recovery, Privacy and Personal Daily-Use Release

## Sprint Goal

Deliver a privately signed Android release whose four-screen capture/review/agent workflow remains correct through backup, restore, upgrades, offline use and model/resource failures. Preserve all recovery obligations of the former Sprint 6 release plan.

## Status and Dependencies

- Status: Planned. Dependencies: Sprints 5–9 acceptance and technical gates, plus accepted Sprints 1–4 behavior, interpreted under [Sprint 8 CAT1](../hosted-category-cutover.md) (`165376fe`). Hosted category selection and local review validation replace active Laya; historical classifier evidence is not an active runtime dependency.
- Workflow: **Full**. Each **S10.1–S10.10** task requires independent evidence PASS and a separate Bronze-only exact-snapshot checkpoint before the next independent task; then assigned final cross-feature differential review and one consolidated user daily-use acceptance pass. No shared batch assumed approved. Explicit role/checkpoint/commit authority required; no automatic push/store publication.
- Worker/reviewer direct ADB permitted with privacy-safe fixtures and user-data preservation. Use isolated test packages/runners; never let instrumentation cleanup uninstall or clear the owner's main app. CAT1's development-data restoration waiver does not waive future preservation or migration gates. Evidence root: `artifacts/sprint-10/`.

## Acceptance Criteria

- Versioned export/restore preserves categories, rules, exact ledger, drafts, source provenance, saved captures/events/links, user corrections, non-secret model-profile descriptors and review/category identity. Retained historical classification snapshots remain provenance only, never active confidence or hosted decisions. Credentials, reversible mappings, provider buffers/cache handles, OTP/unrelated notifications and transient prompts/reasoning are not backup contents; removed model weights/runtime are not restored.
- Corrupt/unsupported backups and failed migration cannot partially overwrite live data. Full replacement requires user confirmation and a recoverable pre-restore copy; restore cannot replay old agent mutations or re-confirm transactions.
- Privacy policy matches actual local storage, explicit hosted-inference consent, masking/minimization, selected endpoints, retention and Android OS backup/data-extraction configuration. No automatic cloud financial backup; credentials and reversible mappings never leave their local boundary. Masking is not a guarantee of anonymity.
- A stable same-package/same-key release update preserves the populated previous release/schema. No uninstall of the user's only data copy to hide signature/migration failures.
- Four screens and the complete note/notification/hosted-category/agent/review/dashboard workflow run on the actual phone with configured hosted providers. Ledger, dashboard, capture, intake, manual category selection and review remain usable offline; hosted interpretation/category selection is unavailable without network and a valid key. No on-device classifier or hidden provider fallback. Disclose network, capability and provider failure limits.
- Measured workflow effort and inference latency/resources are reported with dataset, cold/warm state and sampling limitations. No promises of statistical accuracy, calibrated confidence or battery performance without supporting evidence.

- Backup/release is not reduced because agent work expanded. Existing data and private signing remain essential.
- No public distribution, cloud sync or automatic push. Durable captures are intentional financial records; a claim of no raw chat logs must not conceal their actual storage/backup behavior.
