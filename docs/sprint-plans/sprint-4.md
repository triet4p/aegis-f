## Acceptance Criteria

- The pinned English Laya checkpoint/export and tokenizer run through ONNX Runtime Android on the phone, offline, without requiring a desktop inference server.
- Android decisions match the reference preprocessing/decision semantics within documented numerical tolerance; temperature/calibration is applied correctly rather than labeling raw logits as probabilities.
- Suggestions use stable category IDs and current active category metadata, not fabricated/free-form IDs or names.
- The app imposes no category-count cap: candidate selection respects the runtime token budget, preserves an unknown/no-fit outcome, and never silently truncates an oversized request.
- Ambiguous/no-fit inputs remain reviewable and manually categorizable. No model result silently confirms or changes a financial record.
- A labeled English evaluation records suggestion quality, incorrect confident decisions, candidate retrieval misses, cold/warm latency, and peak process memory on the actual phone. Device/model adoption is based on observed evidence, not published GPU numbers.
- S4.10: Manual expense entry and bank-draft review display real per-category probabilities plus unknown for deliberate choice, with accurate confidence semantics and explicit subset/omitted scope for oversized catalogs. No vocabulary whitelist, ASCII-only, language-detection or arbitrary English eligibility filter may block nonempty user descriptions/notes, including `buy lunch` and Vietnamese text. English preference is advisory only; blank input, runtime token limits and genuine OTP/security protections remain distinct, truthful conditions, not disguised language gates. Show immediate, accessible loading text and visible indeterminate progress during model initialization/inference (no fake percentage), then results/error/manual states. Rules remain labeled separately with no fabricated model scores; low confidence/unknown wins must not hide evaluated distributions. Keep note separate/non-persisted, no automatic financial confirmation.
- S4.11: Offer explicit permanent category deletion, distinct from archive, with confirmation explaining impact. Preserve financial records, amounts and summaries; safely clear affected category references rather than delete transactions, remove dependent correction rules, and invalidate pending/stale suggestions. Verify unused and referenced categories, cancel, persistence after reopen, and absence from subsequent choices. Phone smoke deletes only disposable worker-created categories, never existing user categories.
