## Acceptance Criteria

- One note can produce several source-backed editable event interpretations without creating expenses, inventing missing financial fields or copying every event into every draft.
- Resolve relative times against the note's capture timestamp/timezone; distinguish event time, bank transaction time and notification receipt time. Preserve ambiguity instead of selecting an arbitrary day/period. Optional-language limitations are visible; manual split/link remains available for any input.
- Candidate retrieval is bounded and deterministic against the actual app API. Missing matches, multiple plausible candidates and amount/type/account/time conflicts do not produce silent attachment.
- Automatic attachment, where enabled by explicit app policy, changes only reversible draft context and requires a unique evidence-supported match; model certainty or category choice does not authorize it. Proposed/automatic/manual links are visibly distinguished.
- Within the explicitly started hosted workflow, the model sees current category choices and relevant masked context, then saves one existing category through `update_draft_review`; local identity, scope, revision and live-catalog validation remain authoritative. No separate classifier, category-only tool round-trip or model confidence score is required. Review orders unresolved link/data conflicts first, then missing category, then ready drafts; category selection never resolves an uncertain match or confirms a transaction.
- User correction, rejection, note edit/deletion, link undo and process restart cannot silently duplicate events/links/ledger entries or override previously confirmed financial facts.
- User-facing Chat reports actual saved events, applied/proposed links, unresolved questions and completed versus cancelled operations, not fabricated success or a verbose raw tool transcript.

## Decisions / Boundaries

- No autonomous ledger confirmation or dismissal. The agent may save an existing category as pending draft-review state under CAT1; it cannot authorize financial changes, and category choice is not match evidence or confirmation.
- Already manually recorded note events are excluded from automatic attachment. A later matching bank draft is a possible duplicate for user review, not a reason to re-record, silently merge or remove the prior ledger entry.
- A single bank notification representing several purchases, split-payment allocation or multiple drafts jointly settling one note event requires explicit manual reconciliation. Do not invent automatic split/group support or silently lose unmatched residual events in this delivery.
- Conversational ledger Q&A and generic device automation are not prerequisites. Chat exists to reduce capture/review work.
- Hosted inference uses Sprint 8 provider/key consent, local masking, neutral-token handling and tool/public-output guards. CAT1 removed active Laya runtime, provisioning and translation; historical classification snapshots remain provenance only and never drive current category decisions or queue priority. Use synthetic fixtures for external development trials. General coding-agent capabilities and local model provisioning are outside this roadmap.
- Owner prohibits further DeepSeek Pro usage for this work, including probes, retries and fallback. Authorized direct-provider verification uses Flash only, with the serialized model checked before any external request; no silent model substitution.
- Owner requires observation-driven phone verification: read the current screen and actual clarification before responding; no scripted fixture answers or automated conversation branches. Synthetic data is for privacy and reconciliation only. Manual and assisted comparisons must use the same actual scenario, with catalog gaps handled truthfully through normal UI rather than forcing an incorrect category.
