## Acceptance Criteria

- Bank description, saved user capture and manual annotation remain distinguishable source evidence; no inference overwrites the original bank text or user edits.
- One saved note can own several event interpretations, each with stable identity/source span, optional time/amount and unresolved status. Notes can exist without a notification or ledger transaction.
- Context associations have explicit proposed/accepted/rejected state and safe cardinality; rejected/ambiguous links are not silently recreated. Confirmed/dismissed draft lifecycle is separate from link and inference states.
- A shared typed application layer serves UI and future agent adapters with the same business validation. Trusted caller scope, expected revisions and idempotency prevent unauthorized or duplicate mutations.
- Existing data upgrades without destructive fallback, invented provenance, lost categories/rules/drafts or changed exact ledger totals; manual/category/intake behavior still works.
- Financial confirmation is user-only and transactional. Agent scope permits bounded reads and reversible preparation, never arbitrary SQL, final ledger writes/deletes or hidden financial edits.

## Decisions / Boundaries

- No SLM runtime, new dashboard redesign, automatic reconciliation or benchmark expansion in this sprint. The migration/API foundation must precede them.
- Capture text is intentionally saved business data; model prompts/tool traces remain ephemeral. Preserve only required audit metadata and user-visible evidence, not hidden reasoning.
- Every task that changes Room schema ships its own migration and populated-data upgrade smoke before its evidence/checkpoint gate. Migrate affected callers with each API change; no task may leave the app unlaunchable until S5.8.
- Link confidence and Laya category confidence are different; this sprint establishes their data separation, not unmeasured scoring thresholds.
