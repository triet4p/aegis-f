# Sprint 8 model and phone-runtime research (S8.1)

**Evidence snapshot:** 2026-10-25. This is a source-backed trial shortlist, not a selected/shipping profile. Upstream capability claims are not device measurements; old Sprint 5 parser/prompt scores are not model-quality evidence for Sprint 8.

## Decision summary

- **Primary feasible next physical-phone candidate (after S8.2 freezes the suite):** official `openbmb/MiniCPM-V-4.7-1B` GGUF Q4_K_M is a credible ARM64 CPU trial candidate: exact official GGUF repository, model template, Apache license, Android deployment claim and artifact identity are verified. The existing Sprint 5 harness proves Android llama.cpp CPU trial mechanics only for prior candidates; no MiniCPM trial or Aegis in-process integration was performed. Preserve visual capability as optional; tool trials are text-only first.
- **Alternative agentic-format profile and LiteRT path:** official Gemma 4 E2B-it via the official LiteRT-LM Android Kotlin API and `.litertlm` artifact. Native tool-call template/arguments and exact file integrity metadata are verified. LiteRT has CPU and GPU backends, but the supplied Qualcomm QCS8275 NPU artifact is not shown compatible with this handset's SM6225; do not use it. Generic CPU is the only prudent first path; actual app integration, available storage and model-load headroom remain trial prerequisites. The published Android speed/memory sample is on another phone and is not transferable.
- **Prior Qwen alternative:** `Qwen/Qwen3.5-0.8B` (Apache-2.0) and the third-party `unsloth` Q4_K_M conversion have documented historical Android CPU/KleidiAI execution and SHA-256. This gives a reproducible reference/alternative trial, not adoption. Sprint 5 evaluation has known parser, prompt-contract and rubric defects; do not reuse its scores as model capability or claim the profile qualified.
- **Not trial-ready on this phone as scoped:** `prism-ml/Ternary-Bonsai-2` is not an available repo identity (Hub page returned HTTP 401); exact public derivative repos exist for 4B and 9B. They offer compact packed GGUF files, but parameter compute remains ~4.21B / ~8.95B language parameters (plus vision towers). The documented Prism fork backend list is CUDA/Metal/CPU; no official Android ARM64/Vulkan integration or this phone's tested support was established. Keep both behind a prerequisite to demonstrate a compatible in-process Android build/runtime and memory admission. Do not confuse packed weight bytes with model compute.
- **LFM is instruct/tool-syntax only, not the agent-capable profile:** current LFM2.5-350M is a text-only instruct model with a Python-like tool-call string and custom license; runtime support does not prove suitability for the bounded multi-step agent. Keep it visibly restricted to an optional simple extraction/naming comparison, never agent-routed.

## Decisions and prerequisites

1. Freeze the S8.2 workflow cases and exact tool schema/template parity before any new model generation. Existing prompt/parser scores remain excluded.
2. The first low-risk, well-pinned CPU trial can use MiniCPM official Q4_K_M GGUF; include model and projector only if the frozen case needs vision. Compare with a corrected-contract Qwen reference as the relevant alternative. Gemma LiteRT-LM is the dedicated alternative runtime/profile, pending target-phone memory/storage and Aegis in-process dependency check.
3. Trial input languages must include the required English baseline and optional Vietnamese cases. No model's vendor language claims substitute for task-specific evidence.
4. Record every future tested path by runtime revision, artifact revision + per-file SHA-256, hardware/backend actually selected, app/process memory metric, prompt and case hashes, native template, exact tool arguments, raw outputs and known parser defects. Keep those records separate from source-backed claims.
5. Unknown prerequisites remain explicit: exact MiniCPM active-vs-total parameter accounting and authoritative language guarantee; MiniCPM projector size/hash for selected flavor; current free storage / safe app load headroom under representative background conditions; Vulkan features and OpenCL availability; generic LiteRT GPU match; SM6225 NPU support; any MiniCPM or Gemma actual in-process Aegis run.
