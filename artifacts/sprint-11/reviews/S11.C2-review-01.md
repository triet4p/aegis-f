## 1. Executive Summary and Scope

Round 1 assesses candidate `S11.C2-a1` submitted by `ChatC2` for task S11.C2. The review independently evaluates retry eligibility checking, journaled mutation reconciliation, duplicate bubble prevention, continuation preservation for clarifications, Compose chat behavior, and isolated physical-device proof against `docs/sprint-plans/sprint-11.md:44` and investigation T6:

1. **Admission precedes transcript changes:** `AgentRunHistory.retryAdmission` inspects durable database state (`agent_runs` and `agent_run_attempts`) before any transcript entry is added or modified. The decision evaluates the current durable attempt, attempt allowance (`current + 1 <= MAX_ATTEMPTS`), persisted retry classification, and journal evidence of applied effects.
2. **Truthful no-Retry UI:** The Compose Chat screen shows the Retry action only when `ChatAgentRunState.retryOffer` is present. An exhausted run (`ATTEMPTS_EXHAUSTED`), terminal rejection (`TERMINAL`), or possibly applied mutation (`POSSIBLY_APPLIED`) offers no dead-end Retry button. Instead, the existing failure line is updated in place with specific, truthful copy. An in-progress run reports `STILL_PROCESSING` without racing retries.
3. **No duplicate user bubbles:** An admitted retry turn (`ChatAgentRunState.beginRetryTurn`) appends exactly one assistant waiting entry. The user's original message or clarification answer already resides in both transcript state and durable conversation history; pressing Retry never duplicates user bubbles. A refused retry rewrites the existing status line in place and appends nothing.
4. **Current-attempt per-tool journal key reconciliation:** `reconcileUncertainWrite` resolves the actual per-tool `operationKey` values dispatched by the attempt from recorded tool results (`<attemptKey>:record`, `<attemptKey>:propose`, etc.), with a bounded session-scope fallback (`WorkflowQueryService.workflowOperationsForScope`) when tool results are unrecorded. Bare attempt-key lookups (which never matched mutation journal entries) are eliminated.
5. **Possibly-applied effect detection:** Any attempt that recorded an `APPLIED` outcome or whose dispatched calls produced unrecorded/uncertain results blocks replay as `POSSIBLY_APPLIED`, protecting against double mutations. Clean retryable failures without applied effects remain recoverable.
6. **Clarification retries continue the same answer:** A failed clarification continuation preserves its clarification mode across failure settles. An admitted retry routes to `BoundedWorkflowExecutor.retryClarificationTracked`, which re-issues the suspended continuation with the exact same answer without replaying the original request or re-recording duplicate conversation lines.
7. **C1 contract preservation:** S11.C1 semantics (12 tool calls per turn limit, fresh allowance per turn, unlimited conversation turns, and clarification continuations beyond `MAX_ATTEMPTS = 3`) remain intact without regression.
8. **Scope isolation:** Foreign modifications in `docs/PLAN.md` and `docs/sprint-plans/sprint-11.md` are excluded from the candidate snapshot manifest; S11.C3 natural date grounding remains scheduled separately.

## 4. Acceptance Criteria Verification (Observed)

### A. Retry Admission Checked Before Transcript Mutation
- **Contract & Implementation:** `AgentRunHistory.kt:543` defines `retryAdmission(scope, runId): RetryAdmission`. It evaluates the durable run row (`agent_runs`), the attempt row (`agent_run_attempts`) for `stored.attempt`, attempt limits (`current + 1 <= CanonicalAgentRetryPolicy.MAX_ATTEMPTS`), persisted retryability, and operation journal reconciliation.
  - In `AiChatScreen.kt:316`, `admitRetry(runId)` runs when an incomplete turn settles. If admission returns `RetryAdmission.Ready`, `agentRunState.retryOffer` is set. If blocked, `agentRunState.refuseRetry(...)` is called.
  - In `AiChatScreen.kt:612`, `retryLast()` verifies `agentRunState.retryOffer != null`, re-evaluates `retryAdmission` under coroutine lock, and only calls `agentRunState.beginRetryTurn()` after confirming `RetryAdmission.Ready`.
- **Evidence:**
  - `ChatTranscriptStateTest.kt` (`a refused retry rewrites the existing failure line and appends nothing`): verifies message count does not increase and status line is updated in place.
  - `S810DurableRunHistoryTest.kt` (`an in-progress run reports that it is still being processed`): verifies `RetryAdmission.Blocked(RetryBlockReason.STILL_PROCESSING)`.

### B. Truthful No-Retry on Exhausted and Terminal Runs
- **Contract & Implementation:**
  - `AgentRunHistory.kt:558`: `if (current + 1 > CanonicalAgentRetryPolicy.MAX_ATTEMPTS) return RetryAdmission.Blocked(RetryBlockReason.ATTEMPTS_EXHAUSTED)`.
  - `AgentRunHistory.kt:574`: `if (!retryable) return RetryAdmission.Blocked(RetryBlockReason.TERMINAL)`.
  - `AiChatScreen.kt:937`: the Compose UI renders the Retry button only if `agentRunState.retryOffer != null` and actionable. For exhausted or terminal runs, `retryOffer` is null, so the button is not displayed.
  - `ChatStrings.kt:219, 299`: EN/VI copy provides explicit text: `"This run has used all of its attempts. Start a new message to try again."` / `"Lượt chạy này đã dùng hết số lần thử. Hãy gửi tin nhắn mới để thử lại."`.
- **Evidence:**
