## 4. Acceptance Criteria Verification (Observed)

### A. Exactly 12 Tool Calls Per Turn, 13th Blocked
- **Contract & Implementation:** `BoundedWorkflowExecutor.kt:138` defines `WorkflowRunLimits(val maxToolCalls: Int = 12, ...)`. In `dispatchTurn` (lines 1246–1260), remaining turn allowance is calculated as `(run.request.limits.maxToolCalls - run.toolCalls).coerceAtLeast(0)`. Calls up to allowance execute; any excess call in that turn generates a non-dispatched error envelope:
  ```json
  {
    "outcome": "error",
    "dispatch": "not_dispatched",
    "error": { "code": "TOOL_CALL_BUDGET", "issues": [{ "path": "$", "constraint": "per_turn_tool_call_limit", ... }] }
  }
  ```
  The turn stops with `WorkflowRunStopReason.TOOL_CALL_BUDGET` after all calls have answers, leaving the conversation idle.
- **Evidence:**
  - `BoundedWorkflowExecutorTest.kt` (`one turn permits exactly twelve tool calls and refuses the thirteenth`): single turn with 13 calls dispatches 12 and refuses 1 with `AgentErrorCode.TOOL_CALL_BUDGET`, stopping with `WorkflowRunOutcome.Incomplete`.
  - `S105ChatInstrumentedTest#perTurnToolLimitPausesAndTheNextMessageContinuesTheSameRun` on physical device `ALT-LX2 - 14`: XML `TEST-ALT-LX2 - 14-_app-.xml` records 12 dispatched calls and 1 refused call on Compose UI.

### B. Allowance Restarts on Every User Message / Clarification Answer
- **Contract & Implementation:** `ActiveRun.beginPhase(startedAtMillis)` (lines 2304–2314) resets `turns = 0`, `toolCalls = 0`, `callCounts.clear()`, increments `phase`, and resets `followUpMinted = false`.
  - In `resume(continuation, userAnswer, ...)` (line 918): invoked upon clarification answer.
  - In `followUp(followUp, userMessage, ...)` (line 1001): invoked upon user follow-up message.
- **Evidence:**
  - `BoundedWorkflowExecutorTest.kt` (`a paused turn continues the same session with a fresh allowance`): paused turn continues via `followUp(...)`, dispatching call 13 and settling with `Completed` (cumulative 13 calls).
  - `BoundedWorkflowExecutorTest.kt` (`a clarification raised at the tool limit resumes with a fresh allowance`): clarification raised after 12 calls resumes via `resume(...)`, dispatches call 13, and completes.

### C. Unlimited Conversation Turns (No Session Turn Cap)
- **Contract & Implementation:** `maxTurns` removed from `WorkflowRunLimits`. `TURN_BUDGET` removed from `WorkflowRunStopReason`. `drive(run)` turn loop has no turn-count bound. `mintFollowUp` mints a new handle for every settled turn.
- **Evidence:**
  - `BoundedWorkflowExecutorTest.kt` (`repeated user turns keep receiving a fresh allowance in one session`): runs 5 user turns (initial + 4 follow-ups) dispatching 16 calls across 9 provider turns in a single session without creating a new conversation.

### D. Clarification Continuation Beyond MAX_ATTEMPTS = 3
- **Contract & Implementation:** In `AgentRunHistory.kt:447`:
  ```kotlin
  if (stored.state != "CLARIFYING" && next > CanonicalAgentRetryPolicy.MAX_ATTEMPTS) return null
  ```
  Runs in `CLARIFYING` state are not capped by `MAX_ATTEMPTS = 3`. Failure retries from `FAILED` remain strictly capped.
- **Evidence:**
  - `S810DurableRunHistoryTest.kt` (`clarification continuations are not capped at the failure-retry attempts`): 5 consecutive clarification continuations execute (attempts 1 through 6) and settle in `SUCCEEDED` with 6 attempts recorded in `database.agentRunAttemptDao()`.

### E. Ordered Durable History & Distinction from Retries
- **Contract & Implementation:**
  - `AgentRunHistory.kt:254`: `recordAttemptOutcome` persists clarifying question as `AGENT` line.
  - `AgentRunHistory.kt:380`: `recordClarificationAnswer` persists user answer as `USER` line.
  - `AgentRunHistory.kt:481`: STATUS line reads `"The conversation continued after your answer (attempt $next)."` when `stored.state == "CLARIFYING"`, and `"The run was retried (attempt $next)."` otherwise.
- **Evidence:**
  - `S810DurableRunHistoryTest.kt` (`clarification question and answer are stored in order and the continuation is not a retry`): verifies question (`AGENT`), answer (`USER`), continuation STATUS, and restored transcript projection via `transcriptOf(...)`.

### F. Truthful Turn Limit Pause Copy & In-Place UI Continuation
