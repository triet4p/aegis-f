## Masking boundary finding (read before asserting)

The inherited boundary is layered and egress-only:

- The tool runtime mints neutral tokens itself when it builds an observation
  (`AgentToolRuntime.captureObservation` → `mask(...)`, `draftObservation`, `eventObservation`),
  so model-facing tool results already carry `⟦V-<scope>-nnnn⟧` tokens instead of raw values.
- The executor masks every tool result again (`MaskedPromptBoundary.maskToolResultJson`) before
  the continuation turn, and masks every follow-up/continuation message.
- Local storage keeps raw values for local validation; only egress is masked.

So "exercise masking through tool results" is evidenced by: tool-result payloads carrying tokens,
continuation request bodies carrying tokens, no raw fixture surface in any outbound body, and the
local raw amount still stored for local validation.

## In-scope defect found and fixed: English bare "d" dong shorthand

**Symptom (consumer-visible, preserved before the fix):** with the English note `Today fuel
50000d ... snack ... 20000d ...`, the model received the note with both amounts present as
neutral tokens, chose amount refs for its two `record_event` calls
(`record_event_amount_refs=[ref, ref, null, null]`), yet the stored readings had no amount and
the workflow asked the user for the amount ("the note's amount value there is not readable as a
dong amount").

**Discriminating local probe (no model calls, exact issued refs through production
`SensitiveVault.parseAmount`):** before the fix -
- VI `50.000đ` / `20.000đ` → tokens `numeric`, `parseAmount` = 50000 / 20000.
- EN `50000d` / `20000d` → tokens **`alphanumeric`**, `parseAmount` rejected (the surface matched
  the bank-code shape because the bare `d` is not in the unit list).
- EN `50,000d` → **not masked at all** (the grouped-number pattern needs a word boundary before
  the `d`), so that surface would leave the device raw; a privacy-boundary gap as well.
- EN `50000 VND` → `numeric`, parses correctly.
- `3d` → unmasked (correct: not money).

**Fix (minimal, existing boundary):** `SensitiveVault` now recognises the bare `d`/`D` dong
shorthand with `DONG_D_SUFFIX_PATTERN` and mints the **whole** matched surface (number + unit) as
one `numeric` value whose canonical is the whole-dong digits, placed before the bank-code shape so
it wins the overlap. The bare form requires four digits (so `3d` stays a duration); the grouped
form (`50,000d`, `50.000d`) is also masked. No fixture special-casing, no raw value to the model.

**After the fix (same probe):**
- EN `50000d` / `20000d` → `numeric`, `parseAmount` = 50000 / 20000.
- EN `50,000d` / `20,000 VND` → both masked, `numeric`, 50000 / 20000.
- VI `50.000đ` / `20.000đ` and `50000 VND` unchanged; `3d` still unmasked.

**Regression tests added** (`MaskedValueShapesTest`): English bare-`d` masks and resolves,
grouped `d` masks and resolves, short `3d` stays unmasked, `VND` spelling unchanged. The privacy
unit suite passes (`:app:testDebugUnitTest --tests "io.github.triet4p.aegisf.privacy.*"` BUILD
SUCCESSFUL) and the fixed app APK was rebuilt and installed on the isolated phone for the
end-to-end confirmation run.

Files changed for this fix: `app/src/main/java/io/github/triet4p/aegisf/privacy/SensitiveVault.kt`,
`app/src/test/java/io/github/triet4p/aegisf/privacy/MaskedValueShapesTest.kt`.
