## Implementation

Arrival of a source-backed note event or a permitted pending bank notification now durably enqueues bounded Room work in the same transaction as the arrival. Stable operation identities coalesce callback/command replay; expected event, capture, and review revisions make late work stale instead of reviving changed or terminal state. The coordinator serializes a bounded pending-operation queue, stores per-operation cursors and cumulative outcomes for page resumption, and runs on both arrival and application startup. Each processing page and link outcome commit together so process death leaves resumable work or a completed result.

The note and notification paths share the S9.3 trusted unique-evidence attachment policy. The local background scan is bounded to one shared pending page of up to 500 and remains `INCOMPLETE` above that boundary; this is separate from the hosted `AgentSession` first-32-id grant, which remains incomplete when it has more rows. Rejected, dismissed, confirmed, accepted, ambiguous, stale, or incomplete work cannot be auto-attached. Re-extraction keeps the event identity stable and generated output cannot overwrite user-edited interpretations. No notification source, amount, event text, review state, or ledger transaction is rewritten by reconciliation, and no financial confirm/dismiss action is introduced.
