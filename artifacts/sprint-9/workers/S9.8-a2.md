## Defect found and fixed (production change in this attempt)

**Symptom (observed on the real endpoint).** With `make_time_anchor`/`list_drafts`, the model sent
the *literal text* `"null"` for nullable string arguments (`end_date_ref`, `end_time_ref`, `cursor`,
and later `""`). The host correctly refused: `UNKNOWN_REFERENCE issued_in_this_run` /
`SCHEMA_INVALID nonblank`. Runs stalled at 0 events until the turn bound. This is the same failure
class as a1's lost `$.end_date_ref` argument; a2 preserved the exact argument text.

**Root cause.** `ProviderJson.applySingleType` collapsed every declared `["string","null"]` union to
`type: "string"` + `nullable: true` for OpenAI-compatible protocols. `nullable` is not a JSON Schema
keyword (it is an OpenAPI 3.0 / Gemini Schema field); OpenAI `parameters` is JSON Schema. The model
therefore received "required string" and had to spell absence as text.

**Fix.** The OpenAI lowering keeps the union as a JSON Schema type array
(`{"type": ["string","null"]}`); Gemini keeps its native `nullable`. The declaration, local
validator, authority checks and error codes are unchanged — a literal `"null"`/blank is still
refused, and no permissive coercion was introduced.

**Files.** `app/src/main/java/io/github/triet4p/aegisf/provider/ProviderJson.kt`;
`OpenAiChatCompletionsAdapterTest.kt`, `OpenAiResponsesAdapterTest.kt`,
`ToolArgumentValidationTest.kt` (contract assertions); `CHANGELOG.md` (Unreleased → Fixed).

**Proof.** Before/after serialized schema from real request bodies plus the model's change from
`"null"` text to real JSON null and both completed runs:
`evidence/S9.8-a2/01-nullable-contract.md`; traces `live-vi-grounded.trace.json` (before) and
`live-vi-schema-fix.trace.json` / `live-en-schema-fix.trace.json` (after).
