## Executive Summary

Task S9.7 delivers complete correction, undo, and confirmed-record boundaries across the capture, event, link, draft-review, and ledger lifecycles. The implementation establishes the following core invariants:

1. **Provenance and Retention Across Capture Amendment / Deletion:**
   - In `CaptureMessageRepository.kt`, revising or deleting a capture invokes `invalidateDerivedReadings(captureId, reason)`.
   - In `ContextLinkDao.kt`, `deleteActiveForCapture` deletes unconfirmed active links while strictly retaining links to confirmed drafts (`AND draftId NOT IN (SELECT id FROM pending_bank_drafts WHERE reviewStatus = 'CONFIRMED')`). Refused links (`state == 'REJECTED'`) are likewise preserved.
   - For retained links, the underlying event readings lose derived text/amount/time (`clearDerivedReading`), reporting `unresolvedReason = SOURCE_EDITED` or `SOURCE_DELETED` with status `UNRESOLVED` (or `NO_MATCH` if refused).
   - In `WorkflowQueryService.kt`, `draftContextLinks` evaluates `sourceCurrent = (excerpt != null)` and returns `sourceCurrent = false` and `excerpt = null` when the source text was changed or deleted, while preserving the link's stored canonical evidence, state, and revisions.
   - The confirmed financial record in `transactions` is never modified, rewritten, or deleted by any capture or link operation.

2. **Affected-Review Revalidation and Category Provenance (Room Schema v18):**
   - Room schema v18 adds `pending_bank_drafts.reviewCategoryOrigin` (`ReviewCategoryOrigin`: `NONE`, `USER`, `HOSTED`).
   - In `LedgerDatabase.kt`, `MIGRATION_17_18` alters the table with `DEFAULT 'NONE'`. Existing legacy databases upgrade in place; legacy rows are recorded as `NONE` because the prior schema did not record chooser provenance.
   - User review submissions (`WorkflowCommandService.saveDraftReview`) record `ReviewCategoryOrigin.USER` (or `NONE` if unresolved).
   - Hosted category selections (`WorkflowCommandService.selectDraftCategory`) record `ReviewCategoryOrigin.HOSTED` when called under `WorkflowCallerScope.AgentSession`.
   - Any context-changing mutation (capture revision/deletion, event reading revision, link proposal, acceptance, rejection, or unlink) calls `reopenHostedReviews(affectedDraftIds)`.
   - In `BankDraftReviewDao.kt`, `reopenHostedReviewCategory(draftId)` resets `reviewCategoryId = NULL`, `reviewCategoryResolved = 0`, and `reviewCategoryOrigin = 'NONE'` while incrementing `reviewRevision` by 1, strictly targeting `WHERE reviewStatus = 'PENDING' AND confirmedTransactionId IS NULL AND reviewCategoryOrigin = 'HOSTED'`.
   - User-chosen categories (`USER`) and legacy categories (`NONE`) are left untouched.

3. **Stale-Context Write and Undo Conflict Protection:**
   - A hosted write that observed a pre-edit or pre-undo context cannot mark a draft ready:
     a. Reopening the hosted review advances the draft's `reviewRevision`, causing CAS conflict on in-flight writes holding the old revision.
     b. `WorkflowCommandService.selectDraftCategory` validates `draftContextSnapshot` digest; any change to link state, link revision, or source revision changes the canonical dependency digest and yields `WorkflowCommandOutcome.Conflict`.
   - A stale link undo (holding an outdated link revision) is rejected with `WorkflowCommandOutcome.Conflict`.
   - A valid current undo unlinks the pair cleanly, but leaves any newer user category selection intact. A pre-undo hosted write attempting to complete after undo is rejected due to context snapshot digest mismatch.

4. **Confirmed Financial Record Immutability and Terminal Link Guards:**
   - All four link mutations (`proposeLink`, `acceptLink`, `rejectLink`, `unlinkLink`) in `EventContextRepository.kt` inspect draft status (`isConfirmedDraft` / `reviewStatus != PENDING || confirmedTransactionId != null`) and immediately reject attempts to mutate links to confirmed drafts with `ContextLinkResult.DraftAlreadyReviewed`.
   - `WorkflowCommandService.kt` maps this result to `WorkflowCommandOutcome.Denied(WorkflowDenialReason.CONFIRMED_RECORD)`.
   - In `AgentToolRuntime.kt`, `CONFIRMED_RECORD` throws `AgentToolException(LINK_INELIGIBLE)`.
   - In the UI (`QuickCaptureScreen.kt`, `QuickCaptureEvents.kt`, `ChatOutcomeCards.kt`), edit/delete dialogs explain the retention policy, cards hide the `Unlink` button on confirmed records, and state: *"This draft is a confirmed ledger record. The note reference is kept as provenance and the ledger is unchanged."*

5. **Safety Incident Audit and Scoped Fixture Verification:**
   - Worker disclosed an incident (`INCIDENT-DB-CLEAR.md`): during initial staging of `S97DeviceSurfaceInstrumentedTest`, `clearAllTables()` was called once on the persistent database (`aegis-ledger.db`) of the isolated test package `io.github.triet4p.aegisf.s812evidence`. The owner's main app (`io.github.triet4p.aegisf`) was never accessed, cleared, or uninstalled; no data restoration was fabricated or claimed.
   - Main required removing broad resets from the final fixture, scoping execution to unique seeded IDs only, and demonstrating safe verification.
   - Independent inspection of `S97DeviceSurfaceInstrumentedTest.kt` confirms that `clearAllTables()` and all file deletion calls were completely removed from the test execution logic. The corrected fixture seeds unique run IDs (`UUID`), stores its owned IDs in private SharedPreferences (`s97_device_surface_evidence`), and the `verify` stage asserts strictly those owned IDs.
   - The corrected fixture was built, installed via `adb install -r`, and passed on the physical device (`OK (1 test)` seed, `OK (1 test)` verify).

Independent verification confirms clean builds, complete JVM suites (573 tests, 0 failures, 3 live-smoke skips), clean Android lint (BUILD SUCCESSFUL, 0 errors), successful isolated APK assemblies (matching worker SHA-256 digests), physical phone instrumented execution with 3 test classes (2 boundary tests, 1 Compose review revalidation test, and 2 staged device surface test runs), and physical phone UI evidence with 20 PNG/XML records.
