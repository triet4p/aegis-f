## Executive Summary

Task S9.5 delivers complete orchestration from accepted event-draft linking to hosted category review to live review surface presentation. The implementation establishes the following core invariants:

1. **Same-Run Fresh Context & Category Choices:** When an event is interpreted, an event interpretation updated, or a link attached/changed within the active user-started hosted run, the tool response returns fresh draft observations for every affected draft in scope. Each draft observation carries its own current `category_choices` and masked `linked_context` (including masked reading text, amount, date, and merchant). Category choices are issued with `linkedSubjectKey = handle`, binding them strictly to their issuing draft observation.
2. **Atomic Transactional Validation:** Inside `WorkflowCommandService.selectDraftCategory`, five invariants are revalidated atomically within the Room database transaction:
   - Caller scope authorization: `scope.mayTouchDraft(request.draftId)`.
   - Draft review revision: `draft.reviewRevision == request.expectedReviewRevision`.
   - Draft context snapshot revision: for `AgentSession` callers, `request.expectedContextRevision == query.draftContextSnapshot(request.draftId).second`.
   - Category catalog revision: for `AgentSession` callers, `request.expectedCatalogRevision == categoryCatalogRevision(query.categoryCatalog())`.
   - Category assignability: `rules.categoryAssignable(request.categoryId)` ensures the category exists, is active, and is not archived.
3. **Stale Context & Newer User Edit Protection:** Any in-flight modification to the note capture source (`reviseCapture`), event interpretation, link state (`unlinkLink`), or a concurrent manual category selection by the user bumps either the draft's review revision or its context snapshot digest, causing in-flight automated writes to return `WorkflowCommandOutcome.Conflict` rather than silently overwriting.
4. **Archived and Foreign Choice Isolation:** Category references issued for draft observation B cannot be submitted for draft observation A; `AgentToolRuntime` immediately rejects cross-draft category references with `AgentErrorCode.REFERENCE_SCOPE_REFUSED` (`category_from_same_draft_observation`). Archived categories return `WorkflowDenialReason.CATEGORY_UNAVAILABLE`.
5. **Review Queue Priority (Unresolved Conflicts Outrank Categories):** Drafts with unresolved links or bank data conflicts remain in `ReviewQueueGroup.NEEDS_DECISION` and outrank missing-category and ready drafts, even when a valid category has been saved. Category selection never settles link ambiguity or resolves financial conflicts.
6. **Responsive Visible-Row Review Updates:** The review UI (`BankDraftReviewScreen` and `ReviewQueueFocus`) observes visible drafts individually via Room flows (`observeReviewQueueEntry`). Stored category updates on visible rows refresh in-place without page jitter or navigation away/back. When a draft changes priority group or an off-page conflict arises, `updatePageMembership` and `updateVisibleEntry` re-read the bounded page in strict conflict-first order without altering the user's selected sort order or open draft.
7. **Immutability of Ledger and Sources:** Draft review status remains `PENDING`; no ledger transactions are created (`transactionDao().findAll().isEmpty()`), note sources are untouched, and no replacement classifier or on-device model is introduced.

Independent verification confirms clean builds, complete JVM suites (559 tests, 0 failures, 3 live-smoke skips), clean Android lint (0 errors), successful isolated APK assemblies, physical phone hosted execution with same-run linking and category review (`S95HostedCategoryPhoneInstrumentedTest`, 234.822 s, PASS), and physical phone review surface live refresh (`S95ReviewRefreshPhoneInstrumentedTest`, 3.317 s, PASS).
