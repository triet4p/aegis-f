## Executive Summary

Task S9.4 implements production arrival reconciliation between source-backed note event interpretations and permitted bank notification drafts. The delivery establishes the required invariants:
1. **Arrival Reconciliation & Convergence:** Arrival of a note event interpretation or a permitted bank notification triggers automatic reconciliation against current pending candidates. Both arrival orders (note-first and notification-first) converge deterministically to the same allowed `ACCEPTED` link for unique evidence.
2. **Durable Operation Identity & Replay Coalescing:** Every arrival operation is assigned a stable identity (`event:<id>:<revision>` or `draft:<id>`) and enqueued in `arrival_reconciliation_operations` within the same Room transaction that saves the event or draft. Replayed notification callbacks or idempotently retried commands coalesce via `insertIfAbsent` (`OnConflictStrategy.IGNORE`), preventing duplicate operation entries or duplicate link rows.
3. **Bounded Scanning & Cursor Pagination:** Draft arrivals process unmatched events in bounded pages (32 events per page) via `operationDao.advanceDraftCursor`. Pending draft searches are capped at `QueryPageRequest.MAX_PAGE_SIZE` (500 rows); inboxes exceeding 500 rows return `ARRIVAL_OUTCOME_INCOMPLETE` without auto-attaching.
4. **Crash / Restart Recovery:** Incomplete work marked `PENDING` survives process termination. On application startup, `AegisApplication.onCreate` asynchronously invokes `resumePendingArrivalReconciliation()`, draining pending operations from their last committed page cursor.
5. **User-Edit Protection & Stable Re-extraction Identity:** Note event entities include durable `userEdited: Boolean` flags (Room schema 17). User edits cannot be overwritten by automated model extractions (`NoteEventWriteResult.UserEdited`). Model re-extractions over the same source span preserve event identity (`eventIdentity`) rather than appending duplicate rows.
6. **Rejection / Dismissal Terminality:** User rejections (`ContextLinkState.REJECTED`) and draft dismissals (`IntakeReviewStatus.DISMISSED`) remain permanently terminal; incoming notifications and replay cannot resurrect rejected pairs or link dismissed drafts.
7. **Immutability of Ledger and Sources:** No ledger transactions are created, no draft financial values are rewritten, and note source bodies remain unmodified.

Independent verification confirms clean builds, complete JVM suites (551 tests, 0 failures, 3 live-smoke skips), clean lint (0 errors), and physical phone instrumented verification across 9 focused on-device test scenarios (all passed `OK`).

## Integration Risk Assessment

### 1. Local Coordinator Pending Cap (500) vs Hosted AgentSession Grant (32)
- **Hosted AgentSession:** `QuickCaptureScreen.kt:264-273` queries draft candidates with `limit = 32, offset = 0` and sets `draftScopeComplete = !pendingDraftPage.hasMore`. In `WorkflowCommandService.kt:1822-1827`, automatic attachment invokes `automaticAttachmentPolicy.trustedEvidence(..., pendingDatabaseComplete = scope.draftScopeComplete)`. If more than 32 drafts exist, `draftScopeComplete` is `false`, `trustedEvidence` returns `null`, and the mutation is denied with `WorkflowDenialReason.ATTACH_POLICY`.
- **Local Arrival Coordinator:** `ArrivalReconciliationCoordinator.kt:232-238` queries draft candidates with `limit = QueryPageRequest.MAX_PAGE_SIZE` (500). If `pendingPage.hasMore` is `true`, `reconcileEvent` immediately returns `ARRIVAL_OUTCOME_INCOMPLETE`, refusing auto-attachment.
- **Physical Phone Proof:** `S94ArrivalLifecyclePhoneInstrumentedTest` independently verifies both boundaries on-device:
  - `ambiguityAndIncompletePendingScopeDoNotAutoAttach`: seeds 500 decoys plus a target; the coordinator yields `ARRIVAL_OUTCOME_INCOMPLETE` with zero links attached.
  - `agentFirst32GrantCannotAttachWhenAnotherPendingDraftExists`: seeds 32 decoys plus a target; `commands.attachLink` for `WorkflowCallerScope.AgentSession` is denied with `ATTACH_POLICY`.

### 2. Manual-Command Unit Fixtures and Production Arrival Proof
- In legacy unit tests (`FinancialCommandServiceTest`, `WorkflowCommandServiceTest`, `NoteEventContextTest`, `AgentMaskedValueUsabilityTest`), tests that specifically assert manual command mechanics (`proposeLink`, `attachLink`, `inspectLinkEvidence`) now seed drafts directly via `database.pendingBankDraftDao().store(...)` or control arrival order. This prevents S9.4's new automatic arrival reconciliation from pre-attaching the unique draft before the test can assert manual link transitions.

### 3. AegisApplication Async Startup Recovery vs Migration Fixtures

  - No global manifest override or test application switches remain in the candidate.

### 4. Raw-Byte Digest vs Windows sha256sum -c Discrepancy
- In `artifacts/sprint-9/evidence/S9.4-a1/candidate-manifest.sha256`, 13 files appeared to fail `sha256sum -c` under Windows MSYS2 / Git Bash.
- Independent investigation definitively established the root cause:
  - The manifest formatted entries with double spaces (`<hash>  <filename>`), which MSYS2 `sha256sum` treats as text mode.
  - Exactly 13 files in the candidate have Windows CRLF (`\r\n`) line endings (`CHANGELOG.md`, `README.md`, `LedgerDatabase.kt`, `WorkflowCommandService.kt`, `AgentToolRuntimeTest.kt`, `BoundedWorkflowExecutorTest.kt`, `AgentRunMigrationTest.kt`, `CaptureMessageMigrationTest.kt`, `FinancialCommandMigrationTest.kt`, `FinancialCommandServiceTest.kt`, `NoteEventContextTest.kt`, `WorkflowCommandServiceTest.kt`, `docs/sprint-8-application-tools.md`).
  - Text mode on MSYS2 translates CRLF to LF, producing a false mismatch.
  - Raw byte hashing (`certutil -hashfile` and Python binary `read("rb")`) confirmed that all 40 files in `candidate-manifest.sha256` match their declared SHA-256 digests with 100% precision.
