## Executive Summary

Task S9.8 validates language and provider capability boundaries across the completed note-to-draft workflow under the unchanged production policy (12 turns / 24 tools) on the physical device (`AAAJBB4930914141`) targeting isolated package `io.github.triet4p.aegisf.s812evidence` (+ `.test`). The review independently verified the candidate implementation, test suites, device traces, UI hierarchies, and environmental restorations:

1. **Root-Cause Defect Found and Corrected in S9.8-a2 (`ProviderJson.kt`):**
   - In earlier attempts (a1 and initial a2 runs), OpenAI-compatible models (e.g. DeepSeek V4.1 Flash) stalled because optional nullable references in `make_time_anchor` (`end_date_ref`, `end_time_ref`) and `list_drafts` (`cursor`) were sent by the model as literal text `"null"`. The strict host rejected these strings with `UNKNOWN_REFERENCE issued_in_this_run`, stalling runs at 0 events.
   - Investigation established that `ProviderJson.applySingleType` previously collapsed declared `["string", "null"]` unions to `type: "string"` plus `nullable: true`. While `nullable` is an OpenAPI 3.0 / Gemini Schema field, OpenAI `parameters` is standard JSON Schema where `nullable` is ignored; the model was told the property was a required string with no legal JSON null spelling.
   - S9.8-a2 corrected `ProviderJson.kt` so that `lowerForOpenAi` preserves the JSON Schema type array (`{"type": ["string", "null"]}`) without a `nullable` property, while Gemini lowering retains its native uppercase type + `nullable: true` format.
   - Runtime validation and authority in `AgentToolRuntime.kt` were left strictly unchanged: literal string `"null"` and blank text remain strictly rejected with `UNKNOWN_REFERENCE` and `SCHEMA_INVALID`. An intermediate runtime-coercion experiment was completely removed. Both OpenAI protocol adapters (`OpenAiChatCompletionsAdapter` and `OpenAiResponsesAdapter`) and Gemini adapter contracts were verified.

2. **Accepted S9.8-a1 Dong Masking and Resolution Fix Retained (`SensitiveVault.kt`):**
   - S9.8-a1 identified that an English note writing dong with bare shorthand (e.g. `50000d`) was misclassified as an alphanumeric bank code and rejected by `parseAmount`, while grouped shorthand `50,000d` leaked unmasked entirely.
   - S9.8-a1 added `DONG_D_SUFFIX_PATTERN` to `SensitiveVault.kt` matching grouped or 4+ digit bare numbers followed by `d`/`D`, masking the entire surface as `IssuedValueShape.NUMERIC` and canonicalizing to whole-dong digits. Durations such as `3d` remain unmasked as non-financial text.
   - 4 unit tests in `MaskedValueShapesTest.kt` confirm consumer behavior. The pre-fix privacy claim was explicitly superseded.

1. **Real Chat UI Reasoning Token Truncation (INFO):** In the physical Compose Chat UI on the final APK, DeepSeek V4.1 Flash exhausted its full 8192-token output budget purely on reasoning (`completion_tokens=8192`, `reasoning_tokens=8192`, `prompt_tokens=14840`, 0 tools) due to the enlarged production inbox (4 captures, 8 pending drafts). 2. **Occurrence-Scoped Day Resolution vs. Multi-Clause Notes (INFO):** In notes where "Today" appears only once in the leading clause (e.g. `Today fuel ... and snack ...`), the app's relative date anchoring binds the day strictly to the first occurrence. The second occurrence correctly lacks a grounded day reference, generating a designed date clarification rather than guessing an unstated date. Grounding both clauses (e.g. `Today fuel ... and today snack ...`) completes cleanly in both languages.
3. **Offered Provider Boundary Matrix (INFO):** Gemini 3.5 Flash Lite encountered HTTP 503 ("model experiencing high demand") and HTTP 429 rate limits; Gemma 4 26B hit HTTP 429; GPT-6 Luna entered repeated tool inspection loops exceeding turn limits. Each failure surfaced honestly through the UI/harness with zero silent provider substitution.
