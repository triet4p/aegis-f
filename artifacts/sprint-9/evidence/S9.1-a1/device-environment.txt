## Package safety

- Before install, the only Aegis package on the device was the owner's main app
  `io.github.triet4p.aegisf`.
- Phase 1 (instrumented test): installed the isolated debug build with the existing evidence suffix —
  `io.github.triet4p.aegisf.s812evidence` and its test package
  `io.github.triet4p.aegisf.s812evidence.test` (separate application id, separate data directory) —
  then uninstalled both.
- Phase 2 (live hosted run through the real app UI): reinstalled only
  `io.github.triet4p.aegisf.s812evidence`, used the app's own provider settings inside that isolated
  package, then uninstalled it. No test package was needed.
- After both phases the owner package is still present and untouched:

## Typing on the device

The installed keyboards compose Vietnamese Telex (`coffee` → `Cofê`, `yesterday` → `yểtday`), which
would corrupt a synthetic fixture. For deterministic ASCII input the two typing input methods were
temporarily disabled with `adb shell ime disable`, the text was injected with `adb shell input text`,
and afterwards both were re-enabled and Gboard was restored as the default:

- `com.google.android.inputmethod.latin/com.android.inputmethod.latin.LatinIME` — enabled, default
- `com.touchtype.swiftkey/com.touchtype.KeyboardService` — enabled

No keyboard setting remains changed.
