## Failure observations and corrections

- The first focused build found two unresolved `AcceptedLink` references after an enum edit. The result variant was restored; the subsequent focused build succeeded.
- The initial incomplete-scope phone fixture used 34 pending drafts, which are complete under the generic `QueryPageRequest.MAX_PAGE_SIZE` of 500. Source inspection confirmed the distinct hosted AgentSession grant remains the first 32 ids and marks `hasMore` as incomplete. The fixture was corrected to exceed 500 while keeping the unique target in the visible page, and a separate first-32 grant refusal test was added; the final lifecycle phone class passes 5/5. The local arrival scan and hosted grant are documented separately.
- An early standalone full JVM run produced 551 tests, 41 failures, 3 skips. XML showed 20 legacy manual-link tests were invoking `IntakeRepository.storePermitted`, which now correctly auto-attaches a unique pair before those tests' explicit manual-link assertions. Their test-only fixtures were changed to seed drafts without an arrival callback; all six affected classes then passed 138/138.
- The same early run showed migration-fixture database interference: Robolectric started the real `AegisApplication`, whose new recovery coroutine opened the shared `LedgerDatabase.NAME` while migration tests wrote old-version schemas. A temporary global test-Application override avoided migration interference but caused six notification tests to fail with `ClassCastException` because those tests require `AegisApplication`; that override was removed. The final narrow per-migration-class `@Config(application = android.app.Application::class)` isolation passed together with the real-app notification classes, and the final full suite passes 551/551 with the existing 3 skips.
- `CategoryCutoverMigrationTest` then expected schema version 16 after migrating a version-15 database. The test now asserts `LedgerDatabase.VERSION` and the arrival-operation table that the version-16-to-17 migration adds; the nine-class migration regression set passes.
- One intermediate manifest attempt without `tools:replace` failed at `processDebugUnitTestManifest` due the production application-name merge; the global override was subsequently removed in favor of the test-local migration annotations. This is not present in the final candidate.
