## 3. In-scope defect found and fixed (production change)

**Symptom (preserved):** the English note `Today fuel 50000d ... snack ... 20000d ...` was read
with both amounts present as tokens, but the model's amount refs produced no stored amount and the
workflow asked the user for the amount. Failing-before evidence: pre-fix probe +
pre-fix live run (`record_event_amount_refs=[ref, ref, null, null]`, events without amounts,
clarification "not readable as a dong amount").

**Root cause:** the bare `d` dong shorthand was not a recognised currency unit. The ungrouped
form `50000d` matched the bank-code shape (token `alphanumeric`) so `parseAmount` rejected it; the
grouped form `50,000d` was not masked at all (no word boundary before `d`), so that surface could
leave the device raw.

**Fix:** `SensitiveVault.DONG_D_SUFFIX_PATTERN` masks the whole number+unit surface as one
`numeric` value whose canonical is the whole-dong digits, ordered before the bank-code shape.
Bare form requires 4+ digits (`3d` stays a duration); grouped forms also masked. No fixture
special-casing; no raw amount is exposed to the model.

**Files:** `app/src/main/java/io/github/triet4p/aegisf/privacy/SensitiveVault.kt`,
`app/src/test/java/io/github/triet4p/aegisf/privacy/MaskedValueShapesTest.kt` (4 new deterministic
tests), `CHANGELOG.md` (Unreleased → Fixed).
