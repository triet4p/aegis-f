## 3. Source changes made in a3 (exact)

All changes are uncommitted, unstaged and unpushed.

1. `app/src/main/java/io/github/triet4p/aegisf/agent/AgentInterfaceContract.kt`
   - Added `AgentReferenceRegistry.issuedFor(kinds)`: a bounded, value-free
     inventory of handles this run already issued for the expected kind(s).
     Per-kind bound `MAX_INVENTORY_PER_KIND = 8`; one newest handle per subject in
     first-issuance order. `inventorySubject()` groups only equivalent handles:
     `capture:<id>`, `draft:<id>`, `event:<id>`, `pair:<event>:<draft>`,
     `operation:<key>`; value/anchor/source/category handles stay individual.
     Evicted and foreign handles can never appear (membership is this registry's
     own `entries`). This is identity grouping, never spelling similarity.
   - `resolve()` and `resolveAny()` unknown/blank branches now carry
     `expected = {"kind"|"kinds": …, "issued":[{"ref","kind"}, …]}` and a message
     pointing at `expected.issued`. The refused string is never echoed.
   - The existing `expected` object was reused (it already carries `kind` on
     `REFERENCE_KIND_MISMATCH` and is documented as safe structured metadata), so
     no new envelope field and no tool-schema change was introduced.
2. `app/src/main/java/io/github/triet4p/aegisf/agent/AgentToolRuntime.kt`
   - `repairableTools()` for `UNKNOWN_REFERENCE` / `REFERENCE_KIND_MISMATCH` now
     returns `listOf("observe", tool).distinct()`; the a2 trace showed
     `allowed_tools:["observe","observe"]` for an `observe` failure.
3. `app/src/test/java/io/github/triet4p/aegisf/agent/AgentToolRuntimeTest.kt`

     `an unissued observe alias lists the observable inventory and each allowed tool once`;
     `the issued inventory keeps one newest handle per subject in issuance order`;
     `the issued inventory is bounded and never lists an evicted handle`.
