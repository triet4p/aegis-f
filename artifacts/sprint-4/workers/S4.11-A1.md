- **Implementation shape (one mechanism, no shim):** `CategoryDao.deletePermanently` runs one Room `@Transaction`: clear `transactions.categoryId` for that category (no other column is touched), clear a still-pending draft's pre-set category (`reviewCategoryId = NULL`, `reviewCategoryResolved = 0`, `reviewRevision + 1` so a stale editor is told the draft changed instead of writing the removed id back), count the rules the transaction is about to orphan, then delete the category row — whose declared `ON DELETE CASCADE` removes the rules that named it. `LedgerRepository.deleteCategory` now returns and performs this cascade instead of refusing referenced categories; `categoryDeletionImpact` reads the same three counts for the confirmation. No schema change and therefore no migration. `Reported` counts are the applied counts, not a restatement of the confirmation. `BankDraftReviewDao.saveReview` now refuses a non-assignable category id the same way `confirm` already did, so a stale id cannot be written back into a draft. `TransactionEditorScreen` states out loud when the form's selected category no longer exists and resolves the retained archived option against live rows only. Pending/stale suggestion invalidation reuses S4.10's stable-id resolution unchanged.
