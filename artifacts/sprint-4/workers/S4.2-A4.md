## Root cause (grounded in the user log and the code)

- User log (ground truth, not re-run): `powershell -ExecutionPolicy Bypass -File tools\laya\Invoke-S42ParityProbe.ps1` (PowerShell 7.6.6) passed pins/APK/device checks, `adb install`, and staging-dir creation, then died at the first `adb push` with `FullyQualifiedErrorId : NativeCommandError` quoting `laya.onnx: 1 file pushed, 0 skipped. 487.4 MB/s (3807291 bytes in 0.007s)` at `Invoke-S42ParityProbe.ps1:96` (`$out = & $AdbExe @AdbArgs 2>&1`).
- Mechanism: `2>&1` merges native stderr into the PowerShell output stream as error records, and under `$ErrorActionPreference = 'Stop'` (line 64, deliberately set so real PowerShell errors abort) ANY stderr text from a native child becomes a terminating `NativeCommandError` — regardless of exit code. adb writes transfer progress (`1 file pushed…`) to stderr on success, so every push trips it. Proven by direct reproduction: a native child writing the exact push line to stderr with exit 0 aborts PS 5.1 under `Stop` (`NativeCommandError` at the `&` line), while `pwsh` tolerates the same merge — which is exactly why all prior `pwsh`-only smoke passed and the bug reached the user. The `adb devices` check (`& $AdbExe devices 2>&1`) carried the same trap (daemon chatter on stderr, exit 0); the poll loop (`2>$null`) avoided the abort but discarded diagnostics.
- Why this was missed: A2's throwaway smoke used a `fake-adb.cmd → Python` adapter whose stderr never carried progress text; A3 verified only `-DryRun` (zero native calls). No prior smoke exercised a REAL native child emitting stderr with exit 0 under PS 5.1.

## Decisions and rationale

- `System.Diagnostics.Process` launcher as the fix vehicle: it is the boring correct wrapper already available in .NET Framework (PS 5.1) and .NET Core (`pwsh`) with no imports, no preference changes, and no new dependencies. It bypasses PowerShell's error-record wrapping entirely (the child streams never enter the `2>&1` path), keeps splat-equivalent argv boundaries via quoting only elements containing whitespace/quotes, and drains both pipes concurrently via `ReadToEndAsync` tasks started before `WaitForExit` (measured: 80 KB stdout + stderr child completes cleanly in both shells).
- Rejected shapes (both measured, both crash/fail in BOTH shells, recorded so they are not retried):
  - `2> file` redirection combined with `$out = & …` assignment: still trips `NativeCommandError`/empty capture in PS 5.1 (file stays empty, `$LASTEXITCODE` empty) — the assignment path re-enters the same error-record wrapping.
  - `BeginOutputReadLine`/`BeginErrorReadLine` with scriptblock appends: threadpool callbacks have no PowerShell runspace — crashes the host process (`3762504530`) in both `powershell` and `pwsh`.
- No blanket suppression: both streams are captured and returned; the poll loop reads `Stdout` for the `"verdict"` match but stderr is still in the capture (absence is retried until timeout, never mistaken for success). No special-casing of the push progress line; no retries; no `$ErrorActionPreference` change (verified `eap=Stop` after captures); no shell switch (the documented `powershell …` line stays the advertised path); pins, install flags (`-r`), narrow `755`/`644` perms, owned-staging-only cleanup, stale-clear-before-launch, JSON `verdict`+`state` validation, and BOM-free save are all byte-identical to A2/A3.
- No permanent regression file: repo-wide search finds no Pester harness (`*.Tests.ps1`, `Invoke-Pester`, module manifest — all absent) and no `tools/` test convention; adding one would be new test-framework baggage against the assignment. The throwaway native smoke below is the regression guard evidence; its fixture source is short enough to re-create on demand.
