## Decisions and tradeoffs

- **Finding 1 (changelog):** re-inserted the exact accepted S4.7 bullet verbatim above the S4.8 bullet under `[Unreleased]` (insert, not replace). Also updated the S4.8 bullet wording from `Vietnamese/diacritic` to `non-English (including unaccented Vietnamese)` so the record matches the corrected behavior.
- **Finding 2 (language gate):** chose a conservative positive-evidence check over a Vietnamese blacklist. Eligibility now requires the existing ASCII-shape heuristic PLUS at least one 4+ letter word from an expense-domain English set (`ENGLISH_EVIDENCE_WORDS`) derived from the pinned `tools/laya/expense_examples.json` descriptions and category descriptors plus the Sprint 4 verification trio. Rationale: ASCII shape alone is not English (R1's exact objection); blacklisting Vietnamese phrases would be unmaintainable special-casing that breaks on the next unseen memo. The tradeoff is deliberate over-rejection: genuine English outside this small domain set also stays manual — safe, reviewable, never silently confirmed, consistent with English-first intent. `Chuyen tien an trua`, `Thanh toan tien dien`, `Nap tien dien thoai`, and `CK NHANH 123 THANH TOAN` contain no evidence word and stay manual; `Lunch at a cafe`, `Monthly rent`, `Payment to Alex`, `Grab ride to the airport`, `Pharmacy antibiotics for flu`, `Wedding gift for cousin`, and the boundary food phrasings all contain at least one and stay eligible. Simulated all of these in Python before editing, then proved them in the JVM suite.
- **Finding 2 (masked test):** the old test passed an accented memo as `memoText` while the stored `draft.memo` held the unaccented string the gate never sees. Fixed by asserting `draftSuggestionInput` with identical stored/visible values for accented `Chuyển tiền ăn trưa`, unaccented `Chuyen tien an trua`, and `Thanh toan tien dien`, plus direct `isMeaningfulEnglishForSuggestion` false-assertions and a second test pinning other unaccented banking ASCII (`Nap tien dien thoai`, `CK NHANH 123 THANH TOAN`).
- **Finding 3 (keyboard tap):** dismissed the keyboard with `KEYCODE_BACK` before any panel interaction and scrolled to locate a visible actionable control. Outcome differs from the reviewer's suggested script in one honest way: no suggestion panel appeared at all for these opaque memos (correct gate behavior routes them to the suppressed manual state, which renders no panel), so there was no visible **Use suggestion** button to tap. Tapping blind coordinates would repeat A2's mistap class of error. Explicit acceptance (field-only change), Ignore (field unchanged), manual override, and no-save semantics therefore rest on the host state-machine tests (exercised, passing), while the device proved the reachable half: opaque-manual with unchanged category field, note accepted in the field with real spaces, keyboard dismissed, drafts left unconfirmed with stored memos intact.
- **Note-text reality:** `adb shell input text` inserts at the focused cursor; both A3 notes landed mid-memo (first also picked up a device-level autocorrect on `cafe`). This is an input-method artifact of the smoke harness, not app behavior, and both insertions were discarded unsaved. Recorded plainly rather than retyped over user data.
