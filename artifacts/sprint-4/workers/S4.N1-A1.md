### Outcome

- **Status:** `implementation_complete`.
- **Observable result:**
  - **Evidenced cause:**
    - *Observed device state:* Package-filtered system notification dump confirmed that multiple bank notification events were posted to the system. The latest posted bank notification was not persisted to SQLite at the time it arrived; it was only ingested as a draft when the application process was started via `am start` and triggered connect-time active reconciliation.
    - *Observed listener lifecycle gap:* When the app is updated (`adb install -r`), force-stopped, or when aggressive OEM power management suspends background processes, `system_server` drops the listener connection (`app=null`, `hasBound=false`). The app previously had no automatic rebind on launch or resume—rebind was solely wired to a manual button inside `BankNotificationSettingsScreen`. Furthermore, `reconcileCurrentActive` was only executed inside `onListenerConnected()`; navigating to the home screen or opening `BankDraftReviewScreen` never triggered active reconciliation.
    - *Causal failure mode (distinguished from historical inference):* Notifications arriving while the background listener was unbound were not captured live. When the user opened the app, the un-reconciled draft inbox was empty. Once the user manually recorded the transaction and dismissed/swiped away the notification from the system shade, the notification was no longer in `getActiveNotifications()`, making historical recovery impossible without active OS notification persistence.
  - **Implemented fix:**
    1. **Automatic lifecycle rebind & active reconciliation:** `BankNotificationListener.requestActiveReconciliation(context)` was added and wired into `AegisApplication.onCreate()`, `MainActivity.onResume()`, and `BankDraftReviewScreen` (`LaunchedEffect`). When notification access is granted, the app automatically checks the listener connection; if disconnected, it prompts system rebind with package manager component-toggle fallback; if connected, it invokes `reconcileNow` off-thread to immediately ingest any active bank notifications currently in the status bar into drafts.
    2. **Listener disconnect recovery:** `BankNotificationListener.onListenerDisconnected()` now checks if notification access is still granted in system settings and automatically requests a rebind.
    3. **Privacy-safe diagnostic visibility:** Added targeted privacy-safe `Log.i` and `Log.d` diagnostics across `BankNotificationListener` and `NotificationAccess` logging only connection states, allowlist checks, candidate counts, and rejection reasons—strictly excluding amounts, memos, account numbers, and OTP text.
    4. **Invariants preserved:** Deduplication (`PendingBankDraftDao` deliveryId + evidenceDigest), package allowlist filtering, OTP and security rejection, manual user review, and zero automatic ledger writes remain strictly intact.
- **Remaining criteria/blocker:** None.
