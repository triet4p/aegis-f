## Decisions and rationale

- Boring .NET stream hashing as the fix vehicle: the failure is cmdlet autoload (`PSModulePath` lists PS7 modules first; PS5.1 chokes on the .NET Core Utility binary), not missing functionality — `System.Security.Cryptography.SHA256` ships in the .NET Framework every PowerShell hosts on, works identically under `powershell` and `pwsh`, needs no import, and keeps byte-for-byte the same verification semantics (exact bytes + exact hex, throw on mismatch). Follows the script's own existing pattern (`[System.IO.File]::OpenRead` for the symlink-aware size read, `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)` for the BOM-free save).
- Rejected alternatives: explicit `Import-Module $PSHOME\...\Utility.psd1` preamble (touches module-loading behavior, fragile across hosts, and the assignment says prefer not depending on module cmdlet autoload); switching the documented command to `pwsh`-only (would strand users without PS7 and contradict "keep exact user command honest"); `Add-Type` of the PS7 Utility DLL (proven by R2 not to load under .NET Framework — LoaderException); suppressing/catching the `CommandNotFoundException` or skipping provenance verification (explicitly forbidden — hash checks must still execute, and they do: all four `OK:` lines print only after both gates pass).
- No doc edits: §6's `powershell -ExecutionPolicy Bypass -File tools\laya\Invoke-S42ParityProbe.ps1` line and the README invocation are now literally true in both shells, so changing them would add noise, not honesty. The only docs-adjacent change is the changelog's one added sentence describing the fix.
- Changelog restore method: base text re-read from `git show 27148807:CHANGELOG.md` and re-inserted verbatim (not rephrased), so release history is preserved exactly; final `git diff <base> -- CHANGELOG.md` confirms +1/−0.
