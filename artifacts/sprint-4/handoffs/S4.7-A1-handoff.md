## Decisions and rationale

- Chosen semantics are exact description matching, with only case/whitespace normalization. This is a deliberate user-scoped pattern, not automatic merchant extraction or global category learning.
- Rules store category ID rather than a name. Reads join the current category row and exclude archived rows, so rename reflects current metadata and archive prevents application. The FK removes a rule if its unreferenced category is deleted.
- Stored rules use the same manual suggestion review surface and cannot alter a field or financial record without an explicit user action. A rule hit short-circuits neural inference; a miss or inactive archived rule falls through normally.
- The rule table is separate from ledger records. No transaction DAO calls were added to rule operations.
