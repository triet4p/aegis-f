## 3. Reasoning and gate/visibility decisions A2 must know

These are deliberate A1 (+ carried-over S4.8-A4) behaviors, not accidents. Any fix changes a user-visible contract, so A2 should change exactly one with review sign-off.

1. **Bank panel renders NOTHING in four states — by design.** `DraftSuggestionPanel` returns early (no header, no hint) for `Idle`, `WaitingForDescription`, `ManuallySelected`, and `Ignored`. The manual panel only hides on `Idle`. Carried over from S4.8-A4's review-only suppression philosophy. Consequence: any bank path that lands in those states looks exactly like "no suggestion" to the user.
2. **Opaque memo + empty note = deliberate `Ignored` (invisible).** `DraftDetailContent`: null effective input with non-empty memo/note text calls `machine.ignore(...)` — junk-in-note also suppresses rather than falling back to the memo (anti-poisoning rule from S4.8-A4). Only a truly empty memo + empty note shows `WaitingForDescription` (also invisible in the bank panel). So a user opening a real opaque-memo draft with no note sees nothing at all — correct per S4.8, but indistinguishable from a broken feature.
3. **The bank English gate has no manual-screen counterpart.** Manual entry sends any non-blank description to the model. Bank review admits only `isMeaningfulEnglishForSuggestion` text. Concrete A1-observed asymmetry (anonymized): a common two-word purchase note whose verb is absent from the curated general-English set fails the gate (single recognized word out of two content words is insufficient unless joined by a short function word), so the identical input shows a distribution in manual entry and nothing in bank review. The gate is conservative by design (loanword-leakage protection from S4.8-R2), but its vocabulary boundary is the likeliest explanation if the user's real note/memo phrasing falls outside it.
4. **Panel placement is below the fold.** In draft detail the suggestion panel sits between the note field and the Category header; on a small phone it requires scrolling. A1's smoke confirmed content only after explicit swipes. A "does not show" report can be a placement/discoverability gap, not a logic gap.
5. **Any manual category tap permanently hides the panel for that intent.** `CategoryChoice` taps (including the pre-existing No-category/active rows) call `chooseManually` → `ManuallySelected` → panel gone. If the user's flow taps a category (or a retained choice) before looking for the suggestion, there is nothing to see afterward. Likewise a prior `Ignore` hides it until the memo/note text changes.
6. **Unsupported-format drafts with no note show nothing.** Null/empty memo text with an empty note yields `WaitingForDescription`, which the bank panel suppresses. Truthful manual fallback exists on-screen (category rows), but no hint points at the note field as the unlock.
7. **Rules still precede inference and say so.** `decideRememberedBeforeInference` resolves saved exact-description rules first with "saved rule, not a model score" copy and null scores. A forgotten saved rule on the user's description would show a rule card, not a distribution — A1 audited one such accidental rule end-to-end (created by worker mis-tap, immediately removed, ledger verified unchanged). A2 should consider asking the user what card, if any, they see: rule card vs nothing narrows the cause instantly.
8. **Oversized-subset disclosure was host-tested only.** The evaluated/omitted scope line renders from `RetrievalUncertainty`, but no on-device oversized catalog was exercised (phone set was 2 active + unknown; synthetic bulk insertion was rejected to protect user data). If the user's real catalog is large AND name-evidence-poor, the planner can still return `NO_METADATA_EVIDENCE` manual review — the exact pre-S4.10 silence, preserved by design for unevaluable sets.
