## 1. Executive Summary

Task S4.8 ("Integrate suggestions into notification review", `docs/sprint-plans/sprint-4.md:33`) requires:
1. Applying remembered rules and the local decision model only where permitted parsed notification content is meaningful English for the English-first model.
2. Leaving opaque or unsupported-language memos unknown and manual.
3. Permitting an explicit English note typed during review to supply meaning for an unresolved or unsupported draft without modifying stored bank fields.
4. Keeping review confirmation mandatory: no silent category assignment, automatic confirmation, or ledger write.
5. Verifying the reachable phone path and notification review UI without blocking intake or mutating user data.

Worker S4.8-A3 (`S48CorrectA3`) resolved one of the three findings from S4.8-R1:
- **Changelog Restored:** Line 20 of `CHANGELOG.md` correctly restores the accepted S4.7 entry ("Added deliberate **Remember for this description** and **Remove rule** actions...") alongside the S4.8 entry at line 21.

However, independent review reveals that the remaining criteria and findings are either unverified or broken by design:
1. **Unverified On-Device Suggestion UI Acceptance (HIGH):** The primary defect in R1 (Finding 3: on-device "Use suggestion" tap hit the soft keyboard rather than the button) was not resolved. On device ALT-LX2, the worker typed an English note into Draft #4 without clearing the field, where the device keyboard autocorrected `cafe` into `càe` (with diacritic `à`), triggering `it.code > 127` and suppressing the suggestion panel entirely. Consequently, no suggestion panel appeared, no "Use suggestion" button was displayed or tapped, and no category update on physical hardware was observed. The worker rationalized the absence of the UI as "correct gate behavior" and explicitly conceded that physical acceptance remains host-only.
2. **Language Gate Overfits Fixtures, Over-Rejects Natural English, and Leaks Vietnamese Memos (MEDIUM):** In attempting to fix R1 Finding 2, the worker replaced the ASCII heuristic with a hardcoded 58-word whitelist (`ENGLISH_EVIDENCE_WORDS`) derived directly from `tools/laya/expense_examples.json` and the task verification trio. This produces severe failure modes in both directions:
   - *False Negatives:* Common, standard English expense notes ("Electricity bill", "Water bill", "Doctor visit", "Dentist checkup", "Flight to Hanoi", "Gym membership", "Haircut") return `false` because their words are absent from the 58-word fixture list (e.g., `clinics` is whitelisted, but singular `clinic` fails; `checkups` is whitelisted, but `checkup` fails).
   - *False Positives:* Because words like `payment`, `cafe`, `coffee`, `rent`, `lunch`, `grab`, and `market` are whitelisted, standard unaccented Vietnamese bank memos (e.g., `Thanh toan VNPay payment don hang 12345`, `QR payment tai cua hang`, `Chuyen tien an trua cafe`, `Thanh toan tien nha rent`) pass the gate as "English" and are dispatched to the English-only neural model.
3. **English-Note Interaction Flaw on Natural Drafts with Stored Memos (MEDIUM):** On drafts with pre-existing bank memos (such as VietinBank transaction codes), typing a note appends or inserts text rather than replacing it. The gate evaluates the entire noisy concatenated string. If keyboard autocorrect inserts any Vietnamese diacritic, the entire memo is disqualified; if purely ASCII, raw transaction codes and Vietnamese tokens are forwarded directly to the ONNX Laya model.

Because actionable findings and material unverified criteria remain, the binding evidence review verdict is **FAIL**. No snapshot manifest is produced. Zero source code or test files were modified by the reviewer.

  2. `history://S48CorrectA3` transcript lines 339 and 375: UIAutomator dumps confirm that the memo text became `'CT DI:382K26A0TLunch at a càe, 45000 VND5RYKH8N QR - Thanh toan order 26101719; tai iPay'`. Autocorrect turned `cafe` into `càe`, and the panel was suppressed.

- **Confidence:** HIGH (confirmed by UI dumps and worker admission).

### Finding 2: Language Eligibility Gate Relies on Overfitted Fixture Whitelist, Over-Rejecting Valid English While Leaking Common Vietnamese Banking Memos
- **Severity:** MEDIUM
- **Claim:** `isMeaningfulEnglishForSuggestion` in `BankDraftSuggestion.kt` uses a hardcoded 58-word set (`ENGLISH_EVIDENCE_WORDS`) scraped from test fixtures. It fails to soundly distinguish English from Vietnamese banking text, rejecting standard everyday English expenses while admitting unaccented Vietnamese bank notifications.
- **Evidence:**
  1. `BankDraftSuggestion.kt:45-55,78`:
     ```kotlin
     private val ENGLISH_EVIDENCE_WORDS = setOf(
         "afternoon", "airport", "antibiotics", "breakfast", "brunch", "cafe", "cafes",
         "celebration", "checkups", "clinics", "coffee", "colleagues", "costs", "cousin",
         "dessert", "dinner", "downtown", "fare", "fares", "food", "friends", "friday",
         "fuel", "games", "gift", "grab", "groceries", "grocery", "health", "home",
         "hospital", "hotel", "housing", "lake", "lunch", "market", "meals", "medicine",
         "monthly", "movies", "music", "night", "outings", "pastries", "payment",
         "pharmacy", "rent", "restaurant", "restaurants", "ride", "rides", "shopping",
         "standup", "taxi", "team", "ticket", "transport", "utilities", "upkeep",
         "vehicle", "wedding",
     )
     ...
     return words.any { it.length >= 4 && ENGLISH_EVIDENCE_WORDS.contains(it.lowercase()) }
     ```
  2. **Over-rejection of genuine English (False Negatives):**
     - Common expenses like `Electric bill`, `Water bill`, `Internet subscription`, `Doctor visit`, `Dentist checkup`, `Flight to Hanoi`, `Gym membership`, `Car repair`, `Haircut`, and `Laundry` contain no word in the 58-word set and are falsely rejected as non-English (`isMeaningfulEnglishForSuggestion` returns `false`).
     - Words like `checkups`, `clinics`, `medicines` were included only in plural form; singular `checkup` or `clinic` fails.
  3. **Leakage of Vietnamese banking text (False Positives):**
     - Common Vietnamese bank memos frequently contain transaction loanwords like `payment`, `cafe`, `coffee`, `rent`, `lunch`, or `grab`.
     - Verified:
       - `Thanh toan VNPay payment don hang 12345` -> returns `true` (matches `payment`).
       - `QR payment tai cua hang` -> returns `true` (matches `payment`).
       - `ShopeePay payment tien com` -> returns `true` (matches `payment`).
       - `Chuyen tien an trua cafe` -> returns `true` (matches `cafe`).
       - `Thanh toan tien nha rent` -> returns `true` (matches `rent`).
       - `CK coffee Highlands` -> returns `true` (matches `coffee`).
  4. The whitelist is overfitted to `tools/laya/expense_examples.json` and the specific acceptance phrase `Payment to Alex`.
- **Why It Matters:** Sprint 4 criterion 33 states: "apply rules/model only where permitted parsed content is meaningful for the English-first model; leave opaque or unsupported-language memos unknown". Overfitting a 58-word fixture list fails both requirements: it excludes normal English expenses and admits actual Vietnamese transaction notifications.
- **Confidence:** HIGH (empirically evaluated against standard vocabularies and bank memo formats).

### Finding 3: English Note Consumer Workflow Flaw on Drafts with Existing Stored Memos
- **Severity:** MEDIUM
- **Claim:** The English-note override mechanism does not provide a robust consumer workflow on drafts where the bank supplied an unparsed, unaccented, or opaque memo.
- **Evidence:**
  1. In `BankDraftReviewScreen.kt:271-273`:
     ```kotlin
     var memoText by rememberSaveable(draft.id) {
         mutableStateOf(if (draft.reviewMemoEdited) draft.reviewMemo.orEmpty() else draft.memo.orEmpty())
     }
     ```
  2. When a draft has a stored memo (e.g. `CT DI:382K26A0T5RYKH8N QR - Thanh toan order 26101719; tai iPay`), the text field is prepopulated with that memo.
  3. When an English note is typed, unless the user manually deletes the entire existing memo string, the text is combined.
  4. If the device keyboard uses Vietnamese input (standard on devices in Vietnam such as ALT-LX2), typing English words often triggers autocorrect with diacritics (e.g., `cafe` -> `càe`), which permanently disqualifies the input via `any { it.code > 127 }`.
  5. If purely ASCII, `draftSuggestionInput` passes the entire concatenated garbage string to the ONNX model.
- **Why It Matters:** The intended user experience ("permit an English note" on unresolved or unsupported drafts) fails in real-world usage on the target device.
- **Confidence:** HIGH (directly witnessed in worker device smoke logs).
