## 1. Executive Summary

S4.N1 ("Diagnose and fix missing recent bank intake", plan line 31) is accepted. The user ground-truth report — recent bank notifications not recorded in the app — is traced to an evidenced listener-lifecycle gap, not guessed parsing or dedup behavior: before this fix, `requestListenerRebind` existed only on a manual settings-screen button (`BankNotificationSettingsScreen.kt:160`, retained), `reconcileCurrentActive` ran only inside `onListenerConnected()`, and neither `AegisApplication` nor `MainActivity` checked the listener on startup/resume (verified absent at base via `git show HEAD`, §3 item 2). The fix adds guarded automatic rebind plus active-only reconciliation at `AegisApplication.onCreate`, `MainActivity.onResume`, and `BankDraftReviewScreen` entry, with disconnect-time auto-rebind and a component-toggle fallback when the standard rebind stalls on OEM devices. All privacy gates stand: allowlist-first intake, OTP/security/group/redaction rejection, dedup identity, manual confirmation, and zero automatic ledger writes are preserved in the read code paths.

The worker's claims respect the required distinction: current-device reconciliation is reported as `active=15, permitted candidates=0` — an absence of new drafts from currently visible posts, not a recovered historical delivery — and dismissed/swiped notifications are honestly declared unrecoverable. No auto-backfill of gone notifications is claimed or implemented. Test evidence is independently corroborated (179/0/0/0 across 26 result files; the 12-test `ListenerRecoveryTest` suite passes including all 3 new tests), and the built APK hash differs from the device-smoke hash for a legitimate reason: the worktree APK (`71c60455…`, 94,182,334 bytes) was rebuilt and re-signed after the final `NotificationAccess.kt` component-toggle edit, while the installed smoke APK (`6fad7bd2…`, same byte size) predates that edit — the device log lines still verify the pre-fallback wiring that this fix retains and extends, and the fallback itself is covered by host tests.

## 4. Disclosed Limits (Nonblocking, Not Fabricated)

- **No natural bank delivery in window:** reconciliation observed `active=15, permitted candidates=0`; no new bank draft was created on the phone. The fix's live-capture half (future arrivals while bound + reconciliation on resume/review entry) is proven by host tests and wiring, not by a fresh bank push.
- **Dismissed history unrecoverable:** notifications swiped away before the fix cannot be backfilled — Android exposes only active posts. The worker states this plainly and implements no historical reconstruction.
- **APK hash rotation:** device smoke hash (`6fad7bd2…`) predates the final component-toggle edit; worktree APK hash (`71c60455…`) postdates it. Both are 94,182,334-byte `versionCode 4` debug builds; the difference is expected from a rebuild, not evidence of mismatch with the reviewed source.
- **No aggregate DB census:** device `sqlite3` unavailable under `run-as`; preservation rests on the intact `Saved transactions`/home summary observation plus zero schema/ledger-path changes.
- **OEM coverage:** aggressive power-management behavior beyond the observed force-stop/reinstall unbind (Honor MagicOS specifics) remains device-dependent; the fallback toggle plus resume/review hooks are the bounded mitigation, not a guarantee against every OEM kill policy.
- **Final user experience gate stays at sprint end** per plan; this task gate covers the intake fix only.
