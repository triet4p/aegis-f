## 1. Executive Summary

Task S4.8 ("Integrate suggestions into notification review", `docs/sprint-plans/sprint-4.md:33`) requires:
1. Applying remembered rules and the local decision model only where permitted parsed notification content is meaningful English for the English-first model.
2. Leaving opaque or unsupported-language memos unknown and manual.
3. Permitting an explicit English note typed during review to supply meaning for an unresolved or unsupported draft without modifying stored bank fields.
4. Keeping review confirmation mandatory: no silent category assignment, automatic confirmation, or ledger write.
5. Reusing the bounded background inference lifecycle, current active category IDs, and draft staleness / draft switching protections.

- **Privacy & Non-Destructive Operation:** Natural pending VietinBank drafts were inspected without confirmation or saving; stored draft fields and existing ledger transactions remained unchanged.

The subsequent tap at `(200, 1360)` struck the soft keyboard (typing an 'x' character into the text field) rather than the "Use suggestion" button. Consequently, physical UI acceptance on real hardware was unobserved.

### Finding 2: Language Eligibility Gate Accepts Unaccented Vietnamese Memos; Masked Test
- **Severity:** MEDIUM
- **Claim:** `isMeaningfulEnglishForSuggestion` in `BankDraftSuggestion.kt` permits unaccented Vietnamese bank memos to reach the English-first inference pipeline, violating the criterion that unsupported-language memos stay unknown/manual. The regression test in `BankDraftSuggestionGateTest.kt` masked this behavior.
- **Evidence:**
  1. `BankDraftSuggestion.kt:40-50`:
     ```kotlin
     internal fun isMeaningfulEnglishForSuggestion(text: String): Boolean {
         val trimmed = text.trim()
         if (trimmed.length < 3) return false
         if (trimmed.any { it.code > 127 }) return false
         if (OTP_GUARD.containsMatchIn(trimmed)) return false
         if (VIETNAMESE_SECURITY_GUARD.containsMatchIn(trimmed)) return false
         val words = ASCII_WORD.findAll(trimmed).map { it.value }.toList()
         if (words.isEmpty()) return false
         if (words.any { it.length >= 4 }) return true
         return words.count { it.length >= 3 } >= 2
     }
     ```
     Because all characters in unaccented Vietnamese are ASCII (<= 127), expressions like `Chuyen tien an trua` or `Thanh toan tien dien` (very common in Vietnamese bank notifications) satisfy `words.any { it.length >= 4 }` (`Chuyen` is 6, `tien` is 4) and return `true`.
  2. `BankDraftSuggestionGateTest.kt:90-92`:
     ```kotlin
     @Test
     fun `Vietnamese memo stays manual`() {
         assertNull(draftSuggestionInput(draft(memo = "Chuyen tien an trua"), "Chuy\u1EC3n ti\u1EC1n \u0103n tr\u01B0a"))
     }
     ```
     `draftSuggestionInput(draft, memoText)` ignores `draft.memo` and inspects only `memoText`. The test passed `memoText = "Chuy\u1EC3n ti\u1EC1n \u0103n tr\u01B0a"` (with diacritics > 127), which returned `null`, while `draft.memo = "Chuyen tien an trua"` was unused. If the test had verified `draftSuggestionInput(draft, draft.memo!!)`, it would have returned `"Chuyen tien an trua"` and failed.
- **Why It Matters:** Sprint 4 criterion 33 explicitly specifies: "leave opaque or unsupported-language memos unknown". In actual bank intake, VietinBank and Vietnamese payment gateways frequently emit unaccented ASCII memos. Passing them to the English model induces spurious inferences or out-of-domain errors. A common Vietnamese stopword/marker check or conservative English vocabulary heuristic is required.
- **Confidence:** HIGH (verified by evaluation and code inspection).
