## 1. Executive Summary & Review Scope

This review evaluates task S4.10 attempt S4.10-A2 performed by worker `S410BankFlowA2`.

Task S4.10 was reopened following user testing at the end of Sprint 4: while manual transaction entry correctly displayed ranked category probabilities, bank draft confirm/review showed no suggestions at all on ordinary bank drafts. The user observation was treated as ground truth.

Independent investigation of source and worker records confirms:
1. **Actual Root Cause Verified:** In `BankDraftReviewScreen.kt`, `DraftSuggestionPanel` contained silent early returns for states `ManualCategorySuggestionState.Ignored`, `WaitingForDescription`, and `ManuallySelected`. In an ordinary bank draft with an opaque, coded, or non-English bank memo and an empty note, `draftSuggestionInput` evaluates to `null`. The LaunchedEffect safely routes this to `suggestionMachine.ignore(...)` (or `waitForDescription()`), causing `DraftSuggestionPanel` to return early without rendering anything. The user was presented with no header, no reason, and no indication that category suggestions were supported or how to invoke them with an English note.
2. **Targeted Correction:** The worker implemented `isBankDraftSuggestionPanelVisible(state)`, rendering the panel for all settled machine states (only transient `Idle` is hidden). The panel now renders the `Category suggestion` header followed by a clear, truthful explanation. For `Ignored` with null input and a blank note, it explains that the bank memo is not eligible English, nothing was sent to the model, and points to the separate English note or manual category selection. It also renders helpful status for `WaitingForDescription` and `ManuallySelected`.
3. **Screen Layout:** The `DraftSuggestionPanel` is positioned directly below the optional English suggestion note field and above the Category choice chips and confirmation actions, ensuring discoverability before the user reaches confirm.
4. **Input Gate & Privacy Invariance:** The gating function `draftSuggestionInput` remains completely untouched. Unsupported bank memos, reference codes, OTP patterns, and non-English text continue to yield `null` and are never forwarded to the inference runtime. The bank memo is never modified or overwritten; the suggestion note is strictly temporary and non-persisted; and bank memos and notes are never concatenated.
5. **On-Device Proof & Selection-Tap Analysis:** The worker installed the debug APK (SHA-256 `9800082c2c37a34b78c454792d6867095350cd8f410a85b152f9e5600c25c18a`) on the connected device (HONOR ALT-LX2, Android 14) and verified:
   - Ordinary bank draft with opaque memo and empty note: `Category suggestion` header and truthful ineligible explanation visible above Category choices.
   - Adding a clean synthetic English note: rule-check loading line followed by the live model-returned ranked distribution with multiple category rows and the Unknown row with real shares (Unknown scored highest ~63%, confidence ~29%).
   - Note editing / junk note: immediate invalidation back to the visible ineligible explanation.
   - Back navigation to draft inbox and reopening: stored memo character-identical, temporary note discarded (empty field), panel back to visible ineligible explanation.
   - Manual transaction entry smoke: visible suggestion states preserved; backed out cleanly without saving.
   - Baseline ledger preservation: 9 confirmed expenses and totals identical before and after device verification; no drafts confirmed or saved.
   - Physical selection taps on A2 build: The worker did not tap non-top, Ignore, or Unknown staging rows on this specific build because soft-keyboard diacritics/autocorrect repeatedly mutated text fields and a stray tap flipped the draft type selector. The worker stopped repetitive UI taps to protect device data integrity. This review rigorously evaluates whether this omission constitutes a material gap: the underlying selection callbacks (`onChooseDistributionOption`, `onChooseNoCategory`, `onIgnoreSuggestion`, and `ManualCategorySuggestionMachine`) were NOT modified in this attempt. They are identical to the code accepted in S4.10-A1 / C1 (`3ab6961b`), which previously underwent successful physical on-device tap verification. All 223 host unit tests pass. Therefore, narrow prior proof reuse is sound and this limitation is nonblocking.

Zero actionable defects remain. The verdict is **PASS**.
