1. **Missing On-Device Proof of Bank Draft Mid-Inference Progress Bar (HIGH):** The worker failed to capture or freeze the indeterminate `ProgressBar` node on the Bank Draft Review surface on actual hardware. Under the review contract, mirrored source code cannot substitute for required physical on-device proof, and assigned gates cannot be downgraded.

The worker fell back to host-only reachability claims.

Because material assigned acceptance proof is absent on the physical device, the binding verdict is **FAIL**. No snapshot manifest is generated. Precise minimum safe evidence remedies are provided to guide the follow-up attempt without requiring full test suite rebuilds or posing privacy risks.

## 3. Actionable Findings

### Finding 1: Unverified Mid-Inference Progress Bar on Bank Draft Review Surface (HIGH)

- **Severity:** HIGH (material evidence gap)
- **Claim:** The indeterminate progress bar (`ProgressBar` node / `LinearProgressIndicator`) on the Bank Draft Review surface was not captured or verified on the physical device during active model inference.
- **Evidence:**
  1. `artifacts/sprint-4/workers/S4.10-A3.md:77` explicitly discloses:
     > "Busy-bar-before-result capture: manual screen showed live busy text + indeterminate `ProgressBar` node in the rendered hierarchy before the distribution; bank screen showed visible status copy with the same indeterminate bar wired to identical machine states, but the warm model returned the distribution between consecutive dumps so no mid-inference bank `ProgressBar` node was frozen in a retained dump. No fake delay was added per assignment."
  2. Inspection of `history://S410InputProgressA3` (turn 537) reveals the test command:
     ```bash
     adb -d shell input tap 360 410; sleep 1; adb -d shell "input text 'buy lunch'"; sleep 12; adb -d shell uiautomator dump --compressed /sdcard/aegis-s410a3-busy.xml
     ```
     Because the worker introduced an explicit 12-second sleep (`sleep 12`) immediately after typing the note, warm model inference (~1 second) had already completed, and the UI dump (`s410a3-busy.xml`) captured only the settled result where the progress bar was already cleared.
  3. In contrast, the manual entry test (turn 711) executed `uiautomator dump` immediately after `input text 'buy lunch'` without an intervening sleep, successfully capturing the active `ProgressBar` node:
     ```bash
     adb -d shell input tap 360 1190; sleep 1; adb -d shell "input text 'buy lunch'"; adb -d shell uiautomator dump --compressed /sdcard/aegis-s410a3-manbusy.xml
     ```
- **Why It Matters:** The primary user-reported issue that reopened S4.10 was the lack of visible suggestions and progress indicators on bank draft reviews ("no clear running/progress signal"). While the Compose source code mirrors `TransactionEditorScreen.kt`, the evidence review directives explicitly mandate: *"assess materialproofgap honestly, don't describe mirroredsource as actualbankbarproof, don't downgradeassignedgates."* Omitting physical proof of the progress bar on the bank review screen leaves a core user gate unverified on real hardware.
- **Confidence:** HIGH (100% grounded in worker transcript and execution logs).

### Finding 2: Unverified Clean Unicode / Vietnamese Note Input on Physical Device (MEDIUM)

- **Severity:** MEDIUM (material evidence gap)
- **Claim:** Entering non-ASCII / Vietnamese text was not cleanly observed producing a suggestion or no-fit state on the physical device due to soft-keyboard autocorrect corruption.
- **Evidence:**
  1. `artifacts/sprint-4/workers/S4.10-A3.md:78` records:
     > "Vietnamese note: typed `an trua` reached the note field (advisory path no longer blocks), but the soft keyboard autocorrect mutated the text with extra insertions (`gt`, `VT`, `Vy`, `by` fragments observed across dumps) faster than the inference round-trip, so a stable Vietnamese distribution was not captured. Host regression pins Vietnamese reachability (`an trua` returns input); no multilingual quality is claimed."
  2. The worker fell back to host unit test `short and Vietnamese inputs reach inference` in `BankDraftSuggestionGateTest.kt:70-86`.
- **Why It Matters:** Acceptance criterion 1 explicitly requires that non-blank notes, including Vietnamese phrases (`ăn trưa`, `mua bữa sáng`), are no longer blocked. While the Kotlin logic in `draftSuggestionInput` is verified by unit tests, physical device smoke is required to verify that typing Unicode text does not cause unexpected IME or UI state anomalies.
- **Confidence:** HIGH.

     - Verify that whatever Unicode text is delivered to the note field successfully triggers the category suggestion flow (either displaying ranked probabilities or Unknown) without an "ineligible English" rejection.
   - Cleanly back out to inbox via Back navigation to ensure no draft is confirmed or saved.
