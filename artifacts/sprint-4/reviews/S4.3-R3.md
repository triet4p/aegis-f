## 3. Why the Remaining Limits Are Non-Material (Independent Judgment)

1. **No fresh SAF-import phone run.** The user did not perform a Missing-state folder import (and was correctly told never to delete an already-Ready install to manufacture one). The SAF traversal (`selectedBundleSources`, `LayaProvisioningScreen.kt:366-392`) therefore remains unexercised against a live DocumentsProvider with the real 1.68 GB bundle through this UI. This is a genuine limitation, stated plainly. It is judged non-material for S4.3 because: (a) the contract accepts **transfer OR explicit download** — the verified S4.2 transfer already placed the identical pinned bytes into the identical app-private location and opened them with the identical production runtime probe the provisioner uses (`LayaModelProvisioner.kt:38-47` → `LayaRuntime.open`); (b) the host tests prove the provisioner's copy/hash/stage/publish logic; (c) the current user evidence proves the page's check/status/restart/cancel/manual-entry behavior live on the phone. What SAF would additionally prove (picker traversal + bulk-copy throughput on this handset) is throughput/UX detail, not whether a verified model is provisioned and diagnosed — and device throughput/storage/latency are explicitly S4.9 concerns, not re-demanded here.
2. **Coarse user confirmation.** "Mấy cái đó đều ok" confirms the three requested check groups en bloc, without per-check verbatim text, screenshots, or cancellation timing. This is weaker than the R1/R2 §5 ideal (verbatim text/screenshots per state). It is accepted because the inputs are current-conversation user ground truth under the assignment, the initial Ready report is a near-verbatim match of the app's status title, and the checks are simple present/absent observations (Ready still shown; cancelled text appeared with return-to-ledger available, or the check finished too quickly to cancel; manual entry opened and backed out without saving). Demanding screenshot-level re-proof of the already-confirmed checks would re-demand what the assignment says not to re-demand.
3. **No new host build/test run.** Per assignment, no build/lint/tests/formatters midflight; the necessary targeted proof (JUnit XML re-parse + APK presence) was done once at the end (§4). Prior full Gradle runs (157 tests, debug+release assemblies) remain worker-reported via artifact + history, corroborated by retained build outputs.
4. **Not required here:** later S4.9 adoption metrics (quality/latency/memory distributions), S4.4–S4.8 behavior, destructive model-removal testing, Main-device access. None was required or performed.

No required gate was downgraded: every S4.3 acceptance line above is bound to cited evidence, and the one genuine uncovered path (fresh SAF import) is disclosed with the contractual reason it does not block.
