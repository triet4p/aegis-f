## 1. Executive Summary & Continuity

Task S4.8 ("Integrate suggestions into notification review", `docs/sprint-plans/sprint-4.md:33`) requires:

1. Applying remembered rules and the local decision model only where permitted parsed notification content is meaningful English for the English-first model.
2. Leaving opaque or unsupported-language memos unknown and manual.
3. Permitting an explicit English note typed during review to supply meaning for an unresolved or unsupported draft without modifying stored bank fields.
4. Keeping review confirmation mandatory: no silent category assignment, automatic confirmation, or ledger write.
5. Reusing the bounded background inference lifecycle, current active category IDs, and draft staleness / draft switching protections.

In prior review attempt S4.8-R2 (`S48EvidenceR2`), three findings blocked advancement:

- **Finding 1 (HIGH):** On-device suggestion UI acceptance was unobserved on ALT-LX2 because Gboard autocorrect inserted a diacritic (`à` in `càe`), suppressing the suggestion panel entirely.
- **Finding 2 (MEDIUM):** The language eligibility gate relied on an overfitted 58-word fixture whitelist (`ENGLISH_EVIDENCE_WORDS`) from `expense_examples.json`, causing severe false negatives on everyday English ("Electric bill", "Water bill", "Doctor visit") and false positives on unaccented Vietnamese banking memos containing loanwords ("payment", "cafe", "rent").
- **Finding 3 (MEDIUM):** An English note typed into a draft with an existing bank memo was concatenated with stored bank text and reference codes, poisoning input to the model.

Fresh correction worker S4.8-A4 (`S48NoteA4`) resolved all three defects:

1. **Clean Note Separation:** Introduced an independent `suggestionNote` field starting empty for every draft (`rememberSaveable(draft.id) { mutableStateOf("") }`). It is evaluated strictly alone by `draftSuggestionInput(draft, memoText, suggestionNote)`, never concatenated with the bank memo, never written to `BankDraftReviewEdits`, and never persisted to the draft table or confirmed ledger description. A non-meaningful or diacritic-poisoned note suppresses suggestions (`null`) rather than falling back to the bank memo.
2. **Maintainable General-English Proportion Gate:** Removed the 58-word fixture list. Replaced it with a curated vocabulary of 133 everyday-English terms (bills, food, health, transport, shopping, time, function words), a recognized-content proportion rule ($\ge 50\%$), short English function word support (`Payment to Alex`, `Flight to Hanoi`), and an alphanumeric reference-code guard (`hasMixedLetterDigitCode` matching $[A-Za-z0-9]{5+}$ with mixed letters and digits, forcing manual). Unseen everyday English passes; loanword Vietnamese memos stay manual; banking reference codes stay manual.
3. **On-Device UI Acceptance Verified on ALT-LX2:** Built debug APK (`48e679fe9d62a88dd90dc43ff6932a95fc4552899fe3af8d01e2a2ea5824ce1c`) was installed in place (`adb -d install -r`). On real hardware, draft #6 (opaque VietinBank memo) stayed manual with an empty note field. On draft #4 (opaque memo with reference codes), typing `Shop ride` into the separate note field produced the `Category suggestion` card with `Use suggestion` and `Ignore`. Tapping `Use suggestion` updated only the category field (radio `false -> true`), and tapping `Keep manual choice` preserved manual review. Back navigation safely discarded the note with stored draft memos, inbox count (4 waiting), and ledger (8 confirmed expenses) unchanged.
4. **Host Test Regressions:** Full test suite passed with **208 tests, 0 failures, 0 skipped** across 28 suites, including 23/23 tests in `BankDraftSuggestionGateTest`.

Independent review confirms all acceptance criteria are met. Zero actionable findings remain. The verdict is **PASS**.

### 3.3 Defensibility of General-English Proportion Gate & Reference-Code Guard

The S4.8-R2 review identified that the 58-word fixture whitelist in A3 was brittle, over-rejected standard English, and leaked Vietnamese memos containing loanwords.

Worker A4 implemented a principled, defensible design in `BankDraftSuggestion.kt`:

1. **Pre-filtering Guards:**
   - Input length $< 3$ returns `false`.
   - Non-ASCII codepoints (`it.code > 127`, including all Vietnamese diacritics) return `false`.
   - OTP and Vietnamese security keywords return `false`.
   - `hasMixedLetterDigitCode` matches alphanumeric tokens $\ge 5$ characters with mixed letters and digits (`382K26A0`, `T5RYKH8N`), forcing manual regardless of surrounding English text.
2. **Vocabulary & Proportion Rule:**
   - Content words ($\ge 3$ letters, excluding currency markers `vnd`, `dong`, `usd`) are extracted.
   - A curated vocabulary of 133 everyday-English words (`GENERAL_ENGLISH_WORDS`) covers standard living expenses across bills, food, housing, transport, healthcare, shopping, and time.
   - For a single content word: requires length $\ge 4$ and must be in `GENERAL_ENGLISH_WORDS` (`Rent`, `Haircut`, `Shop` pass; `Ref`, `Bus` stay manual).
   - For multiple content words: at least 50% must be recognized English (`recognized * 2 >= content.size`).
   - For a two-token phrase with one recognized word: requires an accompanying short English function word (`at`, `by`, `in`, `of`, `on`, `or`, `to`), e.g., `Payment to Alex`, `Flight to Hanoi`.
3. **Safety & Robustness:**
   - Unseen everyday English (`Electric bill`, `Water bill`, `Doctor visit`, `Dentist checkup`, `Gym membership`, `Internet subscription`, `Car repair bill`) passes.
   - Vietnamese memos with loanwords (`Thanh toan VNPay payment don hang 12345`, `QR payment tai cua hang`, `Chuyen tien an trua cafe`, `Thanh toan tien nha rent`) have recognized proportions well below 50% and stay manual.
   - Banking codes (`CT DI:382K26A0 Lunch at a cafe T5RYKH8N`) are blocked by `hasMixedLetterDigitCode`.

### 3.4 Note Separation and Zero Financial / Stored Data Mutation

Worker A4 separated suggestion hints from bank memos in `BankDraftReviewScreen.kt`:

1. `suggestionNote` is an independent `@Composable` state initialized to `""` for each draft (`rememberSaveable(draft.id)`).
2. The UI renders an `OutlinedTextField` labeled "Suggestion note (optional English)" with explicit supporting copy: *"Suggestion hint only. It never changes the bank memo or the saved description."*
3. `draftSuggestionInput` evaluates `suggestionNote` strictly alone when non-blank.
4. `BankDraftReviewEdits` (the payload passed to save and confirm handlers) includes only `memoText = memoText`. `suggestionNote` is never passed to repository or database routines.
5. In phone smoke on natural draft #4, `Shop ride` was entered in the note field. Back navigation discarded the draft review screen without saving. The inbox retained all 4 waiting drafts with character-identical memos, and the home screen showed unchanged confirmed expenses (8).
