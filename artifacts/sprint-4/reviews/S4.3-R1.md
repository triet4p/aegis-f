This is exactly the visual/runtime limit the assignment declares material: missing proof means FAIL with no manifest authorization. No frozen snapshot is created; Main must not dispatch a Bronze checkpoint for S4.3 on this evidence.

## 3. Actionable Findings

### Finding 1 (GATE-BLOCKING): Material physical proof missing — phone provisioning path never executed
- **Severity:** HIGH (evidence gap; no code defect asserted)
- **Claim:** The S4.3 user-visible path — SAF folder import of the three pinned export files, staged copy/hash, real on-device runtime validation, Ready display, restart re-verification, and manual-entry coexistence — has no device evidence. Host unit tests and worker-reported smoke do not cover the Android SAF picker, the real 1.68 GB `LayaRuntime.open` probe through the provisioner, or any rendered UI.
- **Evidence:**
  - Worker artifact `artifacts/sprint-4/workers/S4.3-A1.md` §§ Verification/Limitations: "does not establish the Android SAF picker experience, actual-runtime provisioning on a device, or visual layout. The phone is strictly user-only … no device was accessed."
  - `history://S43ProvisionA1` shows host Gradle test/build commands only; no device command.
  - Current tree: `app/src/test/…/laya/` contains `LayaModelProvisionerTest.kt` (8 tests) but no smoke harness or smoke JUnit report (removed by design); `app/build/test-results/testDebugUnitTest/` holds 22 suites / 153 tests with no provisioning-smoke suite.
  - Screen `LayaProvisioningScreen.kt:69-94,271-297` (picker + `DocumentsContract` traversal) and production `checkRuntime` (`LayaModelProvisioner.kt:37-46` → real `LayaRuntime.open`) are unexercised against real storage/weights.
- **Why it matters:** S4.3 acceptance is an on-phone behavior (import into app-private storage, diagnose states, keep manual operation). Fixture-byte host tests cannot prove SAF traversal, 1.68 GB copy throughput/storage pressure, ~10 s runtime open on ALT-LX2, or rendered/restart behavior. Per assignment, this limit is material: FAIL with no manifest and no checkpoint authorization.
- **Confidence:** High.

### Finding 2 (LOW): No cancel affordance while a multi-minute import runs
- **Severity:** LOW
- **Claim:** While `Copying`, both Back (swallowed by `BackHandler(enabled = busy) { }`) and all navigation buttons (`enabled = !busy`) are dead, with no cancel action; the user waits out the full 1.68 GB copy.
- **Evidence:** `LayaProvisioningScreen.kt:96-97,104-105,200-204`.
- **Why it matters:** Usability/robustness only; state stays honest (coroutine cooperative cancel exists in the provisioner, and process death leaves recoverable staging/backup). Not gate-blocking; S4.5 owns lifecycle. Mentioned so Main can decide whether S4.3 or S4.5 adds explicit cancellation.
- **Confidence:** High (code-observed); no behavioral harm demonstrated.
