## 1. Executive Summary

This is the independent Full-route evidence gate for task **S4.2** ("Integrate the Android decision runtime").

The worker (`S42RuntimeA1`, Gold role) completed all reachable host-side implementation, binary tokenizer asset packaging, sequence and calibration algorithms, ONNX Runtime Android dependency integration, and debug harness creation. Specifically:

Because device access is strictly user-only, the worker could not execute the real ONNX Runtime Android session on ARM64 hardware. In accordance with the assignment mandate, physical evidence is treated as a material missing requirement rather than an ignorable non-claim. Consequently, the review verdict is **FAIL** (`advance: false`), and no checkpoint-authorizing manifest is written at this time.

To facilitate prompt completion of this external prerequisite, the reviewer audited the debug-only `LayaParityProbeActivity`, identified documentation defects in `docs/developer-setup.md` §6, and constructed a copy-ready, automated PowerShell procedure for the user to execute on the connected device.

## 3. Detailed Verification Findings

### 3.1 Tokenizer Implementation & Binary Asset Packaging

- **Binary Tokenizer Asset:** The binary file `app/src/main/assets/laya/laya_tokenizer.bin` (1,317,378 bytes) was generated from the pinned export bundle (`receptron/laya-onnx` @ `68f27dfe`) via `tools/laya/export_tokenizer_asset.py`. Its SHA-256 hash was independently calculated and confirmed:
  `09b371ce4b613716bdad862985c37774dfd3ea6373919c8312f9a6cf8bb9ad1b`.
  The hash matches the embedded asset in `app-debug.apk` and `S4.2-A1-tokenizer-report.json`.
- **Parsing & Logic:** `LayaTokenizer.kt` parses the binary format (`LAYATOK1` header, 50,280 vocab tokens, 50,009 BPE merge ranks, 116 added tokens). It implements NFC normalization, longest-match added-token splitting, and Unicode White_Space `[MASK]` lstrip (which absorbs whitespace runs, tabs, newlines, and NBSP while correctly preserving zero-width spaces U+200B and BOM).
- **Unit Test Coverage:** `LayaTokenizerTest` exercises 52 golden strings derived from the pinned reference, verifying exact token IDs, special token assignments (`[MASK]`=50284, `[CLS]`=50281, `[SEP]`=50282, `[PAD]`=50283, `[UNK]`=50280), and whitespace edge cases.

### 3.2 Sequence Construction & Decision Budgeting

- **Format:** `LayaSequence.kt` formats the sequence as:
  `[CLS] choice question: <instructions> [SEP] [MASK] <opt0> [MASK] <opt1> ... [SEP] <state> [SEP]`
- **Budgeting & Protection:** Descriptions and options are scrubbed of literal `[MASK]` strings to prevent prompt injection. Options are capped at 48 tokens. When option head exceeds `HEAD_MAX_LEN` (192), options are shrunken evenly. If budget cannot fit all options with at least 4 tokens each and 8 tokens for instructions, `Outcome.OverBudget` is returned.
- **Unit Test Coverage:** `LayaSequenceTest` verifies that all 9 reference sequences match golden `input_ids` and marker indices bit-for-bit, mask-injection does not shift markers, and 131 candidate options trigger explicit over-budget refusal.

### 3.3 Calibration & Interpretation

- **Logic:** `LayaCalibration.kt` applies the pinned temperature buckets (cardinality $\le 2$: 1.9064; $\le 5$: 1.7602; $\le 10$: 1.0000; $>10$: 0.1006). It computes numerically stable softmax (subtracting maximum logit) and Jev sharpness confidence ($1 - H(p)/\ln(k)$) rounded to 4 decimal places.
- **Preservation of Baseline Misses:** Tested against golden logits from the reference runner. Two zero-shot baseline misses (`Lunch at a cafe, 45000 VND` $\rightarrow$ `unknown`, and `boundary-long-state` $\rightarrow$ `unknown`) are preserved honestly without artificial adjustment.

### 3.4 Runtime Session Wrapper & Error Boundaries

- **Session Handling:** `LayaRuntime.kt` loads the model via `OrtEnvironment.getEnvironment().createSession(onnxPath, SessionOptions())`. It builds 5 input tensors: `input_ids` (int64), `attention_mask` (int64), `marker_pos` (int64), `marker_mask` (bool), and `qtype` (int64 = 0). It extracts `logits` corresponding to the options count.
- **Fail-Loud Validation:** Ordered checks in `open()` verify file presence, budget parameters in `laya_config.json`, tokenizer binary validity, ORT session creation, and executes an initial probe inference. Failure at any stage returns `Result.Unavailable` with `State.Missing` or `State.CorruptOrIncompatible`.
- **States Test:** `LayaRuntimeStatesTest` validates that missing files produce `State.Missing`, tampered config budgets produce `State.CorruptOrIncompatible`, and corrupted tokenizer assets produce `State.CorruptOrIncompatible`.

### 3.5 Native Packaging & ABI Compatibility

- **AAR Dependency:** `app/build.gradle.kts` adds `com.microsoft.onnxruntime:onnxruntime-android:1.22.0`.
- **ELF LOAD Alignment:** Direct inspection of ELF headers in `app/build/outputs/apk/debug/app-debug.apk`:
  - `lib/arm64-v8a/libonnxruntime.so` (18.2 MB): PT_LOAD segment alignment is `0x4000` (16,384 bytes).
  - `lib/arm64-v8a/libonnxruntime4j_jni.so` (100.6 KB): PT_LOAD segment alignment is `0x4000` (16,384 bytes).
  This confirms native compatibility with both the user's 4096-byte page device (HONOR ALT-LX2) and 16 KB page Android environments.
- **Release Isolation:** The debug manifest `app/src/debug/AndroidManifest.xml` declares `LayaParityProbeActivity`. Inspection of `app/build/outputs/apk/release/app-release-unsigned.apk` verified that `LayaParityProbeActivity` is absent from release builds.

## 4. Probe Reachability & User Procedure Audit

The reviewer conducted a thorough audit of `LayaParityProbeActivity.kt` and `docs/developer-setup.md` §6 to verify device readiness:

1. **Activity Reachability:** `LayaParityProbeActivity` is exported in the debug manifest and can be launched via standard `am start`:
   `io.github.triet4p.aegisf/io.github.triet4p.aegisf.layaprobe.LayaParityProbeActivity`
2. **Autonomous Execution:** The activity invokes `startProbe()` in `onCreate()` on a background thread. A manual "Run parity probe" button is also provided for repeated execution.
3. **Internal Storage Paths:**
   - Model bundle directory: `new File(filesDir, "laya/model")` (requires `laya.onnx`, `laya.onnx.data`, `laya_config.json`, and `tokenizer/laya_tokenizer.bin`).
   - Report destination: `new File(filesDir, "laya/parity/S42-parity-report.json")`.
   - Both correspond to relative paths under the app's private data sandbox, accessible via `adb exec-out run-as io.github.triet4p.aegisf cat files/laya/parity/S42-parity-report.json`.
4. **App State Preservation:** The probe activity operates entirely within `files/laya/` and does not access Room database tables, preferences, or notification channels.

### Usability Deficiencies in Documented Procedure (`docs/developer-setup.md` §6)

A review of the manual steps documented in §6 revealed several usability gaps that prevent clean one-shot execution:
- **Unresolved Placeholder:** Step 2 cites `<bundle-dir>\laya.onnx` rather than the concrete host cache path (`F:\llms\hf\models\hub\models--receptron--laya-onnx\snapshots\68f27dfe5a27a54fb2b1fefc432f43f972e90868`).
- **Missing Staging Directory Creation:** `adb push` commands target `/data/local/tmp/laya-model/`. If this directory does not exist on the device, adb fails with `cannot create file`.
- **Permissions Issue Under `run-as`:** Pushed files in `/data/local/tmp` have default permissions that can block the app's user ID from reading them during `cp`. A `chmod -R 777` step is necessary.
- **Storage Waste:** Staging 1.68 GB in `/data/local/tmp` and copying it into app-private storage consumes 3.36 GB of phone storage. The documented procedure omits cleanup of `/data/local/tmp/laya-model`.
- **Absence of Polling Instructions:** Because model loading (1.68 GB) and 9 inferences take 45–90 seconds, running `cat` immediately fails with `No such file or directory`. Polling instructions are required.

These issues are resolved in the copy-ready procedure in Section 6 below.

## 6. Copy-Ready Minimal PowerShell User Procedure

Main must provide the user with the following self-contained, copy-ready PowerShell script to execute on their connected workstation. It automates APK installation, model staging with permission handling, transfer into app-private storage, staging cleanup, probe execution, asynchronous polling, and report retrieval:

```powershell
# ==============================================================================
# S4.2 Device Parity Probe Execution Procedure
# Prerequisites: Phone connected via USB, authorized ('adb devices' -> 'device')
# ==============================================================================

$apk = 'F:\ai-ml\aegis-f\app\build\outputs\apk\debug\app-debug.apk'
$bundleDir = 'F:\llms\hf\models\hub\models--receptron--laya-onnx\snapshots\68f27dfe5a27a54fb2b1fefc432f43f972e90868'
$tokAsset = 'F:\ai-ml\aegis-f\app\src\main\assets\laya\laya_tokenizer.bin'

Write-Host "--- 1. Installing Debug APK ---" -ForegroundColor Cyan
adb -d install -r $apk

Write-Host "`n--- 2. Staging Pinned Bundle to /data/local/tmp ---" -ForegroundColor Cyan
adb -d shell "mkdir -p /data/local/tmp/laya-model"
adb -d push "$bundleDir\laya.onnx" /data/local/tmp/laya-model/laya.onnx
adb -d push "$bundleDir\laya.onnx.data" /data/local/tmp/laya-model/laya.onnx.data
adb -d push "$bundleDir\laya_config.json" /data/local/tmp/laya-model/laya_config.json
adb -d push $tokAsset /data/local/tmp/laya-model/laya_tokenizer.bin
adb -d shell "chmod -R 777 /data/local/tmp/laya-model"

Write-Host "`n--- 3. Transferring to App-Private Storage ---" -ForegroundColor Cyan
adb -d shell "run-as io.github.triet4p.aegisf mkdir -p files/laya/model/tokenizer files/laya/parity"
adb -d shell "run-as io.github.triet4p.aegisf cp /data/local/tmp/laya-model/laya.onnx /data/local/tmp/laya-model/laya.onnx.data /data/local/tmp/laya-model/laya_config.json files/laya/model/"
adb -d shell "run-as io.github.triet4p.aegisf cp /data/local/tmp/laya-model/laya_tokenizer.bin files/laya/model/tokenizer/laya_tokenizer.bin"

Write-Host "`n--- 4. Cleaning up /data/local/tmp (Freeing 1.7 GB) ---" -ForegroundColor Cyan
adb -d shell "rm -rf /data/local/tmp/laya-model"

Write-Host "`n--- 5. Verifying App Storage & Clearing Stale Report ---" -ForegroundColor Cyan
adb -d shell "run-as io.github.triet4p.aegisf ls -l files/laya/model files/laya/model/tokenizer"
adb -d shell "run-as io.github.triet4p.aegisf rm -f files/laya/parity/S42-parity-report.json"

Write-Host "`n--- 6. Launching LayaParityProbeActivity ---" -ForegroundColor Cyan
adb -d shell am start -n io.github.triet4p.aegisf/io.github.triet4p.aegisf.layaprobe.LayaParityProbeActivity

Write-Host "`n--- 7. Polling for Parity Report (Cold load ~45-90s) ---" -ForegroundColor Cyan
$timeoutSeconds = 180
$elapsed = 0
$reportJson = $null
while ($elapsed -lt $timeoutSeconds) {
    Start-Sleep -Seconds 5
    $elapsed += 5
    $raw = adb -d exec-out run-as io.github.triet4p.aegisf cat files/laya/parity/S42-parity-report.json 2>$null
    if ($raw -and $raw -match '"verdict"') {
        $reportJson = $raw
        break
    }
    Write-Host "Running inference... (${elapsed}s elapsed)"
}

if ($reportJson) {
    Write-Host "`n=== PROBE REPORT RECEIVED ===" -ForegroundColor Green
    $reportJson
    $dest = 'F:\ai-ml\aegis-f\artifacts\sprint-4\reviews\S42-parity-report.json'
    [System.IO.File]::WriteAllText($dest, $reportJson, [System.Text.Encoding]::UTF8)
    Write-Host "`nSaved to: $dest" -ForegroundColor Green
} else {
    Write-Error "Timeout reached: probe report was not generated."
}
```
