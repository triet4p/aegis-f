### Parser contract (authoritative for S3.4–S3.8)

- **Entry point:** `parseBankNotification(content: PermittedNotificationContent, zone: TimeZone = TimeZone.getDefault()): BankNotificationParse`. Input is exactly the intake boundary's output, so the package gate and the security/group-summary/empty/redaction-only rejections have already run.
- **Field-union reading (no field mapping assumed):** `title`, `text`, and `bigText` are split on `\n`, trimmed, empties dropped, and exact duplicates removed. A line is found wherever the bank posted it; the same text in two fields is one statement. Which field the real bank uses is still device evidence.
- **Recognition (deterministic, strict):** the payload is a supported VietinBank transaction only if a line begins `VietinBank` **and** a `GD:` transaction line exists. Everything else → `UnsupportedFormat`: another bank, a promotion, a balance-only alert, or any payload without the transaction line. Unsupported content is never bent into a transaction.
- **Amount:** read from the `GD:` line only. Grammar: optional `+`/`-`, digits with optional 3-digit comma grouping, optional dong suffix (`VND`, `VNĐ`, `Đ`, `₫`, or none). The magnitude is validated by `VndMoney.parseManualAmount` (digits only, no zero, no overflow), so `Present(amountVnd)` is always a positive whole-dong value. A non-VND currency, a masked value, malformed grouping, or zero → `Unresolved(Unreadable)`. No sign is stored in the amount.
- **Direction:** `BankDirection` from the `GD:` sign — `-` → `DEBIT`, `+` → `CREDIT`, none → `UNKNOWN`. **This is the bank statement's vocabulary, not `TransactionType`:** a debit is not an expense and a credit is not income; both are only what the bank stated, and the user's review confirmation makes them ledger types.
- **Timestamp:** read from the bank attribution line's remainder (`VietinBank: dd/MM/yyyy HH:mm`), converted with `ManualDateTime` (same device-default zone convention and same non-lenient refusal of impossible dates as manual entry) and returned as epoch millis. The bank states no zone, so none is claimed — the documented convention is the device zone, never the bank's zone and never a guessed UTC instant. Missing line remainder → `Missing`; unsupported shape → `Unresolved(Unreadable)`.
- **Memo:** read from the `ND:` line only, filtered through the shared `carriesUsableContent` judgement. Meaningful text → `Present(text)`; masking/placeholder only (`........`, `Redacted`) → `Unresolved(Redacted)`; no `ND:` line or a blank value → `Missing`. The dotted sample memo is therefore unresolved, never a literal memo.
- **Balance and account are excluded on purpose:** `SDC:` (balance, masked in the sample) and `TK:` (account) are recognised only so they are never read as the amount. No account identifier is extracted or retained, and a readable balance is never substituted for an unreadable amount.
- **Conflicts:** the same label with genuinely different values → `Unresolved(Ambiguous)` (amount, timestamp, or memo). Identical repeats are not a conflict.
- **No invented fields:** the result carries no timezone, no transaction reference, no balance, and no ledger type — none of these was supplied by the sample, and the `Parsed` type has no place to put a guess.
