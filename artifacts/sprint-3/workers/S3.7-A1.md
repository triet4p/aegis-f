### Outcome

- **Status:** `implementation_complete` for S3.7 host-side behavior. Device/OS
  reconnect, OEM behavior, and UI interaction were unavailable and are not claimed;
  the consolidated full-flow/device checks remain S3.8.
- **Entry points:** `BankNotificationListener.onListenerConnected` (allowlist load →
  `Connected` → drain init-window queue in order → `reconcileCurrentActive`);
  `onListenerDisconnected` (clear queue, cancel in-flight work, `Disconnected`);
  `onNotificationRemoved` (deletes nothing); settings screen rebind button +
  revoked-vs-disconnected status.
- **Rebind:** `requestListenerRebind(context, accessGranted)` makes one explicit
  supported `requestRebind` call only when access is granted
  (`ListenerRebindOutcome.Requested`); without the grant nothing is called
  (`RefusedNoAccess`). No retry, no loop, no settings bypass. The system answers
  asynchronously; the status line keeps telling the truth meanwhile.
- **Reconciliation guarantees:** `reconcileActivePosts` judges each supplied post
  exactly like a live callback — allowlist from routing metadata first, then the
  same OTP/security/group/empty/redaction screen — and returns each survivor with
  its platform provenance for the same `storePermitted` persisted
  delivery/evidence identity. A re-read post writes nothing; a later equal-evidence
  post becomes its own flagged candidate; a confirmed/dismissed draft is never
  reopened. Only the supplied currently-active set is considered; removed posts are
  absent and never reconstructed; no removed-history or statement claims.
- **Ordering/revocation:** queued posts drain before reconciliation; every write
  passes the same `Connected` guard, so a disconnect stops further writes while
  already persisted drafts stay untouched. A `SecurityException` on the active
  read stays a miss, not an empty-history claim. One unreadable post never stops
  the rest. Manual entry is independent and untouched.
