## Decisions

- Off-main-thread load + readiness-gated `Connected` (rather than sync cached read, async preload with default-allow, or locking/latch) because the callback is main-thread by AOSP contract, the settings surface must never mistake "bound" for "ready", and an undecided pre-ready return preserves fail-closed with no empty-snapshot decision at S3.1.

- `cancelChildren` on disconnect + `cancel` on destroy (rather than no lifecycle handling) because revocation unbind must not leak a stale `Connected` or snapshot refresh; scope cancellation is the existing coroutine pattern already in the dependency set.
- Real `StatusBarNotification` with empty `Notification()` body in tests (rather than mocks or null-only posts) because it exercises the actual callback path including `packageName` routing while guaranteeing no content exists to be read.
