### Finding 2: Robustness Gap — Platform Call `activeNotifications` Lacks Defensive Null Check
- **Prior Status (R1):** LOW / Actionable Quality. In `BankNotificationListener.kt:224`, `activeNotifications` was invoked directly as `active.toList()`, which throws `NullPointerException` if the platform returns `null`.
- **Correction in S3.8-A2:**
  - AOSP source analysis confirmed that in Android 7.0–8.1 (`android-7.0.0_r1` to `android-8.1.0_r1`, API 24–27), `NotificationListenerService.getActiveNotifications()` returns `null` if the service is not currently bound (`!isBound()`) or encounters an IPC failure. Only in Android 9.0+ (`android-9.0.0_r1`, API 28+) does the framework substitute `new StatusBarNotification[0]`. Because Aegis F specifies `minSdk = 24`, returning `null` is a reachable platform condition on supported devices.
  - Production code fix in `app/src/main/java/io/github/triet4p/aegisf/notification/BankNotificationListener.kt:231-242`:
    ```kotlin
    val active: Array<StatusBarNotification>? =
        if (activeAnswer != null) activeAnswer() else activeNotifications
    if (active == null) {
        return
    }
    reconcileActivePosts(
        active = active.toList(),
        accessGranted = true,
        allowedPackages = snapshot,
    )
    ```
    If `active` is null, the coroutine returns immediately. It makes no content reads, writes no draft entries, claims no removed history, and leaves existing durable drafts completely untouched.
  - Test Seam & Regression Test:
    - Updated `activeNotificationsForTest: (() -> Array<StatusBarNotification>?)?` to allow returning `null`.
    - Added regression test `an unavailable active answer reconciles nothing and keeps the durable drafts` in `app/src/test/java/io/github/triet4p/aegisf/notification/ListenerRecoveryTest.kt:271-325`.
    - The test verifies:
      1. A pre-existing draft is stored in the database.
      2. The listener's active answer returns `null`.
      3. `listener.onListenerConnected()` is executed and pumped via `advanceUntilIdle()`.
      4. `writes.isEmpty()` is asserted (0 store calls made).
      5. The pre-existing draft remains unchanged in `pending_bank_drafts`.
      6. No unhandled exception or coroutine cancellation occurs.
  - Pre-fix Reproduction: Worker demonstrated that reverting the null check causes `ListenerRecoveryTest` to fail with `java.lang.NullPointerException` inside `BankNotificationListener.reconcileCurrentActive`.
  - Shipped Bytecode Verification: Inspection of `classes7.dex` within `app-debug.apk` confirmed that `reconcileCurrentActive` compiles the `Function0.invoke`/`getActiveNotifications` invocation followed by `move-result` and `if-eqz` branching to `return-void`.
  - Documentation: Documented in `CHANGELOG.md` under `[Unreleased] -> Fixed`.
- **Differential Risk Assessment:**
  - *Risk of data loss:* None; durable database state is unmodified when platform snapshot is unavailable.
  - *Risk of missed intake:* None; subsequent reconnects or incoming live notifications via `onNotificationPosted()` process normally once the listener binding is fully active.
- **Verdict on Finding 2:** **VERIFIED CLOSED**.

## 5. Consolidated User-Only Device Action Checklist

To complete physical acceptance of Sprint 3 and task S3.8, the device owner must run the following consolidated checklist using the final built APK (`app-debug.apk`, SHA-256 `342348b81fd758e4296357c6e0a09cd3613edf37f096cac3b0d8dd2241c5282c`). Redundant initial S3.1 setup tests are omitted as S3.1 was previously verified and accepted in `S3.1-R4`.

### Step 1: Install Update In-Place
- Run from your terminal:
  ```powershell
  adb -d install -r "F:\ai-ml\aegis-f\app\build\outputs\apk\debug\app-debug.apk"
  ```
- *Strict Rule:* Do **not** uninstall or clear app data, so existing database records and notification permissions are preserved.
- Open **Aegis F** → **Bank notifications**; verify status remains **Listener connected** and your bank package is listed.

### Step 2: Natural Bank Notification Delivery & Field Mapping
- Await a real, naturally delivered VietinBank transaction notification on your phone (do **not** fabricate fake money transfers).
- Open **Aegis F** → **Review bank drafts**.
- Check that a new pending draft appears.
- Record the observed Android field mapping: which field carried the message (title vs text vs big-text) and note any reference syntax present on `ND:` or other lines.
- *Strict Privacy Rule:* Do **not** export, screenshot, or share unredacted notification text, account numbers, balances, or OTPs.

### Step 3: Draft Inspection & Atomic Confirmation
- Tap **Review draft #N** on the pending draft.
- Verify:
  - Stated amount is the transaction amount (e.g. 50,000 VND), **not** the balance (`SDC:`).
  - Masked or dot-filled memo shows as unresolved or unedited.
- Select transaction type (**Expense**), choose category, and tap **Confirm transaction**.
- Verify:
  - Draft status transitions to **Confirmed** with linked transaction id.
  - Return to Home screen; verify **THIS MONTH** expense total increments by the transaction amount exactly once.
  - Tapping confirm again or re-opening draft does not double-count.

### Step 4: Duplicate & Distinct Description Verification
- When subsequent notifications arrive:
  - If a transaction arrives with the **same amount** but a **different description** (`ND: REF#101` vs `ND: REF#102`), verify both appear as independent unflagged drafts and can be confirmed separately.
  - If a transaction arrives with **identical description/masking**, verify the later draft is retained and flagged with the warning: *"Possible duplicate. Both drafts are kept for review."*

### Step 5: Draft Dismissal
- On a pending draft, tap **Dismiss draft** → confirm dismissal.
- Verify:
  - Draft status updates to **Dismissed**.
  - Home screen **THIS MONTH** total remains unchanged.
  - Re-delivery/re-reading of the dismissed notification does not re-open it or create a new draft.

### Step 6: Security & OTP Discard Check
- When an OTP, login authorization, or security notification arrives from your bank, observe that **no** draft row is created in **Review bank drafts** and no ledger change occurs.

### Step 7: On-Device Revocation & Manual Continuity
- In Android Settings (`Settings -> Apps -> Special app access -> Notification access`), temporarily toggle off notification access for Aegis F.
- Reopen Aegis F → **Bank notifications**; verify status updates to **Listener disconnected — access revoked**.
- Tap **Record a transaction**; verify manual entry continues to work without error.
- Re-enable notification access in Android Settings.

### Step 8: OS Lifecycle, Screen Lock & Reboot Recovery
- Lock and unlock the screen; verify no draft state is lost or duplicated.
- Force-stop Aegis F (`Settings -> Apps -> Aegis F -> Force stop`) or reboot the device.
- Reopen Aegis F; verify all confirmed ledger transactions, pending drafts, and dismissed drafts persist intact.
- If status shows disconnected, tap **Ask the system to reconnect**; verify listener reconnects and reconciles only currently active notifications without creating duplicate drafts.

### Step 9: UI Sanity Check
- Verify **Review bank drafts** renders properly in portrait orientation, dark theme, and with larger system font scaling, with no truncated text or broken layouts.
