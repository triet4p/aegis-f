## 3. Privacy Boundary & Security Assessment

### 3.1 Ordering Guarantee
Inspection of `decideNotificationIntake` confirms strict short-circuit evaluation:
```kotlin
if (!isIntakePermitted(accessGranted = true, allowedPackages = allowedPackages, packageName = notification.packageName)) {
    return NotificationIntakeDecision.NotPermitted
}
return screenContent(notification.notification)
```
Because `StatusBarNotification.getPackageName()` returns routing metadata without calling `getNotification()`, non-allowlisted packages cannot trigger framework content unpacking. `ContentReadProbe.java` provides concrete verification that `getNotification()` invocation count remains 0 in all non-permitted scenarios.

### 3.2 Information Leakage Prevention
`NotificationIntakeDecision.Rejected` carries only the enum discriminator `NotificationIntakeRejection`. The rejected notification body is discarded immediately upon the return of `screenContent`. Neither `NotificationIntake.kt` nor `BankNotificationListener.kt` contains logging invocations (`android.util.Log`, `println`, or `System.out`), and no database or SharedPreferences writes occur.

### 3.3 Security Marker Boundaries and False-Positive Risk
The security regexes in `SECURITY_PATTERNS` are bounded:
- Word boundaries (`\b`) prevent sub-token collisions in English patterns (e.g., `\botp\b`, `\bnew device\b`, `\bpassword\b`).
- Vietnamese patterns (`mã\s*(?:otp|xác\s*thực|xác\s*nhận|bảo\s*mật|pin)`, `không\s*(?:chia\s*sẻ|cung\s*cấp|tiết\s*lộ)`) specifically target authorization/OTP pushes and security warnings.
- Legitimate bank transaction lines ("Tin biến động số dư", "GD: -50,000 VND", "SDC: xxx,000 VND", "Mã GD", "Ref") do not collide with these patterns.

### 3.4 Permitted Candidate Semantics
`PermittedNotificationContent` contains only `(title: String?, text: String?, bigText: String?)`. It does not parse or populate amounts, debit/credit directions, timestamps, or account numbers. It remains purely an intake candidate awaiting downstream parser logic (S3.3) and draft lifecycle storage (S3.4).

Task S3.7 will implement active notification reconciliation via `NotificationListenerService.getActiveNotifications()` upon reconnection.
