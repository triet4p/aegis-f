## 1. Executive Summary

Worker `S31SetupA1` implemented the static and local boundaries for task S3.1: the system-bound service declaration in `AndroidManifest.xml`, the Jetpack Compose `BankNotificationSettingsScreen`, the `NotificationAccessStore` backed by `SharedPreferences`, the `BankNotificationListener` skeleton with package-only routing and no content intake, navigation entry from `MainActivity`, documentation in `README.md` and `CHANGELOG.md`, and 7 host-side Robolectric boundary unit tests.

However, the review verdict is **FAIL** (`advance: false`) due to material unverified acceptance criteria and actionable evidence gaps:

1. **Material Acceptance Criteria Unverified on Physical Device / Runtime:** Due to the absence of an Android runtime (no emulator and project rules reserving `adb` and physical device access for the user), key observable acceptance criteria—granting access in Android settings, real-device listener binding callbacks, revocation state updates, restricted-settings unlocking on Android 13/14+, and on-device manual recording compatibility—remain unverified. Per review instructions, these material gaps cannot be converted to a passing gate verdict without physical device execution.
2. **Behavioral Smoke Claim Gap:** The worker reported a passing 7/7 "throwaway behavioral smoke" for the state/gate surface; however, examination of worker history (`history://S31SetupA1` event 478) confirms this smoke was a JavaScript reimplementation in Node.js against a temporary JSON file, not execution of the changed Kotlin code.
3. **Source Architecture Fragility:** `isNotificationAccessGranted()` relies on reading the hidden and deprecated `Settings.Secure.getString` key `"enabled_notification_listeners"` with manual string parsing rather than the official Android framework method `NotificationManager.isNotificationListenerAccessGranted(ComponentName)`.
4. **Listener Connection Race Risk:** Allowlist loading in `BankNotificationListener.onListenerConnected()` is dispatched asynchronously on `Dispatchers.IO` while defaulting to `emptySet()`, creating a transient race where notifications posted at listener bind time could be silently dropped.

### Finding 3: Use of Deprecated/Hidden `Settings.Secure.getString` Instead of Platform API

- **Severity:** MEDIUM
- **Target:** `app/src/main/java/io/github/triet4p/aegisf/notification/NotificationAccess.kt:29-38`
- **Claim:** Detection of granted notification access bypasses the official Android API in favor of raw string parsing on a hidden `@hide` setting key.
- **Evidence:**
  ```kotlin
  fun isNotificationAccessGranted(context: Context): Boolean {
      val enabled = Settings.Secure.getString(
          context.contentResolver,
          ENABLED_NOTIFICATION_LISTENERS,
      ) ?: return false
      val component = ComponentName(context, BankNotificationListener::class.java)
      return enabled.split(':').any { entry ->
          entry == component.flattenToString() || entry == component.flattenToShortString()
      }
  }
  ```
- **Why It Matters:** In AOSP, `ENABLED_NOTIFICATION_LISTENERS` is annotated `@hide` and `@deprecated`. Since API 27 (Android 8.1), Android provides `NotificationManager.isNotificationListenerAccessGranted(ComponentName)`. While reading the setting is currently annotated `@Readable` in standard AOSP, manual parsing of colon-separated flattened component strings risks OEM variations (e.g. OEM-specific component formatting or security restrictions) and lacks any automated unit test in `NotificationAccessSetupTest.kt`.
- **Confidence:** HIGH

---

### Finding 4: Asynchronous Allowlist Loading in `onListenerConnected()` Risks Dropping Intake

- **Severity:** LOW
- **Target:** `app/src/main/java/io/github/triet4p/aegisf/notification/BankNotificationListener.kt:35-42,57-60,83-85`
- **Claim:** An asynchronous dispatch to load allowlisted packages during `onListenerConnected()` creates a race condition upon listener startup.
- **Evidence:**
  ```kotlin
  @Volatile
  var allowedPackages: Set<String> = emptySet()
      private set

  override fun onListenerConnected() {
      connectionState.value = ListenerConnection.Connected(System.currentTimeMillis())
      serviceScope.launch {
          allowedPackages = NotificationAccessStore(applicationContext).loadAllowedPackages()
      }
  }
  ```
- **Why It Matters:** If the system delivers pending or active notifications immediately upon binding, `onNotificationPosted()` evaluates `if (!allowedPackages.contains(packageName)) return`. Because `allowedPackages` starts as `emptySet()`, notifications arriving before the IO coroutine executes will be treated as non-allowlisted and silently dropped. Because `NotificationAccessStore.loadAllowedPackages()` is backed by in-memory cached `SharedPreferences`, loading can be performed synchronously or synchronized prior to callback evaluation. (Nonblocking in S3.1 because intake is omitted, but directly impacts S3.2+).
- **Confidence:** HIGH

### Analysis 5: System-Bound Listener Binding Semantics (`android:exported="false"`)

- **Severity:** INFO
- **Target:** `app/src/main/AndroidManifest.xml:18-26`
- **Finding:** The listener is declared with:
  ```xml
  <service
      android:name=".notification.BankNotificationListener"
      android:exported="false"
      android:label="Aegis F bank notification listener"
      android:permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE">
      <intent-filter>
          <action android:name="android.service.notification.NotificationListenerService" />
      </intent-filter>
  </service>
  ```
- **Evaluation:** Verified against AOSP platform architecture. The Android system server (`NotificationManagerService` running as UID 1000) possesses platform root privileges and explicitly bypasses `android:exported="false"` restrictions when binding enabled listeners. Google AOSP documentation and best security practices recommend `android:exported="false"` alongside `android.permission.BIND_NOTIFICATION_LISTENER_SERVICE` to prevent third-party applications from directly querying or binding to the service. This declaration is structurally sound.
- **Confidence:** HIGH
