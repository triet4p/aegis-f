3. **Catalog seeding:** six categories inserted into each isolated DB while the app was stopped (S7.7's established method); identical ids/names/epochs. Baseline schema v11, current v12; no migration involved in the isolated installs.
4. **Model copy:** `run-as` app UID cannot write `/data/local/tmp` (`tar … Permission denied`), so the model was streamed from the user's app to the isolated app through one `adb shell` pipe; onnx/config hashes verified on the isolated side.
5. **Stale notifications:** the still-active S7.7 synthetic shell posts were re-read as extra drafts on first connect. They were snoozed (keys in `snoozed-shell-keys.txt`) before the clean reinstall, so neither build carries foreign drafts. All fixture draft rows verified id 1–7 with the exact memos/amounts.
6. **Measurement definitions (for the resume):** description-entry count = number of drafts where the user had to type a suggestion note/description to obtain a model suggestion (earlier path: B, C, D, E; current path: 0). Deliberate taps counted from driver actions, excluding ADB sleeps; swipes and text entries reported separately; review wall time decomposed into explicit inference waits, driver overhead (measured per action) and residual. 7. **Same final decisions planned in both builds:** E confirm Food → F dismiss → B Food → C Bills → D Shopping → A accept Housing → G correct Entertainment to Food → confirm. Expected ledger: 6 confirmed expenses, 9,847,000 VND, 0 income, 0 transfers, 0 pending, no duplicate confirmation.
