The S7.5 single-entry read (`ReviewQueueDao.findOrderRow` / `WorkflowQueryService.reviewQueueEntry`) uses the same policy view for the detail.   - **Relative confidence only under S7.1 L1–L6.** `RelativeConfidence` is produced only for a fresh `MODEL` entry in `ReviewQueueGroup.SUGGESTION` whose suggested id resolves to an active category, with no stale reason, no user resolution, no possible duplicate/proposed link/unresolved bank data, and a well-formed distribution. No numeric cutoff was invented. The card and detail labels state the top share, no-fit share, sharpness and evaluated scope, call it a suggestion among the evaluated options, and state it is not a guarantee and never auto-confirmed. A sharp prediction on a Rank 0 proposed link carries no label.
  - **Cancel / retry / manual choice.** The durable queue gained `cancel(draftId)` (conditional `cancelActiveForDraft`, plus cancellation of the in-flight attempt so the boundary discards a late native answer) and `retry(draftId)` (normal admission, explicit retry re-arms a user cancellation). A duplicate re-report never re-arms a `USER_CANCELLED` job. The detail exposes **Cancel check**, **Retry check / Retry stale suggestion**, **Re-read stored suggestion / Refresh suggestion**, **Open model setup** on a model/inference failure, and the existing category controls. A manual category choice still only stages the field, and **Save corrections** remains separate from **Confirm transaction**.
  - **Context without leaving review.** Attaching/unlinking a note excerpt or saving a corrected description marks the shown stored suggestion as outdated and shows an explicit refresh; the panel never swaps scores under the user. The live status shows the queued/checking work, and the explicit refresh reads the improved stored suggestion. F1/F3 focus behaviour is unchanged.
