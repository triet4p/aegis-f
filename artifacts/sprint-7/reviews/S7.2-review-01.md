## 3. Acceptance Criteria and Contract Verification

### 3.1 Real Intake Persists First, Then Bounded Revision-Aware Enqueue

- In `IntakeRepository.kt`:
  - `storePermitted` runs within `database.withTransaction`:
    - `storedDraftId = draftDao.store(draft)`
    - `storeBankEvidenceReference(storedDraftId, draft)` (if `PARSED`)
  - Only after the transaction has successfully committed, `notifyDraftStored(draftId)` is invoked for `PARSED` drafts.
  - `notifyDraftStored` wraps the invocation in `try { onDraftStored(draftId) } catch (error: Exception) { Log.w(...) }`, guaranteeing that a queue failure or exception cannot fail or roll back the durable intake persistence.
  - Drafts with `UNSUPPORTED_FORMAT` do not call `notifyDraftStored`, ensuring no invalid work is scheduled.
- In `BankDraftClassificationQueue.kt`:
  - Enqueue is bounded via `Channel<Long>(capacity = 32)`.
  - Non-blocking admission: `synchronized(lock)` checks `closed`, dedupes via `tracked.add(draftId)`, and executes `pending.trySend(draftId)`. A full queue logs a warning and leaves the draft unclassified without blocking or throwing.
  - A single background coroutine (`worker`) processes items sequentially on `Dispatchers.IO`, ensuring only one native model inference runs at a time.
  - Each item is bound to its context and catalog revisions via `intakeClassificationRequestKey`, which creates a canonical digest over `["INTAKE_CLASSIFICATION", draftId, dependencies.contextRevision, dependencies.categoryRevision]`.
