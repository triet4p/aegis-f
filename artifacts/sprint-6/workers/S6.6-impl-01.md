## What changed

- **Shared query surface** (`WorkflowQueryTypes.kt`, `WorkflowQueryService.kt`, `NoteEventDao.kt`): new bounded `draftContextLinks(draftId, bounds)` returns each stored link with its state/revision, the reading, and the **exact source excerpt** of the span, plus a truthful `sourceCurrent` flag (false when the capture moved on, is a tombstone, or the span no longer fits). `UnrecordedNoteEvent` now carries the same exact `excerpt`, so the manual picker never shows a reading in place of the user's words. Added a batched `NoteEventDao.findByIds` rather than N reads.
- **Review screen** (`BankDraftReviewScreen.kt`): the draft detail now renders one scrollable review flow — bank source and stated fields, possible duplicates, **note context**, editable amount/date/time/description, type, model probabilities/confidence and the category selection, corrections, confirm, dismiss. Note context cards show attached/proposed/refused excerpts with provenance (`Saved note #N · event #N`, reading revision, link revision) and explicit **Attach / Refuse / Unlink** through the shared command boundary; **Add note context** opens a bounded list of complete, unlinked saved notes with "Attach as context". Empty, loading, error+retry and model-unavailable states are explicit; every action states that the bank amount, review fields and ledger are unchanged.
- **Stale preview and failed commands:** the pending confirmation keeps both the preview and the edits it was made from. The dialog compares them with the live draft revision and the current form: a moved draft or moved form is titled "Preview is stale", names the revisions, states that nothing was written, withholds Confirm and offers "Check current values". A confirmation now carries the preview's own revision/binding/edits, so checking current values restores confirmability. A failed command leaves the draft, the dialog outcome message and the user's unsaved fields in place.
- **Shared helper reuse** (`QuickCaptureEvents.kt`): `decideUserLink` and the link outcome/message helpers are now internal and parameterized by the explicit user-override text, so Review and Quick Capture use one link path instead of a second convention.
- **Docs:** `README.md`, `CHANGELOG.md` and `.agents/memory/lessons-learned.md` (one product lesson on preview-binding identity and one harness lesson on Telex input/personal-banner hygiene) describe the review context, provenance and stale-preview behavior.

## Product defect found and fixed by the rendered flow

- **Defect:** after "Check current values" produced a current preview, pressing Confirm failed with "The draft changed under the caller." every time a re-preview followed a moved draft.
- **Cause:** `confirm()` sent the form's saved `expectedRevision` and the current edits while the dialog held a preview computed from a newer revision.
- **Fix:** the confirmation now carries the preview's `expectedRevision`, `binding` and `edits`, and `preview()` adopts the preview revision. Re-proven on the phone: stale dialog → Check current values → Confirm → exactly one record (`21`→`28`).
