## Provenance decision

Followed the existing policy rather than creating a second capture convention:

- `docs/sprint-5-capture-persistence.md:7-19`: `USER_NOTE` / `USER_QUICK_CAPTURE`, stable UUID source identity, capture instant/timezone, revision-CAS body replacement, text-free tombstone.
- `docs/sprint-5-event-context-persistence.md:87-104`: editing/deleting clears derived event content and active links in the same Room transaction; refused links stay; event/source identity remains; confirmed ledger is untouched.

The existing repository already supported deletion, but the shared command boundary did not. `WorkflowCommandService.deleteCapture` now applies authorization, current-revision checks, repository policy, and durable idempotent outcome recording through the shared operation codec. No UI-to-DAO bypass or compatibility shim was added.
