## Changed scope

- **New `ui/AppShell.kt`** — the four-destination shell:
  - private `PrimaryDestination` enum: Dashboard, Chat / Quick Capture (visible label `Chat`), Review notifications (visible label `Review`), Manual;
  - a text-labelled bottom bar with role/selected/content-description semantics, ≥56 dp items, a selected underline, and a live `N waiting` badge on Review;
  - one saveable secondary stack per destination (Settings/Bank notifications/Model setup; Categories/Transaction list/New transaction/Detail/Edit; draft detail), so back pops the current route, then returns a non-Dashboard destination to Dashboard;
  - `rememberSaveableStateHolder` keyed by destination so every `rememberSaveable` value inside a destination (editor fields, page indices, list scroll, category dialogs) survives switching to another destination and back;
  - Dashboard root reuses `CurrentMonthExpenseSummary`; Manual root reuses the existing record/browse/categories actions; Settings hub routes to the existing bank-notification and model screens; Chat root is an honest empty destination with real manual actions.
- **`MainActivity.kt`** — removed the old home-screen `LaunchDestination`/`LaunchScreen`; the activity now owns services and mounts `AegisAppShell`. Theme unchanged.
- **`ui/BankDraftReviewScreen.kt`** — optional `showBack` (default `true`) so the inbox can be a destination root with no Back control or back-gesture handler; inbox title is now `Review notifications`; detail behaviour unchanged.
- **`ui/ExpenseSummaryPanel.kt`** — comments now say Dashboard, not home screen.
- **`ui/LayaProvisioningScreen.kt`, `ui/TransactionEditorScreen.kt`, `ui/TransactionListScreen.kt`** — user-facing copy that pointed at the old home screen now points at the Manual destination.
- **`README.md`**, **`CHANGELOG.md`** — user-facing navigation/feature paths and the unreleased Added entry.
- No data-layer, Room schema, model, command or query changes. No new dependency.

## Baseline (captured before the UI changed)

### Isolation and seed procedure

The user's own install and personal data were never used as the test dataset.

1. From the base commit, a temporary `applicationIdSuffix = ".s6evidence"` was added to `defaultConfig` in `app/build.gradle.kts`, producing package `io.github.triet4p.aegisf.s6evidence` beside the user's package. The suffix was reverted before the final production build (verified: no `applicationIdSuffix` remains, APK package is `io.github.triet4p.aegisf`).
2. Notification-listener access was granted to the isolated component with
   `adb shell cmd notification allow_listener io.github.triet4p.aegisf.s6evidence/io.github.triet4p.aegisf.notification.BankNotificationListener`.
3. Dataset, built through the app's own UI with the pre-change build:
   - one manual expense **123,000 VND**, description `S61 seed manual` in the first manual seed and `S61seed` in the reproducible seed command, Expense, today's device date;
   - allowlist entry `com.android.shell` added on the Bank notifications screen;
   - one synthetic pending draft posted by `com.android.shell` with the supported VietinBank shape:
     `VietinBank: 22/10/2026 08:15 / TK: Redacted / GD: -45,000 VND / SDC: xxx,000 VND / ND: S61 seed draft`.
     No real bank notification or account data is involved; other apps' notifications are dropped before content is read.
4. Baseline measurements then ran the driver below; each run added a disposable 45,000 VND record, so every run started from `123,000 VND + one draft` and the same screen state.

The reproducible driver is [`../evidence/s61_driver.py`](../evidence/s61_driver.py). Its `seed` command reproduces the same dataset through the shipped UI and the notification post; it assumes the isolated package's data was cleared. The `after` runs and `s61_verify.py` rely on that seed.

Elapsed is monotonic wall time from the UI being ready to the completion text, including a fixed 0.6 s settle after each action and the `uiautomator` dump cost. It is a like-for-like automation measure, not a human-interaction claim.

## Limits and deliberate boundaries

- **Chat / Quick Capture has no capture UI yet.** S6.4 owns persistence/retry/history; S6.5 owns split/attach. The destination is present and truthful (no saved text, no reply, no match, no transaction) and links to the real manual entry. This is a scope boundary, not a fabricated feature.
- **Dashboard** intentionally reuses only the existing confirmed-month summary; cards/filters and charts belong to S6.2/S6.3. Review self-containment and Manual simplification belong to S6.6/S6.7.
- **Back from an unsaved draft** still leaves without saving, exactly as before this task; the form explicitly says leaving changes nothing. The S6.1 guarantee exercised here is that *switching destinations* preserves the draft (and that shell-level back does not reset filters or another destination's state). If the reviewer reads "back" as including the editor's own leave action, that is an existing, documented behaviour rather than a shell state loss. Re-tapping the already-selected destination returns to its root (standard bottom-navigation behaviour); the unsaved-draft guarantee covers switching to another destination and returning.
- The model screen's Back cancels an in-flight model check before it leaves (existing behaviour); the production smoke waits for the check to settle before pressing back. Not a regression.
- The old home screen's static **CURRENCY CONTEXT** card and closing tagline were not carried over: they held no data and no action. Every actionable or data-bearing home surface — the month summary, record/browse actions, categories, bank notifications, model setup and draft review — is routed and reachable.
- Dark theme was the device state for all screenshots; light theme and large-font/TalkBack checks are S6.8 scope. Bottom-bar items are ≥56 dp tall with selected-state semantics, underline and bold weight (not color alone); top-level screens use the existing Material insets, and no overlap was observed at 720×1610.
- The isolated evidence package `io.github.triet4p.aegisf.s6evidence` is **still installed** with the synthetic dataset so the reviewer can inspect it directly. Its notification access is limited to the allowlisted synthetic `com.android.shell`; personal bank packages are not allowlisted and are dropped before content is read. The production package is also installed (data preserved) and was only navigated read-only.
