## Actionable findings

1. **MEDIUM — A source-event save can bypass its expected revision.** `SaveManualTransactionRequest.expectedSourceEventRevision` is nullable (`app/src/main/java/io/github/triet4p/aegisf/data/FinancialCommandTypes.kt:69-79`), and `saveManualTransaction` checks the event revision only when the value is non-null (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandService.kt:1411-1426`). A request may name `sourceEventId` while omitting the revision, allowing a caller with a stale event selection to resolve the current event state without a compare-and-set. This can attach a ledger record to an edited or cleared note reading and bypasses the documented “revision of the reading the caller read” rule. The current editor supplies the selected event's revision (`app/src/main/java/io/github/triet4p/aegisf/ui/TransactionEditorScreen.kt:500-510`), but that does not close the command contract's bypass. **Confidence: high.**

2. **LOW — Terminal draft no-change outcomes can identify the wrong state.** When `dismissDraft` receives a draft already confirmed, the terminal branch returns `NoChange(change = DraftDismissed(...))` (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandService.kt:1812-1818`), although `WorkflowChange.DraftDismissed` is documented as a draft that was dismissed (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandTypes.kt:230-231`). Likewise, terminal `saveDraftReview` reports `DraftReviewSaved` even when the draft is confirmed or dismissed (`WorkflowCommandService.kt:1586-1592`). A consumer using the structured change rather than the optional detail receives a false state summary. **Confidence: high.**
