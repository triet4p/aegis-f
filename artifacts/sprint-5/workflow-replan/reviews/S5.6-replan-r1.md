## Actionable findings

1. **HIGH — Agent-supplied link evidence satisfies attach policy without trusted proof.** `ProposeLinkRequest.evidence` is an arbitrary nullable `String` request field (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandTypes.kt:237-242`); `proposeLink` persists it unchanged (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandService.kt:248-272`), and agent attachment accepts any nonblank value plus no second active link (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandService.kt:346-347, 786-790`). The boundary never verifies that evidence against app-trusted facts. The test itself demonstrates this by accepting agent-authored text such as `"same day, same amount"` (`app/src/test/java/io/github/triet4p/aegisf/data/WorkflowCommandServiceTest.kt:449-474`). An agent/model can therefore assert fabricated evidence and promote a link the policy reserves for a unique evidence-supported association. **Confidence: high.**
2. **MEDIUM — Link scope checks occur after a protected event lookup, and the key replay lookup precedes scope.** `proposeLink`, `attachLink`, and `unlinkLink` call `eventDao.findById` before checking the event's capture scope (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandService.kt:262-265, 327-330, 479-482`), so an agent can distinguish a nonexistent event (`NotFound`) from an existing out-of-scope event (`Denied`). Separately, `runCommand` and classification read the global idempotency table before the target-scope check (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandService.kt:695-697, 560-563`); a foreign key yields a different generic conflict response. No payload is returned, but protected existence/replay state is observable, contrary to the assigned scope-before-read/leak criterion. **Confidence: high.**
3. **MEDIUM — Concurrent same-key classification requests can both invoke inference.** Classification checks for a recorded key, then runs `decideRememberedBeforeInference` / the engine before inserting the unique operation row (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandService.kt:560-561, 585-595, 624-671`). Unlike the common write path's transaction around effect+record (`app/src/main/java/io/github/triet4p/aegisf/data/WorkflowCommandService.kt:685-708`), there is no in-flight claim/serialization for classification, so two concurrent same-key misses may each call the model before one transaction loses the unique-key race. The concurrency regression covers only `saveCapture` (`app/src/test/java/io/github/triet4p/aegisf/data/WorkflowCommandServiceTest.kt:170-193`); no classification-race evidence closes this gap. This weakens concurrent idempotency and can duplicate expensive inference. **Confidence: high.**
