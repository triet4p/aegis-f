## 1. Executive Summary & Review Scope

Task S10.1 delivers the complete mobile UI/UX redesign specification and interactive prototype for Aegis. Following the technical PASS of cycle `S10.1-cycle-1`, the product owner introduced two authoritative scope refinements:
1. **Dedicated Streaming AI Chat Screen:** A dedicated, discoverable conversation screen (`AiChatScreen`) with incremental token streaming, visible lifecycle state indicators (waiting, streaming, tool-working, completed, stopped, error), composer/Send/Stop behavior, in-context draft link actions, conversation history, and clear decoupling of quick note saving from AI execution.
2. **Anti-Stacking & Single-Task Ergonomic Principle:** Every screen must embody **one defined user task and one primary action (CTA)**. Avoid vertically stacking unrelated functional component blocks even when polished. Secondary workflows, deep forms, and multi-item feeds are delegated to dedicated child screens or contextual sheets. Information density is permitted strictly when presenting data serving the same task (e.g. digital receipt breakdown, KPI analytics comparison), never as an endless vertical pile of heterogeneous functional launchers.

Reviewer `S101ChatEvidence` conducted an independent, read-only audit of the updated candidate deliverables against `docs/sprint-plans/sprint-10.md`, `docs/design/sprint-10-mobile-experience-specification.md`, worker report `artifacts/sprint-10/workers/S10.1-streaming-design-a1.md`, visual screenshot assets (`artifacts/sprint-10/renders/`), and the running web prototype served at `http://127.0.0.1:8085/` via automated headless Chromium browser testing (`eval(language="js")`).

The assessment concludes that while the synthetic streaming AI chat lifecycle (incremental chunks, Stop invariant, zero late chunks, in-context `LinkEvidenceCard`, and offline handling) is well-implemented and truthful, **the candidate fails the Owner's core anti-stacking mandate on `HomeScreen`** and leaks internal implementation jargon onto everyday user screens. Consolidated `changes_requested` is issued (`advance: false`), consuming Round 1. A fresh designer correction attempt will address these findings in Round 2.

## 3. Actionable Findings (Consolidated for Round 2 Correction)

### Finding 1: Home Screen Layout Remains a Stack of 4 Component Blocks with Heavy Cross-Screen Redundancy (HIGH)
- **Claim:** Despite being described in the worker report as an "unstacked Task Launcher & Financial Glance", `HomeScreen` continues to stack 4 distinct vertical cards that consume the entire mobile viewport, while redundantly replicating actions already present in the persistent navigation bar.
- **Evidence:**
  1. *DOM Measurements & Visual Inspection (`artifacts/sprint-10/prototype/app.js:564-681`, `01_home_screen.webp`):* In an 798px viewport, Home piles:
     - Hero Financial Balance Card: height **179px** (spent VND, privacy eye toggle, income, net cashflow).
     - Primary 8-Item Feature Grid Card: height **224.5px** (titled card container with 8 squircles).
     - Contextual Pending Review Alert Card: height **69.8px** (full-width warning block).
     - Full Ledger Shortcut Card: height **69.8px** ("Xem toàn bộ sổ giao dịch ›").
     - Total height of stacked functional blocks: **543px** (68% of total viewport height).
  2. *Action Duplication / Redundancy Across Screen:*
     - **Sổ quỹ / Sổ giao dịch (Ledger):** Appears 3 times on the same screen — in the 8-item feature squircle grid (`feature_ledger`), in the bottom full-width shortcut card (`view_all`), and in the persistent bottom navigation tab (`tab-ledger`).
     - **Duyệt tin / Duyệt biến động (Review):** Appears 4 times on the same screen — in the top app bar bell icon with badge `2`, in the feature grid squircle with badge `2`, in the full-width alert warning card, and in the persistent bottom navigation tab with badge `2`.
     - **Cài đặt (Settings):** Appears twice — in the top app bar (avatar + gear button) and in the feature grid squircle.
- **Why it matters:** The product owner's explicit feedback was:
  > *"Hạn chế việc stack các khối component trong cùng 1 màn hình. Cố gắng mỗi màn nên chỉ đảm nhiệm 1 nhiệm vụ nào đó xác định."*
  Home's singular defined task is to be a **lightweight task launcher** where the user chooses what they want to do. Piling a giant financial card, an icon grid, an alert banner, and a ledger shortcut turns Home right back into a vertical card stack. Detailed financial balance and cashflow breakdowns belong in `AnalyticsScreen` / `Reports`. Unreviewed draft alerts should be indicated via a badge counter on the launcher squircle and top bell (not an extra full-width card). The duplicate "Xem toàn bộ sổ giao dịch ›" shortcut card should be removed as it has no unique purpose.
- **Confidence:** HIGH (confirmed by DOM bounding rects in Chromium, visual inspection of `01_home_screen.webp`, and Main's direct observation).

### Finding 2: Developer & Architecture Jargon Leaks onto Everyday Screens (MEDIUM)
- **Claim:** Implementation details ("SQLite", "0 token", "Turn #run-...") leak into everyday user-facing copy on `QuickCaptureScreen` and `AiChatScreen`, and history session clicks trigger alert modals rather than restoring conversation turns.
- **Evidence:**
  1. *Quick Capture Note Composer (`app.js:1079`, `app.js:86,157`):* Displays `<span style="font-size: 11px; color: var(--fg-muted);">Lưu SQLite · 0 token · Tức thì</span>`. In I18N token dictionary: `note_saved_success: "Note saved to local database (0 tokens used)"` / `"Đã lưu ghi chú vào cơ sở dữ liệu cục bộ (0 token)"`. Furthermore, saving a note executes `alert("Đã lưu ghi chú cục bộ an toàn!")`.
  2. *AI Chat Conversation History Sheet (`app.js:1317-1323`, `app.js:374-395`):* Displays internal database run IDs `Turn #${sess.runId}` (e.g. `Turn #run-20241109-01`) and raw unformatted backend status enums `SUCCEEDED` / `CANCELLED`.
  3. *History Item Tap Action (`app.js:2197-2204`):* Clicking a past session triggers a browser modal `alert('Đã nạp lịch sử hội thoại Turn #${runId}')` rather than populating the transcript with that session's actual messages.
- **Why it matters:** Acceptance Criterion 24 mandates that everyday screens remain free of developer/operational jargon. Ordinary mobile finance users should see humane copy like "Lưu trên máy · Tức thì · Không cần mạng" / "Saved to device (Offline)", not internal engine names like SQLite or token counts. In conversation history, sessions should display relative timestamps ("12:35 · Hôm nay"), user prompt titles, and localized status badges ("Hoàn thành", "Đã dừng"), and tapping a session must restore its conversation turns into the transcript.
- **Confidence:** HIGH (verified by source inspection and interactive browser execution).

### Finding 3: AI Chat Floating FAB Overlaps Sticky Composer and Transcript Padding Clips Content (MEDIUM)
- **Claim:** The floating scroll-to-bottom FAB visually collides with and overlaps the sticky composer bar, and the transcript bottom padding is smaller than the composer bar, causing the active stream cursor and bottom messages to be clipped.
- **Evidence:**
  1. *FAB Overlap (`style.css:1421-1439`, `style.css:1344-1356`):* `.scroll-bottom-fab` has `position: absolute; bottom: 80px; right: 16px;`. The `.chat-composer-bar` has a rendered height of **98px** (Y=862 to Y=960). The FAB is positioned at Y=857 to Y=886, overlapping the top of the composer bar by **24 vertical pixels** (`overlaps: true`). This collides with prompt suggestion chips and creates overlapping touch targets.
  2. *Transcript Scroll Padding (`style.css:1090`):* `.chat-transcript-area` has `padding-bottom: 90px`. Because the composer height is 98px–110px, the bottom 8px–20px of the message transcript and active typing caret `▍` are obscured behind the composer container when scrolled down.
- **Why it matters:** Violates Acceptance Criterion 22 (touch targets, scrolling, insets). The floating FAB must float safely above the composer bar (`bottom: calc(var(--composer-height, 105px) + 12px)`), and transcript bottom padding must comfortably accommodate the composer height plus gesture pill insets.
- **Confidence:** HIGH (measured via Puppeteer DOM bounding rects in Chromium).

### Finding 4: AI Chat Tool-Working State Representation & Language Switch on Bottom Nav (LOW)
- **Claim:** The tool-working state in AI Chat is rendered as a minimal inline status pill rather than a distinct tool execution card, and toggling language to English leaves the persistent bottom navigation tabs in Vietnamese.
- **Evidence:**
  1. *Tool-Working Representation (`app.js:1226-1234`, `15_chat_streaming.webp`):* During `TOOL_WORKING` (chunk 5), the assistant bubble only shows a small text pill `🔍 Đang đối chiếu biến động ngân hàng...` beneath the streaming text. A structured tool progress card showing what tool is running and what it is querying would provide clearer differentiation from text generation.
  2. *Bottom Navigation I18N (`app.js:405-411`, `index.html:76-98`):* While `toggleLanguage()` updates views rendered dynamically by `renderScreen()`, static elements with `data-i18n` in `index.html` (including the 5 bottom navigation tabs) are not dynamically re-translated, remaining in Vietnamese ("Trang chủ", "Sổ quỹ", "Ghi chép", "Trợ lý AI", "Duyệt tin") when English is selected.
- **Why it matters:** Distinct tool execution feedback prevents users from mistaking autonomous tool queries for final answers. English-first contract requires all primary navigation tabs to reflect the selected language.
- **Confidence:** HIGH (verified in browser execution).

## 5. Required Round 2 Corrections for Designer

1. **Re-architect `HomeScreen` into a True Lightweight Task Launcher:**
   - Replace the stacked 4-block layout with a clean, unstacked launcher.
   - Make the Hero Financial Glance genuinely compact (e.g. single-line period spend with eye toggle, or move detailed income/net breakdown to `AnalyticsScreen`).
   - Remove the titled card container around the 8-item feature squircle grid; let the feature icons sit directly on the screen surface as primary launchers.
   - Remove the full-width alert warning card; display pending review count strictly as a notification badge counter on the "Duyệt tin" launcher squircle and top bar bell icon.
   - Remove the redundant "Xem toàn bộ sổ giao dịch ›" shortcut card (the Sổ quỹ squircle and bottom navigation tab already provide immediate access).
2. **Purge Developer / Database Jargon on Everyday Surfaces:**
   - Replace `"Lưu SQLite · 0 token · Tức thì"` and `"0 tokens used"` on Quick Capture with user-friendly copy: `"Lưu trên máy · Tức thì · Không cần mạng"` / `"Saved to device (Offline)"`. Replace browser `alert()` modal with clean inline toast/feedback.
   - In AI Chat History, replace `"Turn #run-..."` with prompt title and relative time ("12:35 · Hôm nay"), and replace `"SUCCEEDED"` / `"CANCELLED"` with localized status badges ("Hoàn thành", "Đã dừng").
   - Implement `loadChatSession` to actually load the selected session's prompt and responses into the transcript area, rather than showing a browser `alert()`.
3. **Fix Chat Viewport Overlap and Transcript Padding:**
   - Anchor `.scroll-bottom-fab` safely above `.chat-composer-bar` (`bottom: calc(var(--composer-height, 105px) + 12px)`) so it never overlaps the composer or prompt suggestions.
   - Increase `.chat-transcript-area` bottom padding to `115px` to ensure the active typing caret and bottom message are never clipped behind the composer.
4. **Enhance Tool-Working Card & Bottom Navigation I18N:**
   - Render a distinct tool execution card/box during `TOOL_WORKING` showing the active query context.
   - Update `toggleLanguage()` to translate static `[data-i18n]` elements in `index.html` (especially the 5 bottom navigation tabs) into English when English mode is active.
5. **Re-capture Visual Renders:**
   - Update `01_home_screen.webp`, `07_quick_capture.webp`, `15_chat_streaming.webp`, `19_chat_history.webp`, and `gallery.html` to reflect the corrected designs.
