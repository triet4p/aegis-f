## 7. Actionable Findings (Must Fix in Round 2)

**F1 — MEDIUM — First source-prefill can overwrite user-typed values (unexercised race, safety).**
Evidence: `TransactionEditorScreen.kt:340-380` — the source-load `LaunchedEffect` applies `amountText`/`dateText`/`timeText`/`descriptionText` whenever `!sourcePrefillApplied`, without checking `editedSinceOpen` (declared ~line 333, set true only by user edits). If the user types during the first read, the completing prefill overwrites those keystrokes; the card shows Loading and Save is disabled, but the fields stay editable. Today's suite never races the first read, so this is disclosed-unexercised, not proven behavior — and it is a genuine silent-entry-loss shape on the exact screen whose contract forbids silent loss. Worker proposed the minimal guard (`if (!sourcePrefillApplied && !editedSinceOpen)`); reviewer agrees it preserves note loading + revision send while protecting typed input.
Why it matters: the same contract that demands stale/missing refusals keep typed values must also protect keystrokes typed before the first async note read lands.
Confidence: HIGH (source-verified; unexercised-at-runtime by both sides' admission).

**F2 — LOW — Retained archived category badge in the full sheet is hardcoded English.**
Evidence: `CategoryChoiceSheet` → `CategoryChoiceRow(..., archived = true, ...)` (~lines 1415-1421) → `ArchivedCategoryBadge()` with default `label = "ARCHIVED"` (`CategoryPalette.kt:90`), while the quick tile path passes localized `baseStrings.archivedLabel` (`TransactionEditorScreen.kt:744,1052,1107,1174`; VI = `Đã lưu trữ`). A Vietnamese correction carrying a retained archived category would show `ARCHIVED` inside the sheet. Fix: thread the same localized label into the sheet/row (no data/routing change).
Why it matters: VI parity is an explicit acceptance item; the rest of the screen is fully localized.
Confidence: HIGH.

**F3 — LOW — Category tile accessibility description appends English-only ", selected".**
Evidence: `CategoryTile` `contentDescription` (`TransactionEditorScreen.kt:1111-1115`): archived uses the localized label, but selection appends the literal `", selected"` with no VI equivalent; the `selectable(..., role = Role.RadioButton)` semantics already expose selection state, so the suffix can be removed or localized. Fix: drop the suffix (preferred — no new strings) or localize it.
Why it matters: VI/accessibility parity on the primary category control; trivial, behavior-preserving.
Confidence: HIGH.
