## 1. Executive Summary & Review Scope

Task S10.4 delivers the decoupled, privacy-first local note journaling experience for Aegis, upholding the owner-approved S10.1 single-task-per-screen architecture and anti-stacking mandate (`docs/sprint-plans/sprint-10.md:15-26, 44-47, 79-94`, spec §3.6, screen spec §6):

- **Focused Notes Root (`QuickCaptureScreen`):** Dedicated strictly to writing and locally persisting one quick note (`CaptureMessageEntity`). Features an uppercase title, a clean note text area, humane copy ("Saved on this device · Works offline · Instant" / "Lưu trên thiết bị · Không cần mạng · Tức thì"), one primary action **Save note** with in-page feedback, a guarded **Clear draft** dialog, and a single navigation entry row into **Saved notes**. Saving writes locally to Room and strictly initiates no hosted request, no background agent run, no ledger entry, and no draft link.
- **Saved Notes Browsing (`SavedNotesScreen`):** A dedicated child browse destination presenting active user quick captures newest-first with timestamp and detail/link summary. Bottom navigation is hidden; Back returns to the root composer with any unsaved draft preserved intact. Bounded pagination, loading, empty, and read-error states are handled gracefully.
- **Saved-Note Detail (`NoteDetailScreen`):** Dedicated inspection destination displaying exact note text, source provenance ("Written on this device"), recorded timestamp, an explicit **Discuss with AI** handoff banner, a manual **Record a transaction** shortcut, derived detail interpretation rows, and pinned **Edit note** and guarded **Delete** actions.
- **Note Editor (`NoteEditorScreen`):** Dedicated editing destination with optimistic revision compare-and-set. Edits protect typed text upon conflict, require explicit confirmation to reload from disk, and guard against accidental Back navigation when unsaved changes exist.
- **Detail / Interpretation Editor (`NoteEventScreen`):** Dedicated child for extracting structured interpretations from a note. Requires an exact unique source excerpt, provides a neutral optional-amount hint ("Add an amount, or explain what is missing") rather than an aggressive premature validation error, detects out-of-date source text, and houses bank notification linking and manual transaction prefill routes.
- **Pending Bank Notification Chooser (`NoteDraftChooserScreen`):** Dedicated child for associating a note detail with an unconfirmed bank draft. Disables automatic matching; provides explicit **Attach** and **Reject** controls, keeps permanent record of user refusals, enforces that an accepted link must be unlinked before another is attached, and alters no financial ledger balance or confirmed draft state.
- **Explicit AI Chat Handoff:** Selected note detail pre-attaches a visible `ChatNoteContext` card to the top of `AiChatScreen` with **Remove attached note** and truthful notice ("This text is included when you send. Nothing has been sent."). Tapping handoff or saving a note starts zero hosted runs (`agent_runs = 0`); note content is included in a model prompt only upon explicit user send.
- **Design System & Localization:** Full English and Vietnamese parity, typography hierarchy, 48dp minimum touch targets, IME insets padding (`imePadding()`), light and dark themes, and non-color status cues (glyph + label). Obsolete inline event cards and stacked composer lists are retired. Shared vocabulary split into `NoteStrings` (132 parameters) to strictly remain within Dalvik method-argument limits while delegating from `AegisStrings`.

## 3. Audit of Round-1 Findings & Bounded Fix Resolution

### 3.1. Finding 1: Proposed Bank Notification Link Blocked Chooser Button (HIGH) — RESOLVED

- **Files / Lines:** `app/src/main/java/io/github/triet4p/aegisf/ui/NoteEventScreen.kt:893, 967`
- **Initial Defect:** In Candidate 1, `NoteEventLinks` evaluated whether a bank notification link was active by checking if any link was present that was not rejected (`ACCEPTED` or `PROPOSED`). Consequently, when a link was in the `PROPOSED` state (e.g., from background suggestion), `acceptedLink` evaluated to non-null, hiding the "Choose a pending bank notification" button. Because the Unlink action was only rendered for `ACCEPTED` links, a proposed link had no Attach, Reject, or Unlink surface, stranding the proposal in an unresolvable state.
- **Correction Applied:** 
  1. Updated `acceptedLink` predicate in `NoteEventLinks` to strictly check for `ContextLinkState.ACCEPTED`:
     ```kotlin
     val acceptedLink = links.firstOrNull { it.link.state == ContextLinkState.ACCEPTED }
     ```
  2. The button `Choose a pending bank notification` is now visible and enabled whenever `acceptedLink == null`, allowing notes with `PROPOSED` links to navigate to `NoteDraftChooserScreen`.
  3. In `NoteDraftChooserScreen`, proposed links display explicit **Attach** and **Reject** buttons, allowing direct resolution.
- **Verification:** 
  Added dedicated runtime instrumentation test `proposedLinkIsResolvableFromTheFocusedChooser` in `S104NotesJournalInstrumentedTest.kt:445-539`. The test seeds a synthetic pending draft, creates a `PROPOSED` link via `commandService.proposeLink`, navigates through Notes -> Saved notes -> Detail -> Edit detail, and verifies:
  - "Choose a pending bank notification" button is enabled and clicked.
  - Chooser opens, showing candidate card with "Suggested for this detail; choose Attach or Reject." (`337-proposal-chooser-1.5x.png`).
  - Tapping **Attach** transitions link to accepted, displays "Attached. The bank notification and the ledger are unchanged.", and updates card to "Already attached to this detail." (`337b-proposal-accepted-chooser-1.5x.png`).
  - Returning to Edit detail confirms "Linked to a bank notification" with **Unlink** action (`339-event-attached-1.5x.png`).
  - Tapping **Unlink** unlinks the draft. Re-entering chooser and tapping **Reject** permanently refuses the pair, displaying "Refused before. This pair cannot be suggested again." (`338-proposal-refused-1.5x.png`).
  - Returning to Edit detail confirms "Match refused (decision kept)".

### 5.2. Audit of Disclosed Deviations
1. **Anti-Stacking Architecture vs. Wireframe Stacking:** The approved render `07_quick_capture.webp` illustratively stacked a composer, an AI banner, a saved notes list, and a prototype notice on a single screen. Per owner one-screen/one-task direction and sprint plan lines 18–19 & 44–47, stacking unrelated workflows on the root was superseded. The root is strictly the composer + entry row; browsing is a focused child; detail owns AI handoff. This is fully justified and expected.
2. **Left-Aligned Tab Title:** The wireframe showed a centered title with Back and Trash icons. As a primary root destination in the 5-tab shell, Notes uses the consistent left-aligned title without Back/Trash (matching Home, Ledger, AI Chat, Review).
3. **Sky/Cyan AI Accent vs. Wireframe Purple:** The AI handoff uses the design system's primary cyan/sky accent (`#00A3FF`) rather than purple, maintaining palette consistency with S10.2 / S10.3 tokens.
4. **No Bulk Clear / Per-Row Delete:** Deletion is guarded inside the note detail; bulk clear was not invented without confirmation or requirement.
