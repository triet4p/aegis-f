The real-shell capture `device-archive-instead-result-dark.png` visibly shows, on the same archived `Food` row, both the badge `Archived · history kept` and the adjacent status line `Archived · history kept` (right column repeats the same two-word state). One screen/one-task clarity and the worker's own §11 correction claim require one badge wording plus one non-repeating caption on every archived row, with a re-opened capture proving it.

### F5 — MEDIUM: Deletion-safety wording is assessment-blocked: plan says "active references block unsafe deletion" while the frozen backend + UI deliberately permit informed delete

This is the explicitly disclosed deviation the assignment requires resolved, not silently waived. The operative plan sentence requires `active references block unsafe deletion`; the design mapping §1.3 requires `A category can be deleted only when zero stored transactions and zero active rules reference it`. The frozen implementation does the opposite by design: `CategoryDao.deletePermanently` detaches transactions (`categoryId=null`), removes referencing rules, and clears pending pre-set choices (`CategoryDao.kt:183-196`); `CategoryDeletionTest` asserts informed delete (`deleteCategory` returns `CategoryDeletionImpact(1,0,0)` while the record keeps exactly 45,000₫ uncategorized, rules go with the category, pending drafts lose the pre-set but stay reviewable); the UI gates the destructive button on impact-read success (`loaded != null`, `CategoryRulesScreen.kt:1579`) and offers Archive-instead, but never enforces a zero-reference hard block. The native + real-shell 45,000₫ preservation (record survives uncategorized, totals unchanged) proves financial safety, and the impact-first + explicit-destructive-confirm + Archive-instead UX is genuinely safer than a blind delete — but it does not satisfy either cited sentence as written. Round 2 must resolve the contractual conflict explicitly: either (a) enforce the zero-reference block for referenced categories (delete disabled/refused while `referenced == true`, Archive-only path, with native regression proof), or (b) retain informed-delete only with an explicit owner-accepted criterion/mapping deviation recorded as a durable plan decision stating that "block unsafe deletion" means impact-first + Archive-instead + explicit destructive confirm over the existing validated informed-delete backend. The reviewer cannot PASS the plan sentence on UX quality alone while the mapping sentence directly contradicts the shipped semantics.

Unlaunched system actions cannot be marked exercised on hook-rendering alone.
