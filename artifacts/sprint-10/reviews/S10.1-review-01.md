## 3. Audit of Consolidated Findings & Resolution

### Finding 1: Missing JavaScript Handlers in Web Prototype (Formerly HIGH)
- **Claim & Observed Gap:** Seven functions invoked by inline `onclick` handlers in `artifacts/sprint-10/prototype/app.js` were undefined (`filterLedgerByCategory`, `selectFormType`, `selectCategorySwatch`, `clearNotes`, `toggleReviewOrder`, `addNewCategoryPrompt`, `toggleCategoryTab`), triggering uncaught `ReferenceError` exceptions upon user interaction in Analytics, Manual Record, Capture Chat, Review Inbox, and Category Rules.
- **Resolution in Round 2:** All 7 functions were implemented with concrete state mutations and view re-renders. Verified via headless Chromium browser evaluation (`tab.evaluate`): all 7 functions exist, execute cleanly, and update prototype state without errors.

### Finding 2: Home Screen Information Architecture Redundancy & Clutter (Formerly HIGH)
- **Claim & Observed Gap:** The initial Home screen duplicated the same actions across three stacked rows: a 4-pill quick action card, an 8-item feature icon grid, and the persistent 5-tab bottom navigation bar. Actions such as "Ghi chép", "Nhập tay", "Báo cáo", and "Duyệt tin" (appearing 4 times) created redundant visual noise and failed to resolve card-stacking fatigue.
- **Resolution in Round 2:** The redundant 4-pill quick action row was completely removed. The Home layout was restructured: Top Bar -> Hero Balance Card (with privacy eye toggle) -> Primary 8-Item Feature Icon Grid (vector SVGs) -> Contextual Pending Review Alert (only when drafts wait) -> Recent Transactions Feed. Redundancy is eliminated; clear hierarchical spacing is established.

### Finding 3: Primary Action CTAs Cut Off on Deep Forms & Detail Screens (Formerly HIGH)
- **Claim & Observed Gap:** On `DraftDetailScreen` (`09_draft_detail.webp`) and `ManualRecordScreen` (`06_manual_record.webp`), the persistent 70px bottom navigation bar covered the lower screen, pushing primary buttons ("Xác nhận ghi vào sổ giao dịch" and "Lưu vào sổ giao dịch") out of the viewport.
- **Resolution in Round 2:** Deep detail and form screens (`screen-detail`, `screen-record`, `screen-draft-detail`, `screen-categories`) now hide the bottom navigation bar (`display: none`). Primary actions are anchored in a persistent sticky bottom CTA container (`.sticky-bottom-bar`) positioned directly above the Android gesture navigation pill. Both buttons are 100% visible and thumb-accessible upon screen entry.

### Finding 4: Backend Invariant Misinterpretation: Category Immutability (Formerly HIGH)
- **Claim & Observed Gap:** Worker report, specifications, and `CategoryRulesScreen` (`10_categories_rules.webp`) asserted that default categories were "Hosted locked / immutable", showing padlocks ("🔒 Hệ thống mặc định (Cố định)") and disallowing rename/delete. In reality, the Aegis backend (`CategoryEntity`, `WorkflowCommandService`) makes all categories user-defined and mutable (`CategoryAdded`, `CategoryRenamed`, `CategoryArchived`, `CategoryDeleted`). `ReviewCategoryOrigin` (`USER` vs `HOSTED`) applies strictly to draft suggestion provenance, not catalog immutability.
- **Resolution in Round 2:** Padlocks and "Hosted locked" claims were removed. Specifications and `CategoryRulesScreen` now explicitly reflect that all categories are user-owned and can be renamed, archived, or deleted (with referential safety checks). `ReviewCategoryOrigin` is correctly documented as draft review suggestion provenance.

### Finding 5: Developer & Operational Jargon on Everyday Screens (Formerly MEDIUM)
- **Claim & Observed Gap:** `DraftDetailScreen` displayed raw capitalized database enums (`"Trạng thái: ATTACHED"`) and technical section headers (`"NỘI DUNG GỐC TỪ NGÂN HÀNG (AUDIT)"`), violating Acceptance Criterion 23.
- **Resolution in Round 2:** Terminology replaced with friendly, user-centric copy: `"✓ Đã liên kết với sự kiện ghi chú"` and `"Nội dung thông báo từ ngân hàng"`. Internal enums and audit jargon removed from user-facing screens.

### Finding 6: Iconography System: OS Emojis vs Vector SVGs (Formerly MEDIUM)
- **Claim & Observed Gap:** Prototype and renders relied on heterogeneous, OS-rendered Unicode emojis (🏠, 📖, 📝, 📥, ⚙️, 🍜, 🛍️, 🏛️, 💳, ➕, 📊, ✨) which render inconsistently across operating systems and look unpolished.
- **Resolution in Round 2:** Replaced all emojis with a cohesive inline vector SVG iconography system (`SVG_ICONS`) across navigation tabs, feature squircle launchers, category swatches, bank logos, and status indicators.

### Finding 7: Target Device Simulation: iPhone vs Android (Formerly MEDIUM)
- **Claim & Observed Gap:** Prototype device frame simulated an Apple iPhone 14/15/16 Pro Dynamic Island (`.dynamic-island`) and iOS status bar, despite Aegis being an Android application targeting Android Compose edge-to-edge insets (`WindowInsets.statusBars`, `WindowInsets.navigationBars`, `WindowInsets.imePadding`).
- **Resolution in Round 2:** Device frame aligned with Android hardware specifications: centered camera punch hole (`.camera-punch-hole`), Android status icons (LTE, 98% battery, signal), and Android gesture navigation bar pill.

### Finding 8: Language Contract: English-First Baseline with Bilingual Parity (Formerly MEDIUM)
- **Claim & Observed Gap:** Prototype and specifications were hardcoded 100% in Vietnamese, deviating from `README.md:9` and `PLAN.md:89` which mandate an English-first user interface contract.
- **Resolution in Round 2:** Created bilingual `I18N` token dictionary in `app.js` with complete English baseline and Vietnamese localization. Added an interactive `🌐 EN | VI` language toggle in the prototype evaluation toolbar. Documented English domain entity baseline across design specifications.

### Finding 9: Secondary Settings Hub & Lifecycle Controls Under-Specified (Formerly MEDIUM)
- **Claim & Observed Gap:** `SettingsScreen` previously collapsed Hosted Provider settings into a static dropdown with a readonly dummy key, and reduced Bank Notification settings to a dead checkbox without system permission or package whitelist controls.
- **Resolution in Round 2:** Expanded `SettingsScreen`:
  - Bank Notification Listener: listener service toggle, system permission check trigger, test notification intake trigger, and allowed bank package whitelist (`com.VCB`, `com.mbmobile`, `com.techcombank.bb.app`).
  - Multi-Profile AI Configuration: provider presets (OpenAI, Gemini, Ollama, Custom), model name input, HTTPS endpoint base URL, masked Keystore vault key, reasoning effort, parallel tools toggle, and working test connection trigger with live status feedback (`#ai-test-status`).
  - Note event editing and note clearing lifecycle controls added to Capture Chat.
