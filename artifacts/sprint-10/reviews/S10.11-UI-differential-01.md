## 2. Differential probes (source read-only; no gate reruns)

1. **Event-API exhaustiveness.** All three consumers of the sealed progress types are exhaustive:
   `MaskedHostedGateway.kt:142-151` (forwards `Reasoning` text-free, gates `PublicText`),
   `BoundedWorkflowExecutor.kt:1994-2001` (`toWorkflowRunProgress` maps all five
   `HostedTurnProgress` variants), `AiChatScreen.kt:906-925` (all five `WorkflowRunProgress`
   variants). The UI sink is the sole `WorkflowRunProgress` consumer and is wired on every run
   path — new run `AiChatScreen.kt:400`, retry `:516`, clarification resume `:565` — so no run
   path silently loses the corrected progress display.
2. **Tool-arguments-ready vs result-applied across multi-call / error / clarification / settle.**
   `ToolCallCompleted` maps to the same running step (`BoundedWorkflowExecutor.kt:1997-1999`);
   `ToolStepFinished` fires once after every call of the turn is answered and applied
   (`:1287-1288`), including on the clarification break before `clarifyingOutcome` (`:1289-1291`).
   Paths that return before `ToolStepFinished` (tool failure `:1260-1270`, loop/budget stops) all
   settle through UI transitions that overwrite the status line — `failTurn` sets
   `statusLine = message`, `stopTurn` sets the stopped line, `completeTurn`/`clarifyTurn` null it
   (`ChatAgentRunState.kt:339-423` in `app/src/main/java/io/github/triet4p/aegisf/ui/`). No stale
   tool/reasoning label survives an error, stop, or settle; multi-call turns keep one label until
   the whole turn's results land (R2's assessment holds).
3. **Stop / no-late-events.** Sink is guarded by `isActive(token)` (`AiChatScreen.kt:905`);
   `stopTurn` clears `activeToken` before cancellation (`ChatAgentRunState.kt:405-423`), so late
   `Reasoning`/`ToolStepFinished`/chunk callbacks from a cancelling coroutine are ignored and a
   later `beginTurn` token cannot be touched by the old run. Consistent with carried S10.5 proof.
4. **Privacy display path.** Adapter emits presence-only `Reasoning` and never appends the delta
   text to the answer (`OpenAiChatCompletionsAdapter.kt:211-223`); the gateway forwards presence
   only (`MaskedHostedGateway.kt:144-150`); the UI sets fixed labels only (`AiChatScreen.kt:912-913`);
   a late reasoning signal cannot add a second line once answer text is visible
   (`ChatAgentRunState.kt:338-345`), and `appendChunk` clears the status line (`:285-294`).
5. **Protocol fallback interplay.** On a non-streaming route, `StreamingUnavailable` sets the
   honest label once per turn (`MaskedHostedGateway.kt:133-135`); `ToolStepFinished` then clears it
   while the run genuinely waits on the next model turn — truthful, no invented progress. Gemini
   `thought` parts and Responses reasoning-summary events are unchanged (carried accepted
   limitation, ChatCompletions-only signal; not re-litigated).
6. **Strings.** EN/VI parity confirmed for the new/carrying phase copy (`ChatStrings.kt:175-178,

   stored or traced" is contradicted by the slice's own trace evidence.** The worker record
   (workers/S10.11-UI-a1.md, Observable result) and the R2 gate row ("Reasoning text never
   displayed, stored, traced, or reconstructed", reviews/S10.11-UI-review-02.md §4) assert a
   system-level property, but `AgentTraceRecorder.providerStreamChunk`
   (`app/src/main/java/io/github/triet4p/aegisf/agent/AgentTraceRecorder.kt:123-146`) stores every
   raw SSE event verbatim into `agent_trace_events` via `TracingHttpTransport`
   (`…/agent/TracingHttpTransport.kt:80-82`), and Chat Completions SSE deltas carry
   `reasoning_content` text — the slice's own verification derives its numbers from exactly those
   stored payloads ("extracted from `agent_trace_events` chunk payload structure", 
   evidence/S10.11-UI-a1/verification.md §1; "763 reasoning deltas / 10,054 characters", §4). The
   adapter-level statement ("never read into the answer, trace or continuation", §2) is accurate;
   the unqualified record wording is not.

   - **Why it matters:** a future reader trusting the gate record would exclude
     `agent_trace_events` from a privacy sweep even though provider reasoning text persists there
     locally — directly relevant to Sprint 11's planned privacy hardening and backup/restore
     scope (the trace is private and excluded from today's export path per
     `AgentRunHistory.kt:487-491`, but backup/restore is a different path that must be checked
     against it).
   - **Boundedness:** the UI-display criterion of S10.11 is genuinely met (probe 4; all five
     frames opened); the trace design is pre-existing, unchanged by the 9-path slice (transport
     and recorder are not in the R2 manifest), deliberately documented
     (`AgentTraceRecorder.kt:108-113`: chunks never merged/truncated), and not re-litigated as a
     product defect. The correction is a record/annotation fix plus a Sprint 11 scope note — not a
     product code change and not a redo of the checkpoint.
