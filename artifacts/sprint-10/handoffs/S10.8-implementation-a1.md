## Decisions and rationale

- **Hard reference block, not informed delete.** The plan/mapping require active references to
  block unsafe deletion. The check is inside the delete transaction (race-safe), the command returns
  a structured Conflict, and the UI never offers a destructive action for a referenced category.
  Archive is the supported history path. This preserves the backend’s data integrity while
  implementing the binding criterion; unreferenced delete remains.
- **Rules mapping.** The stored rule is one normalized exact description (unique `patternKey`,
  lowercase/whitespace normalization). The plan now records this mapping; no prefix/wildcard backend
  was added. UI/README label matching truthfully.
- **Provider no-network.** The screen consumes the production connectivity signal; a false signal
  refuses before any transport call, with edits retained and no profile saved. This is a non-radio
  detection proof; no second airplane run was made.
- **System intents vs reconnect.** Safe destinations were launched/returned; reconnect would change
  system state and remains an explicit device-restricted N/A pending owner approval. Its refusal
  path is tested.
- **Provider test seam.** The screen accepts an `HttpTransport` defaulting to production; the native
  success test uses a deterministic transport, no network call.
