## Exact blocker / missing prerequisite

Owner permission for S10.5 verification is recorded, but **permission is not a credential**. The
app's Settings shows only presets; no profile is saved/activated, so `activeProvider()` is null and
an authorized request cannot be made. To close the mandatory criterion the owner must create,
save and activate a usable provider in the app's own Settings (provider, HTTPS endpoint, model,
credential). Then, with explicit confirmation:

1. reinstall the current candidate/test APKs if needed,
2. run `adb shell am instrument -w -e s105_real yes -e class
   io.github.triet4p.aegisf.ui.S105ChatInstrumentedTest#realConfiguredProviderStreamsProgressivelyStopsAndAcceptsTheNextMessage
   io.github.triet4p.aegisf.test/androidx.test.runner.AndroidJUnitRunner`,
3. pull/capture `530`–`532`, re-run the full suite, refresh the snapshot/report, and submit for
   review.

The opt-in test builds the real production adapter/gateway over an **empty caller scope** with an
isolated in-memory DB and sends only a synthetic non-personal prompt. It must not be run with
production query/command services or with unrelated notes/drafts in scope. No secret/profile
payload may be recorded.

## Tried and rejected hypotheses

- **"Selected" in provider Settings meant a saved active profile.** Rejected by the absence of any
  saved-profile row/list, `activeProvider()` returning null, and no provider/prefs file; it is a
  preset selection only.
- **A stable chat scope for all sends would simplify history while preserving sessions.** Rejected:
  the admission fingerprint would replay an identical repeated prompt instead of starting the
  requested next message; the design instead uses per-send scopes and a bounded cross-session
  recent-run read.
- **Restoring the latest durable conversation is token auto-resume.** Rejected: restore is a
  read-only transcript projection; RUNNING/PENDING rows render as interrupted and no provider job,
  continuation or Send is started.
- **The recreation timeout was only an offscreen lazy-item assertion.** Rejected by instrumented
  state logging (`initialLoadAttempted=false`): the initial-load effect was keyed on its own
  mutable flag and cancelled at its first suspension. Fixed by keying only on history.
- **A second `setContent`/keyed screen instance could prove process recreation.** Rejected as a
  test host artifact; durable read/restore is asserted through the real history read and
  history-loaded native capture, with actual process death left as a disclosed limitation until a
  durable real run exists.
- **The no-provider strip and stacked follow-up were acceptable.** Rejected after personally
  viewing captures: duplicate guidance and a second composer were removed; follow-up remains only
  beside a visible effect result.
- **A scripted local adapter could satisfy the provider criterion.** Rejected outright: actual
  authorized provider output is mandatory; the scripted adapter is test-seam evidence only.
