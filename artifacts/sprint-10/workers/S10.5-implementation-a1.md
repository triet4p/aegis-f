## 1. Scope delivered

- **Dedicated Chat destination.** `AiChatScreen` is a conversation only: title, History, New chat,
  provider/masking disclosure, transcript and one composer. Provider configuration is a focused
  child route with Back; no configuration panel is stacked into Chat.
- **Real streaming presentation.** The screen appends the executor's already-guarded
  `PublicText` chunks to one assistant turn, shows waiting, streaming, working, completed, stopped
  and failed lifecycle states, and keeps the composer's Stop action while a run is live. It never
  synthesizes answer text or a synthetic badge.
- **Stop semantics.** Stop clears the exchange token before cancelling the job, commits the
  received partial text as a stopped turn, records cancellation durably under `NonCancellable`,
  and drops every later progress callback because its token no longer owns the transcript. The
  next message is enabled immediately. Stored effects are never claimed as rolled back.
- **Durable history.** A bounded `findRecent` read lists the app's run rows across per-send
  sessions. The history sheet shows the request's own title, local time and lifecycle word and
  loads the stored conversation, replacing the transcript instead of appending. A fresh screen
  re-reads the newest durable conversation; an interrupted RUNNING/PENDING row is shown as
  interrupted and no run is resumed. A real defect found during verification — the initial-load
  effect was keyed on its own mutable flag, so its first suspension cancelled the load — is fixed.
- **Scrolling.** The transcript follows new chunks only while the reader is at the bottom. A
  manual scroll pauses the follow; a labelled jump-to-latest action restores it. Explicit Send
  re-enables following for the new turn.
- **Context.** The Notes handoff card is visible and removable. Before egress the screen re-reads
  the note by id; a changed, deleted or unreadable note blocks Send until the user removes it or
  explicitly uses the current text. Attaching starts nothing.
- **No provider / offline / failure.** No active profile or no validated network shows a
  persistent explanation and disables Send. Provider failure keeps typed and received text and
  explains the failure. Retry is bounded: after the durable attempt allowance is spent, the UI
  says so instead of silently starting an unlimited run.
- **Link interaction.** The settled outcome still renders the existing live effect cards with
  explicit, revision-checked Attach/Reject/Unlink; these cards re-read stored rows and never
  confirm a draft or change the ledger. A second follow-up form is no longer stacked beside a
  plain answer; it appears only when there is a visible effect to discuss.
- **Localization/design system.** Chat shell/state/history/composer copy is English/Vietnamese;
  the screen uses the shared theme, type scale, 48dp controls, insets/IME padding and non-colour
  lifecycle words. Chat outcome-card copy remains the existing English S9 copy (its shared cards
  are outside this task's copy boundary).

## 5. Missing prerequisite and limitations

- **Mandatory actual-provider criterion is unmet.** The app has no saved provider profile: the
  Settings list is only preset choices and `activeProvider()` is null. Main's recorded owner
  permission for S10.5 verification is not a credential. To close this criterion the owner must
  create/save and activate a usable profile in the app's own provider settings (provider, HTTPS
  endpoint, model, credential), or provide an equivalent explicitly authorized profile.
  Then the present opt-in test can run with `-e s105_real yes` (`530`–`532` captures expected);
  no secret may be placed in records. No substitute/synthetic output is offered.
- Real process death with a completed conversation was not exercised: producing a durable real
  run requires the missing profile, and the worker did not write synthetic run rows into the
  production database. The durable restore/history paths are covered by real in-memory Room
  instrumentation and a product defect found in that path was fixed.
- Network was not toggled (system-setting change not authorized). Offline UI is exercised with the
  screen's validated-network input in isolation; no request was attempted.
- Link Attach/Reject/Unlink runtime behavior is the existing S9.6/S9.3-proven card implementation,
  not re-proven here with a hosted run; the screen renders those cards unchanged.
- Chat outcome-card copy remains English; the new shell/state/history/composer copy is bilingual.
- Two new owner drafts were ingested by normal app reconciliation during verification and are
  preserved; exact counts are in `reconciliation.txt`.
