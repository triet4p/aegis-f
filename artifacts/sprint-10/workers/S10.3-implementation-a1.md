## 1. Scope delivered

- **Home (`HomeScreen`)** is a task launcher, not a dashboard: a time-of-day greeting, a Review bell with its waiting count, one compact exact current-month spending glance with a privacy toggle and a direct Reports route, and the eight labelled launchers sitting directly on the surface. No hero, enclosing launcher card, recent-record feed, separate warning card or duplicate shortcut block.
- **Reports (`AnalyticsScreen`)** is a focused analytics destination: month chevrons walk whole calendar months, a custom inclusive From/Through range is available, and the period is shown as exact dates plus day count. Four separate exact statements are shown — confirmed spending, confirmed income, net cash flow (income minus spending) and internal transfers — followed by a proportional category breakdown whose rows open their own confirmed spending records, and a daily spending chart with a text-list alternative. Internal transfers are never added to net; a draft is in no figure; a refused/reversed range reads nothing.
- **Ledger (`LedgerScreen`)** owns browsing: literal description search, type chips, a collapsible category/date panel, device-local day grouping, and the bounded page controls. Draft-stored records are marked `Draft` on the row. A top-bar action opens the existing manual-record form; tapping a row opens the receipt.
- **Receipt (`TransactionDetailScreen`)** shows the exact signed amount, confirmation status, type, category (with archived marker), device-local moment, provenance, note, record id and recorded/corrected times. **Edit** and guarded **Delete** are anchored at the bottom; a record that changed elsewhere reports the conflict and reloads instead of deleting an unseen row.
- **Drill scope**: an Analytics drill route carries its own period/category snapshot, so Back from the scoped ledger and receipt returns to the same Analytics month and figures, and the scoped list's page/scroll is retained by its own saveable route state.
- **Data-layer support**: `LedgerRecordQuery.searchText` adds a literal description substring dimension (SQL `instr(lower(description), lower(:searchText))`, never `LIKE`, so `%`/`_` are characters); blank input is no filter. No financial, provenance, revision, consent or masking contract changed.
- **Localization**: English baseline and Vietnamese parity for all four owned screens, including dates, month names, weekday names, status words, provenance and errors.
- **Design system reuse**: existing theme, typography, exact `₫` money primitive, launcher grid, glyphs, status chips and discard dialog; added only the left-chevron glyph and an optional amount prefix.

## 5. Limitations and rejected measurements

- The system font scale and night mode were never changed by this task; 1.5× is app-scoped instrumentation and dark is the in-app theme choice.
- Offline browsing was not forced by toggling a system network setting (prohibited). The four screens read only the local Room database and perform no network request; this is a code-path fact, not a toggled-network observation.
- Read-error UI is now exercised at the real UI boundary by dropping the ledger table in a separate in-memory database: both Reports and the receipt render their recovery copy and retry (see §1.1 and the two instrumentation screenshots). This is a controlled storage failure, not corruption of the owner's file; a genuine on-device storage failure is still not claimed.
- Process death was not forced (no `am kill` evidence); saveable state is covered by activity-recreation instrumentation from S10.2 and route state here.
- 501-row pagination was proven with an app-scoped in-memory database, not by writing 501 rows into the owner's ledger.
- Round-1 visual defects (KPI digit wrap, ledger metadata collapse, receipt mid-word action labels) are corrected in candidate 2 and re-captured; the directory retains the original round-1 captures (`100`, `110`, `132` etc.) beside the corrected `200`–`203` and instrumentation captures so the change is auditable.
- The greeting has no user name/avatar: the app stores no user identity, and inventing one would not be truthful. The Review bell is retained as the approved design status affordance; it opens the same Review destination as the launcher.
- Previous-period percentage deltas from illustrative renders were not implemented; they would require a second aggregate and an exactness story the acceptance does not require.
- Native PNGs are local-only under `.gitignore` (`/artifacts/**/*.png`); the checked-in evidence is the XML state index plus this report.
