### Outcome

- **Status:** `implementation_complete` (independent evidence review PASS, snapshot
  `71d2b5e66fe043ef249066234857f940956577fb52d604bfb3894e2746884ee8`; separate Bronze

- **Observable result:** In the real main app, a live Chat request now shows
  `Thinking through your request…` while the provider streams private reasoning, then a named tool
  step from the provider's announced call until the executor has applied that call's result, then
  answer text with `Receiving the reply…` as it arrives. Each state is driven by an actual provider
  or executor event. The stored runtime trace proves the cause it fixes: the owner's 13m41s run
  produced 2,679/3,002 reasoning deltas (34,745/37,203 characters) against 20/5 answer deltas, and
  nothing was reported for the reasoning phase. The new presence-only progress signal never
  displays reasoning text, never appends it to the answer, and the new UI path never stores or
  traces it; the waiting line is not drawn under a specific phase label; a late reasoning delta
  cannot add a second status line under visible answer text.

  **Record correction — 2026-11-12 (`S10.11-UI-record-correction-a2`, `S10.11-UI-evidence`
  conditional round 3, record-only):** the earlier wording "Reasoning text is never displayed,
  stored or traced" over-stated a system-wide property and is withdrawn in that form. The
  no-display/no-new-storage claim applies only to the new presence-only UI progress event
  (`HostedTurnProgress.Reasoning` → `WorkflowRunProgress.Reasoning` → fixed phase label). It is not
  a claim that reasoning text is absent from the app's storage: the pre-existing
  `TracingHttpTransport` → `AgentTraceRecorder.providerStreamChunk` path already persists every raw
  provider SSE event payload verbatim in the local private `agent_trace_events` store
  (`AgentTraceRecorder.kt`: the payload is "exactly what the endpoint delivered for that event
  (field name and data text), in wire order"; chunks are never merged, summarized or truncated),
  and the Chat Completions deltas carry `reasoning_content` text. This slice's own delta counts in
  `verification.md` §1/§4 are derived from exactly those stored payloads. That transport trace is
  pre-existing and outside the reviewed 9-path snapshot, unchanged by this slice — it is not a new
  UI signal or display path. Storage/retention, export-path and backup/restore implications for that
  trace are deferred to Sprint 11 privacy hardening. No product code, measured evidence, image or
  reviewed product hash was changed by this record correction.
- **Round-2 correction:** the UI-facing progress vocabulary no longer carries a misleading
  `completed` flag for a provider argument-completion event. `ToolActivity(name)` is one running

  applied, and the screen clears the label on it. Round 1's stale label (still shown after
