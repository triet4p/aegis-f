`{capture_id: 111, amount_vnd: 28000, merchant: null, anchor_date: 2026-10-21, anchor_time: 12:30,
status: INTERPRETED}`. The frozen expectation is the same reading with `merchant: "Highlands"`.
`qualificationSafetyStop` compares `capture_id, amount_vnd, merchant, anchor_date, anchor_time,
status` against the expected set and returns `unexpected_or_financially_incorrect_event` on the
merchant mismatch, which aborts the repetition. The scoring path compares the same six fields
(`exact_expected_events`), so this case would also be a task failure rather than a safety incident.

Root-cause chain, established from retained evidence plus production source:

1. `record_event` declares `merchant_ref` as "Source alias for an exact merchant substring of this
   occurrence, or the host-issued clarification source alias linked to it; JSON null when the
   optional merchant is unstated" (`tools/slm/s8_agent_tools_v3.json`).
2. `AgentToolRuntime.recordEvent` resolves it as a SOURCE-kind handle and rehydrates
   `merchant.display` into the stored merchant; `merchantWithin` requires an exact merchant
   substring of the selected source.
3. `AgentToolRuntime.valueRefsIn` (1860-1890) mints value references **only** for AMOUNT, DATE and
   TIME tokens found by `SensitiveVault.TOKEN_PATTERN`; merchants are not sensitive tokens and get no
   reference.
4. The only other merchant reference source is `registerClarification` (1231-1248), i.e. after the
   user answers an `ask_user` field `merchant` question.
5. The retained turn-1 `select_source` results offered exactly `amount`, `date`, `time` aliases, and
   the selected source carried the literal text "Highlands" with no alias. The model passed
   `merchant_ref: null` for both readings — the only valid value available — and `clarification:
   none`.
6. `a8-multi-01`'s frozen `v3_tool_flow` is `observe, select_source, make_time_anchor, record_event`
   with no `ask_user`, and the fixture supplies no clarification answer, so the expected merchant is
   not expressible through the frozen interface.
7. `a8-multi-01` is the **first** case in the frozen run order, so the single inexpressible field
   aborts all 24 slots before any other case is attempted. It is also the only case that must record
   a new reading with a non-null merchant; `a8-link-01`'s `Highlands` reading is pre-seeded as
   event 311.
