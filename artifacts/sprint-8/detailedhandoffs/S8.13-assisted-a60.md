## 4. Same-state continuation mechanism and host coordination

The assisted batch uses an **in-session pause**, not a replay or a rebuilt fixture:

1. After a slot's first attempt, the device writes the final first record to
   `<runDir>/<case>.json` and publishes `<runDir>/assisted/ready/<case>.json` containing the
   exact first-record digest.
2. The instrumentation process stays alive (same `ActiveRun`, Room DB, vault, reference
   registry, journal and provider conversation) and polls
   `<runDir>/assisted/decision/<case>.json` for up to `S813_ASSISTED_FEEDBACK_TIMEOUT_MS`.
3. The host monitor decides the slot with the frozen rubric and pushes either
   `pass_no_feedback` (slot never touched again) or one `fail_feedback` decision authored by a
   Main-dispatched worker.
4. The device validates the decision, calls `executor.followUp(...)` with that one message, and
   writes `<runDir>/assisted/<case>.json` (feedback, both records, phase accounting,
   cumulative safety). It never applies a second message or a further phase.

Host coordination is mandatory: keep the `run` process alive for the whole pass, answer each
request promptly, and set `--timeout-seconds` above the summed feedback window. A missing
response records `absent_timeout` and leaves the first verdict in place; nothing is invented.

## 7. Known limitations and failure modes

- In-session pause requires host coordination and a live instrumentation process; a missing
  decision records `absent_timeout` and leaves the first verdict (no fabricated message).
- A decision file present but invalid is recorded as a protocol error; the slot keeps its first
  verdict and the host record marks a hard stop rather than silently under-measuring.
- Only one decision per slot is ever applied; the device never mints a second follow-up.
- Assisted rows need separate semantic review (`phase: "assisted"`); without them the assisted
  pass count stays conservative (no recovery credit).
- The frozen gates remain evaluated on PASS@1; assisted gates are reported separately and
  choosing the assisted basis is an owner decision.
- The device smoke uses a local scripted provider double, so hosted model identity/transport is
  not claimed; the provider gate is documented as not applicable and effect-level safety is
  asserted directly.
- No hosted measurement has been performed; the later batch must not start before the review
  PASS and the Bronze exact-snapshot checkpoint.
