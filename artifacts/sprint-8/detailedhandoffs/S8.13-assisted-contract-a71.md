## 2. Root causes (confirmed against the accepted source)

- **A.** The exhaustive batch-continuation policy was bound only by the retained-prefix mode
  (`--exhaustive-from`). A fresh assisted full batch therefore took the default case-level
  fail-fast branch, so `a68`'s tentative `PROPOSED` link to the sibling duplicate stopped the
  whole batch after six slots.
- **B.** The first record was annotated with the local adjudication in the batch loop, but the
  assisted record was written only with the raw second-phase record plus a separate
  `assisted_adjudication` wrapper. The host scores `record["assisted_record"]` and requires
  `adjudication_version == s8.13-quality-vs-safety-adjudication/v5`, so every continuation
  reported `adjudication_binding: false` and no recovery could be credited.

## 3. Implementation

### 3.1 Fresh batch-continuation mode (A)

- `S813ExhaustiveContinuation.kt`: the host now declares the retained prefix explicitly
  (`S813_EXHAUSTIVE_RETAINED_CASE_IDS`; the non-empty sentinel `none` means "no retained
  prefix"). The pass plan derives from it (pass 1 = frozen order minus the prefix, passes 2–3 =
  the whole order), and the plan carries derived `totalSlots`/`measuredSlots`. The identity
  digest still binds attempt, snapshot, pass, selection, retained prefix and prior provenance; a
  skipped leading slot, a retained rerun, a forged digest or a different provenance is rejected
  before any effect.
- `S813QualificationInstrumentedTest.kt`: the batch safety stop now evaluates the bound
  continuation decision for a scripted or hosted batch alike, with the scripted effect-safety
  guard kept as a floor. A case-level rubric verdict never reaches the run-level stop.
- Host `s8_agent_v3_qualification.py`: `--no-fail-fast` binds the same contract for a fresh batch
  (`build_fresh_continuation`): retained prefix empty, 24 cases per repetition, 72 measured
  slots, total 72, no a55 provenance. `--exhaustive-from` keeps the retained six-slot shape. The
  two modes are mutually exclusive and recorded in the preflight/mapping/freeze identity; the
  live-run and slot accounting use the plan's own totals instead of constants.

### 3.2 Assisted record binding (B)

- `S813QualificationInstrumentedTest.kt` gained one binder `s813BindCaseAdjudication(record,
  adjudication)` used by both the first record and the assisted record, so both carry
  `adjudication_version`, `financial_safety_match` and `quality_findings`. The assisted binding is
  written before the assisted-record digest. The cumulative-safety expression is unchanged: the
  first phase's verdict can never be erased.
- Host `evaluate_case`: current records must carry the labels (`adjudication_fields_present`);
  immutable retained prior records are exempt and read exactly as recorded. The host still
  recomputes the verdict from `business_adjudication(mapping, post)`, the tool trace, masking and
  the post-state; the recorded fields are not trusted as a substitute.

### 3.3 Proof path (TEST_ONLY, no hosted call)

- Device: `S813ScriptedProvider` gained a host-declared per-case, per-phase script (tool/text
  steps with `$event`/`$draft:<visible id>`/`$pair` placeholders resolved from the real
  observations and tool results) and an explicit `S813_SCRIPTED_PROOF` full-batch mode that runs
  the real batch entry on the isolated package. The declared scripts travel base64-encoded because
  an empty `-e` value does not survive the adb shell; the runner also rejects empty instrumentation
  values now.
- Host: `run --scripted-proof --proof-plan <plan>` opens no credential socket and passes the
  declared script/decision plan. The real monitor decides slots with the same rubric (provider
  transport marked not applicable only for the declared proof), a separate coordinator answers
  only slots the monitor marked `feedback_requested`, and the unmodified harness validates and
  delivers each message. The actual `score` computes the 72-slot `assisted_evaluation`.
- `validate_live_run` and `validate_full_suite_debug_tree` accept the declared scripted proof's
  honest values (scripted transport, no wire capture) while every other identity, denominator,
  isolation, capture-integrity and secret check stays mandatory. The score is labelled
  `TEST_ONLY_PROOF_NOT_QUALIFICATION`; `provider_model_id` is null and
  `provider_protocol: scripted_local`.

## 6. Corrections made while proving (all on superseded, unfrozen attempts)

1. `require_not_none` call missing its label → one-line default parameter.
2. The fresh plan sent an empty retained-prefix `-e` value; the adb shell dropped it and shifted
   every later binding, so `am` printed its usage text and the runner's PIPE waited (Windows pipe
   deadlock). Fixed with the explicit `none` sentinel and a launch guard that rejects empty
   instrumentation values.
3. The full-suite debug validator read a missing `exchanges.jsonl` for a scripted case; the bearer
   scan now guards on file presence (a scripted proof has no wire body).
4. A `Clarifying` first attempt offered no follow-up because the scripted adapter returned the
   answered conversation with its pending call ids; it now returns an idle conversation exactly
   like the legacy double, so the one assisted follow-up is minted.

Each correction was followed by the required rebuild/device-preflight/freeze; the final freeze
above is the candidate. Superseded pass data was removed with its snapshot; no superseded result
is cited as evidence.
