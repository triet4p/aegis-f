## Capture semantics (what the reproduction will retain)

Per case directory under the debug root:

- `case.json` — TEST_ONLY marker, contract, mode `synthetic_only_full_bodies`, header values false,
  case id, declared tool names, synthetic scope tag plus prefix check, fixture id/digest, opened_at.
- `exchanges.jsonl` — one record per HTTP exchange, written from the transport before the adapter
  turns the guard verdict into a refusal: verbatim `request_body`, `response_body`, protocol,
  header **names**, `http_status`, decoded `assistant_message`/`assistant_reasoning`/`assistant_text`,
  `response_privacy_guard` (accepted, refusal reason, safe location, node type, counters), the
  `refusal_stage` (`inbound_response_guard` / `inbound_protocol_error` / `accepted`) and
  `token_provenance` (vault entry count, this turn's issued token set, per-candidate
  known/issued/seen/near-miss and, only when proven a fixture substring, the synthetic value).
- `turns.jsonl` — the harness's per-turn derived view: model echo, finish reason, usage, assistant
  text, tool calls with arguments/`arguments_json`, and the tool results attached to the turn that
  issued the calls.
- `effects.json` — postconditions, executor trace and verified effects.

Header values are never accepted by the recorder. The guard's own refusal reason, location and
no-effect postconditions are recorded unchanged; unknown/foreign tokens are still rejected and no
reasoning is accepted or ignored.

### Interpretation

The refusal is a content-dependent model behaviour: when the model paraphrases a masked reading as a
template with bare kind markers it collides with the guard's reserved `⟦…⟧` syntax; when it copies
issued tokens verbatim the same cases proceed (batch-18 8/24 versus this run 1/3, same freeze/model).
The correction candidate is versioned model education forbidding invented token syntax — never a
guard bypass. No correction was implemented; the frozen candidate and all retained records stay
untouched.

## Representation design/impact assessment (assessment only)

`evidence/S8.13-replan-a19/representation-impact-assessment.md` compares (A) the current
scope-bearing token, (B) short typed per-session aliases such as `[AMOUNT_1]`, (C) keeping the
envelope but removing the last required token copy in `select_source.quote`, (D) making token
candidacy definitional to the full mintable shape, and (E) display-only labels with references-only
authority. Grounded facts: all value arguments are already `r_…` registry refs; token text is
required only for the `select_source.quote` and is authority only in four host paths; the vault is
in-memory, masked text persists as display text, the cache key already carries the session tag
separately, and there is no local response cache.

Bottom line: B does not remove the refusal class (an invented alias must still be refused or
accepted) and loses positive foreign detection unless replaced by registry-only semantics plus an
evidence-taxonomy change, an escape rule for user-authored alias-shaped text and a history-display
invalidation rule. The smallest safe step (owner approval needed, not implemented) is D + C; the
only option that ends the class is E. No source, schema, fixture or expected-effect file was
changed for this assessment.
