   automatically. The skill catalog carries an explicit per-skill version, so `event-reading` went

   `repair_count`, recovery evidence and the selfcheck share one reading.
4. **Missing-only quality exception.** Main's scope correction is implemented exactly: an absent
   optional merchant with otherwise correct facts is quality-only; a merchant that is present but
   different from the mapping remains a financial/authority stop because it misattributes the
   reading. Versions: adjudication `s8.13-quality-vs-safety-adjudication/v3`, scoring
   `aegis-f-s8-agent-v3-qualification-scoring/v5`.
5. **One adjudicator per language, shared by both consumers.** Kotlin uses a top-level internal
   `s813CaseAdjudication` consumed by the hosted harness and the device preflight; Python uses
   `business_adjudication` consumed by `evaluate_case` and the selfcheck. Duplicate logic in the
   harness was removed rather than kept as a second copy.
6. **Fail-closed version binding.** The harness requires the frozen scoring asset's
   `adjudication.version`; the live-run/diagnostic records must carry the same literal;
   `evaluate_case` requires the case-record literal. A mismatch is a technical failure, never a
   silent regrade.
7. **Retain, don't rewrite, superseded candidates.** The failed first phone preflight and the
   passing `/v2`-wording candidate were renamed to `snapshot-22-preflight-failed-01` and
   `snapshot-23-earlier-candidate-01`; the corrected candidate froze into `snapshot-24`. Nothing was
   deleted or regraded, and no snapshot id was silently reused.
