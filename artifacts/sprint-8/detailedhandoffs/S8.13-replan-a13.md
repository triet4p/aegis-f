## Implemented policy (Main-approved scope)

The response guard receives a `HostedResponseMetadataPolicy` built from the adapter's own validated
configuration (protocol, configured model, and whether the configured endpoint is exactly the
OpenCode Go Zen route). Only these can be technical metadata, and only when the decoded value
satisfies the published schema:

1. protocol-declared root fields — opaque provider-assigned `id`/`responseId` as bounded nonempty
   printable ASCII (no assumed prefix), the configured `model`/`modelVersion` echo, the fixed
   `object` discriminator (`chat.completion` / `response`), and a nonnegative integer
   `created`/`created_at`;
2. the exact protocol usage-counter paths already shared with the adapters, as nonnegative integer
   JSON numbers;
3. only on the exact Go route, `usage.opencode.allowance` and `usage.opencode.list_cost` as finite
   nonnegative JSON numbers.

Never exempt: model content, reasoning, tool arguments, sensitive key names, unknown fields,
arbitrary nested `id`/`model`/`usage` fields, and accounting fields on any other route. Wrong type,
empty/non-ASCII id, wrong discriminator, fractional or negative timestamp, string/negative/non-finite
amount ⇒ `INVALID_PROTOCOL_METADATA` protocol error (surfaced as a sanitized `InvalidResponse`);
duplicate keys, invalid/trailing JSON and unsupported roots keep failing closed. Outbound masking and
the bare-digit ACCOUNT detector are untouched. The semantic scorer is now
`aegis-f-s8-agent-v3-qualification-scoring/v3`; business gates, case IDs, repetitions and
denominators are unchanged.

Evidence is value-free: accepted exemptions are reported per exchange as kind + allowlisted safe
location + node type; refusals keep the existing typed reason/kind/path/type/flag vocabulary.
