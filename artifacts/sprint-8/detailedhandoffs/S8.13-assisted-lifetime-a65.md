## 2. Root cause (inspected in the accepted source, not assumed)

In the accepted source (`ff787d9`), `runCase` (`S813QualificationInstrumentedTest.kt:965`) built
the first record and returned `S813CaseExecution(record, slot)` from inside its `try`, while the
`finally` at `:1183-1184` closed `laya` and `db`. The caller invoked `runAssistedStep(...)` only
after `runCase` returned (`:858`). The assisted continuation's record builder then read the same
case state after that closure:

- `postconditions(db, …)` at `:1152`, a suspend DAO reader (`:1606`);
- `layaEvidence(context, db, …)` at `:1160`;
- the same `wire`/boundary for masking evidence and the same `LayaInferenceLifecycle`.

The first state read after the closure is `postconditions`; Room's closed query context cancels
the DAO call, so the failure surfaces as `kotlinx.coroutines.JobCancellationException` and escaped
the batch loop, exactly matching the a63 abort. The accepted source's assisted step was also
outside the per-case error boundary (`:812` catches `runCase`, `:858` is not guarded).

Confirmed on device, not only by reading: the pre-fix build of the same full batch entry (with the
TEST_ONLY scripted provider and a host-delivered `fail_feedback`) failed at Time 1,164 ms with
`kotlinx.coroutines.JobCancellationException: Job was cancelled; job=SupervisorJobImpl{Cancelled}`
after the ready/decision exchange, with no assisted record
(`artifacts/sprint-8/evidence/S8.13-assisted-lifetime-a65/old-lifecycle/`).

A reverted-lifetime diagnostic with the new error boundary still aborted the same way
(`.../diagnostic-lifetime-reverted/`, Time 1,283 ms). This is deliberate and informative: the
closed-state failure arrives as a **cancellation**, and the boundary must not swallow a parent
cancellation. The correction is therefore the resource lifetime, not catching exceptions.

## 3. Implementation

### 3.1 Resource ownership (`S813AssistedContinuation.kt`, `S813QualificationInstrumentedTest.kt`)

- `S813CaseExecution` now implements `AutoCloseable` with a single-use `release` callback.
- `runCase` records `resources_opened`, defines `releaseResources` (probe event, then
  `laya.close()` and `db.close()` guarded by `try/finally` so the database is always closed even
  if Laya throws), and hands the live execution to the batch (`:1181-1188`, `:1375-1379`). A
  failure inside `runCase` still closes before propagating (`handedOff` guard).
- The batch wraps the case-local work (adjudication, first-record persist, assisted step,
  safety-stop evaluation) in `try/finally` and calls `execution.close()` exactly once after the
  assisted record is durable (`:852-906`). The inter-case delay runs after the release.
- `runAssistedStep` (`:1470+`) now runs while the case still owns that state, so the continuation's
  postconditions, masking and Laya evidence read the same live Room database.

### 3.2 Error boundary and cancellation

`runAssistedStep` publishes ready, awaits the decision, builds the record, applies at most one
feedback message and writes `assisted/<case>.json`. Non-cancellation failures are retained as an
`assisted_step_error` record (`S813_ASSISTED_STATUS_STEP_ERROR`) with the failure type, a redacted
detail/stack, the retained first verdict and no assisted record; the batch then continues.
`CancellationException` is rethrown untouched (`:1534`), and if the failure record itself cannot
be written the original failure propagates rather than a silent success. No `catch (Throwable)`
no-op and no swallow of parent cancellation was introduced.

### 3.3 TEST_ONLY full-entrypoint verification (`S813ScriptedProvider.kt` + scripted mode)

The smoke launches the **real** batch entry `runFrozenDevAndHeldoutSuites`, not a helper:
`S813_SCRIPTED_PROVIDER=aegis-s813-scripted-provider/v1` with a `reproduction` identity and the
isolated package. Validation requires exactly that contract, the isolated package and a
`reproduction` pass; otherwise the hosted path is unchanged. In this mode:

- the credential socket is not read; a declared unused placeholder feeds the unchanged provider
  config, and the report states `transport_protocol=scripted_local`,
  `credential_*=not_applicable_scripted_provider`, `scripted_provider.hosted_calls=0`;
- `runCase` receives a deterministic local adapter while the real masked gateway, executor, tool
  runtime, Room services, vault, reference registry, journal, debug capture and the in-session
  host pause run unchanged;
- the frozen hosted-provider identity/wire gates cannot apply, so the batch uses only an explicit
  effect-safety stop (no ledger row, nothing out of scope, no unexpected mutation) and records
  `provider_identity_gate=not_applicable_scripted_provider`; it never claims a rubric or PASS;
- the host declares `S813_SCRIPTED_PLAN=<case>=<decision>,…` (`pass_no_feedback`,
  `fail_feedback`, `no_decision`); the device requires full coverage and asserts each declared
  outcome;
- the scripted case must declare `select_source` and `ask_user` (INTERPRET_EVENTS). Its phase 1
  selects the case's captured source and asks for the missing time; phase 2 asks one further
  question through the same reference registry.

After the loop, `scriptedLifecycleEvidence` (`:1026`) asserts per case: first attempt
`Clarifying/time`; the declared assisted status/decision; for `feedback_applied` a
`Clarifying/time` assisted record with complete postconditions and Laya evidence; for
`pass_no_feedback`/`absent_timeout` no continuation; exactly one open and one release; and the
order `first_record_persisted < assisted_record_persisted < case_resources_released`. Distinct
per-case scopes are required. The probe is inert unless `enable()` is called by the scripted mode.
