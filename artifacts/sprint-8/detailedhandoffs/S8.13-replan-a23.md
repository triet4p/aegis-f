## What changed and why

### 1. Guard-channel classification (`MaskedPromptBoundary.kt`)

`internal enum class ResponseChannel { PROVIDER_REASONING, MODEL_ANSWER, MODEL_TOOL_ARGUMENTS, PROTOCOL }`
with `guarded = this != PROVIDER_REASONING`. Only `PROVIDER_REASONING` leaves are skipped by the
decoded-body content scan; every other channel is scanned exactly as the accepted S8.6 boundary did.

Classification per protocol (`channelForField` / `channelForNode`):

| Protocol | Reasoning (exempt) | Answer (guarded) | Arguments (guarded) |
| --- | --- | --- | --- |
| Chat Completions | `choices[].message.reasoning_content`, `choices[].message.reasoning` (whole subtree) | `message.content`, `message.refusal` | `message.tool_calls[].function.arguments`, `message.function_call.arguments` |
| Gemini | part with `thought: true` (whole part), `thoughtSignature` | non-thought part `text` | `functionCall.args` |
| Responses | output item with `type: "reasoning"` (whole item: summary, encrypted_content, content) | `output[].content[].text`/`refusal`, root `output_text` | `function_call.arguments` |

Mechanics: `collectReasoningIndex(body, protocol)` is a tolerant, depth-capped pre-scan that records
only structural positions (Gemini `(candidate index, part index)`; Responses `output item index`).
The existing strict streaming scan is unchanged apart from carrying `channel`, an array-index stack
and the index; it still enforces JSON validity, duplicate keys, depth, unsupported roots, root
metadata and usage-counter schemas, and keeps its first-failure refusal ordering. Nesting inherits
the parent channel (`channelForField` default `inherited`), so reasoning subtrees stay exempt and
answer/argument containers stay guarded. Unclassified fields remain `PROTOCOL` and guarded, which
preserves the previously accepted defense-in-depth for unknown fields and provider error text.

Second enforcement points are unchanged: `MaskedHostedGateway.maskTurnOrBlock` scans
`turn.assistantText` (before publication) and every `argumentsJson` (before dispatch);
`AgentToolRuntime` re-scans the argument object before executing a typed tool.

## Real-runtime observations / limitations

- Android's real strict `JsonReader` accepts a trailing comma (`{"…"},]`) that Robolectric's shadow
  rejects. This is pre-existing parser tolerance, not introduced here; any sensitive or unknown token
  in such a body is still refused. Proven structural refusals on device: truncated JSON, duplicate
  key, depth limit. Flagged for an owner decision if JSON strictness should be tightened separately.
- `org.json` serializes `/` as `\/`, so wire-text assertions must match `issued_mask_token_inventory`
  rather than the raw version literal.
- Robolectric is not a substitute for the device parser; the device class exists for that reason.
