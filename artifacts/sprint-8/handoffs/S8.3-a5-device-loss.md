## 3. Why this was blocked (resolved — see §11)

The phone disappeared from ADB during the third Gemini pass:

- `adb devices -l` → empty; `pm list instrumentation` → `no devices/emulators found`;
- an ADB crash-buffer read returned `protocol fault ... connection reset`;
- `adb reconnect offline`, `adb kill-server` + `start-server` did not restore it;
- `Get-PnpDevice -PresentOnly` shows no Android/ADB USB device at OS level, so it is a
  physical/USB disconnect rather than an ADB daemon problem;
- two bounded waits (`timeout 90` and `timeout 1800 adb wait-for-device`) both ended without a
  device.

Eight of Gemini pass 3's sixteen cases therefore have no application trace. Under the contract
a pass without real effects cannot be scored, so it is preserved as invalid and excluded from
every denominator. DeepSeek passes 2–3 were never started for the same reason.

## 7. Decisions and rationale

- **Used the Go gateway route after verifying it, and kept the wrong route as a diagnostic.**
  The Console `/inference` route returned 402, which is not evidence about a Go subscription;
  the documented Go route `https://opencode.ai/zen/go/v1` returned 200 with a native tool call
  and `billing_source: go`. No vendor inference API and no substitute model was used.
- **Kept every measured failure in its pass denominator.** The Gemma 429 was not retried inside
  the pass and not replaced by a later pass.
- **Reported the DeepSeek cap truncation as a transport-limit failure.** `finish_reason:
  length`, 1814 reasoning tokens against the frozen 2048 cap, 389-character arguments string
  truncated. Raising the cap afterwards would have made the set non-comparable.
- **Did not reconstruct missing application traces.** The interrupted Gemini cases have real
  generations but no effects; fabricating a dispatch would be a mock.
- **Rejected** prompt/case/rubric changes, re-scoring prior evidence, and any "best of N"
  selection among passes.
