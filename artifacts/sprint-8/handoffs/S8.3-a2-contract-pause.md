## 2. Why the attempt is paused

The frozen scorer compares observed calls to expected calls with exact list/dict equality.
The expected calls contain literal values the model cannot derive from any supplied input:

- `tools/slm/s8_workflow_cases.json:15` (case `s8-time-01`) expects
  `idempotencyKey: "case-time-01"` and
  `interpretation.normalizedText: "Book purchase"`.
- The same pattern appears in 9 of the 11 call-bearing cases (values such as
  `case-multi-01-event-1`, `case-link-01-propose`, `case-link-01-attach`,
  `case-laya-01`, `case-injection-01`, `heldout-multi-01-a`, `heldout-laya-01`).
- `tools/slm/s8_workflow_system_prompt.txt` (7 lines) never states any idempotency-key
  value and never states a required normalized-text string.
- `docs/sprint-8-evaluation-contract.md:26` requires exact required arguments
  “including revisions, spans, idempotency keys, limits, nulls, and ordered multi-call
  sequences”; `:38` requires “exact ordered call name/argument equality”;
  `:42` forbids post-result dropping/re-labeling.
- `tools/slm/s8_contract.py:486` implements the comparison:
  `if actual_calls != expected.get("calls", []): reasons.append("call_intent_or_arguments_mismatch")`.

A functionally correct call therefore cannot pass unless the model guesses the fixture’s
arbitrary key and free-form text. The proposed 80% frozen / 70% held-out correctness
targets are consequently not measurable as written. This is an S8.2 contract property, not
a model capability result, and no frozen case/prompt/denominator was edited to work around
it.

### 4.2 Measurement method

- Isolated per-case prompt directories and per-case raw output:
  `/data/local/tmp/slm/trials/S8.3-a2/<profile>/<case>/{stdout.txt,stderr.txt,samples.csv,status,pid}`,
  pulled to the host evidence tree and recorded atomically per case.
- Sampler: temperature 0.1, top-k 50, repeat-penalty 1.05, seed 42, `-no-cnv -sp --perf`,
  4 threads, `-c 4096`. Prompts LF-terminated and rendered with the S8.2 frozen family
  renderers (`qwen35_render` for MiniCPM/Qwen, `gemma4_render`, restricted `lfm25_render`).
- App fixture context supplied to the model: frozen date/timezone, capture id/revision and
  source text, and existing event/draft revisions — never expected arguments or literal
  keys/text.
- Memory: process `VmHWM`/`VmRSS` and `Pss` from `/proc/<pid>/smaps_rollup` sampled every
  200 ms by `tools/slm/s8_device_probe.sh`; device `MemAvailable` sampled separately.
  RSS and PSS are reported as distinct labels; `MemAvailable` is not a process budget.
- First result = wall time from submitting the prompt file to process completion of a
  complete generation. Cold start is the first case after provisioning; per-case cold
  distribution is n=1 because the phone rejects page-cache eviction without root.
