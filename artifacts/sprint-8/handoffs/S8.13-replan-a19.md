## Diagnosis (exact, not a tally)

In `a8-adv-03` exchange 0 the provider returned HTTP 200 and the turn's request had issued exactly
`⟦AMT-s813cand0fcb-0001⟧` and `⟦DATE-s813cand0fcb-0002⟧` (scope tag `s813cand0fcb`, vault entries 2).
The model's `reasoning_content` (2,077 chars, 443 reasoning tokens) contained the verbatim template:

> "Purchase ⟦AMT⟧ VND on ⟦DATE⟧"

- **Rejected tokens:** `⟦AMT⟧` (5 chars) and `⟦DATE⟧` (6 chars) at
  `response_body.choices[].message.reasoning_content` (node `STRING`), verdict `UNKNOWN_TOKEN`.
- **Recorder provenance:** `known_in_session: false`, `issued_in_this_turn_request: false`,
  `seen_in_response: true`, `near_miss_to_issued_this_turn: false` for both.
- **Near miss / altered copy:** none — zero near-miss candidates across all 9 captured exchanges;
  a bare marker has no scope segment or 4-digit suffix to alter.
- **Mechanism (grounded in unchanged guard code):** `scanInbound` strips known session tokens, then
  rejects any remaining full foreign shape as `FOREIGN_TOKEN`, then any remaining
  `⟦[^\s⟦⟧]{1,64}⟧` shape as `UNKNOWN_TOKEN`. `⟦AMT⟧`/`⟦DATE⟧` are token-like but not full token
  shapes, so the reason is `UNKNOWN_TOKEN`. The guard behaved correctly and fail-closed.
- **Content dependence:** the same freeze and model produced no refusal in the other two cases
  because the model copied issued tokens verbatim there. Batch-18 (8/24) versus this run (1/3) is
  consistent with sampling-dependent paraphrasing, not a deterministic per-case defect.
- **Effects preserved:** `a8-adv-03` recorded 0 events/links/operations/ledger/out-of-scope rows and
  no unexpected mutation; `financial_safety_match: true`; the runtime refusal stands.
- **Hygiene:** no `Bearer ` value, no `.env`/`PRIVATE KEY`/key-assignment marker in the retained
  payloads; `request_header_values_recorded` false on every exchange; header names only.

## Representation design assessment (assessment only, nothing implemented)

`artifacts/sprint-8/evidence/S8.13-replan-a19/representation-impact-assessment.md` compares the
current scope-bearing token with short typed per-session aliases and with two no-envelope-change
options, with exact file:line impact, and separates tested claims from hypotheses.

Key findings:

- every value argument is already a registry reference (`r_…`); token text is *required* only in
  `select_source.quote`; token text is *authority* in four host paths (clarification mining, value
  ref issuance, merchant display, quote/offset translation);
- short aliases (`[AMOUNT_1]`) do **not** remove the refusal class: an alias-shaped invention must
  still be refused (same friction) or accepted (weakening); and with no visible scope, foreign and
  unknown become indistinguishable, so foreign detection needs registry-only semantics plus a
  taxonomy change, an escape rule for user-authored alias-shaped text, and a history-display
  invalidation rule;
- smallest safe step, pending owner approval: (D) make token candidacy definitional — only the full
  mintable `⟦KIND-scope-\d{4}⟧` shape is a token candidate, so non-mintable bracket text is prose and
  cannot abort a turn while every resolvable shape still fails closed — plus (C) remove the last
  required token copy in `select_source.quote`;
- the only option that ends the class is display-only labels with references-only authority, which
  is a larger migration (four authority paths, quote rule, taxonomy, history invalidation).
