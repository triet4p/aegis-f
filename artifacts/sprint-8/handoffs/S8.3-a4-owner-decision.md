## 6. Decisions and rationale

- **Fixed a real bridge/harness defect instead of working around it.** `org.json.put(key, null)`
  removes the key, so optional trace fields vanished and the host derivation aborted the first
  run at case 5. The bridge now writes `JSONObject.NULL`, and the harness reads optional keys
  with `.get`. The aborted run's five real generations are preserved unscored under
  `evidence/S8.3/a4/aborted-run-1-minicpm/aborted.json`.
- **Adjudicated semantics from the actual text before scoring**, including the borderline
  `s8h-ambiguity-01` MiniCPM clarification (pass, with its imprecision recorded) and Qwen's
  `s8-match-02` (fail: it asked for draft descriptions so the model could decide rather than
  asking the user to choose). Rationale is written next to each profile's `adjudication.json`.
- **Did not change the first-result gate.** The harness gates first-result latency on a complete
  parse, not on semantic correctness; this is disclosed, and the Qwen cold value (120.77 s) is
  labelled parse-gated because its first case was prose without an envelope.
- **Did not run Gemma.** Official runtime is LiteRT-LM (not in this engine); the third-party GGUF
  was already measured at ~3.5 GB peak RSS in S5. Re-running would repeat a rejected approach
  without new evidence.
- **Rejected** injecting expected keys/text, rescoring a2 raw as v2, treating `adb shell`-merged
  output as evidence, and any mock/echo tool.
