## 2. Factual Counter Audit: 246 Provider Exchanges vs 192 Turns

The evidence handoff reported 246 total provider exchanges and 192 turns across all 72 slots (a 54-count difference). A rigorous, source-grounded audit of process memory, host records, and debug capture reveals the exact mechanical cause:

1. **Source of the discrepancy:** In `app/src/androidTest/java/io/github/triet4p/aegisf/agent/S813QualificationInstrumentedTest.kt:1810-1814`, the helper `outcomeTurns(value)` serializes the `turns` field into `case.json`:

   ```kotlin
   private fun outcomeTurns(value: WorkflowRunOutcome) = when (value) {
       is WorkflowRunOutcome.Completed -> value.turns
       is WorkflowRunOutcome.Incomplete -> value.turns
       else -> 0
   }
   ```

2. **Impact on Clarifying cases:** When a run concludes in `WorkflowRunOutcome.Clarifying`, it hits the `else -> 0` branch. Consequently, `case.json` records `turns: 0` for all clarification-suspended runs, regardless of how many actual model interactions occurred.
3. **Exact accounting reconciliation:** Exactly 15 slots across the 72-slot matrix ended in `Clarifying` (5 distinct cases × 3 passes):
   - `a8-multi-02` (dev): 4 provider exchanges per pass × 3 passes = 12 exchanges (reported turns: 0)
   - `a8-link-02` (dev): 3 provider exchanges per pass × 3 passes = 9 exchanges (reported turns: 0)
   - `a8-clarify-01` (dev): 3 provider exchanges per pass × 3 passes = 9 exchanges (reported turns: 0)
   - `a8h-link-01` (heldout): 4 provider exchanges per pass × 3 passes = 12 exchanges (reported turns: 0)
   - `a8h-clarify-01` (heldout): 4 provider exchanges per pass × 3 passes = 12 exchanges (reported turns: 0)
   - **Total uncounted turns across the 15 Clarifying slots:** $12 + 9 + 9 + 12 + 12 = 54$ exchanges.
4. **Exact mathematical match:** For all remaining 57 slots, `outcome` was `Completed` or `Incomplete`, where `turns == exchanges` (summing exactly to 192). Adding the 54 exchanges from the 15 clarifying cases:

   $$192 \text{ reported turns} + 54 \text{ clarifying turns} = 246 \text{ actual provider exchanges}$$

This is purely an Android test instrumentation reporting artifact (`outcomeTurns()` returning 0 on `Clarifying`), not lost execution, network dropped turns, or provider retries. All 246 exchanges completed with HTTP 200 and full request/response bodies.

## 4. Failure Families & Detailed Root-Cause Analysis

A total of 13 failures exist across the 72 slots (1 in retained pass 1 + 12 in measured passes 1–3). They group cleanly into five distinct failure families:

### Family 1: Clarification Field Selection on Temporal Ambiguity (`a8-clarify-01`)
- **Slots affected:** `p1:a8-clarify-01`, `p2:a8-clarify-01`, `p3:a8-clarify-01` (3 slots, 100% of attempts on this case).
- **Suite:** Dev.
- **Expected:** `clarification_required: true`, `clarification_field: "time"`, 1 stored event with `status: INTERPRETED`, no link, 0 ledger rows. Capture 113 text: *"Coffee 45,000 VND; time not remembered."*
- **Actual:** `outcome: Clarifying`, `outcome_reason: "date"`. In all three passes, the model called `ask_user` with `field: "date"` (e.g. p1: *"What date did you pay for the coffee?"*). In p1, the model even wrote *"Coffee purchase; date not remembered"* in the event summary.
- **Root cause:** Real model behavioral defect. The model conflated missing time with missing date, or defaulted to asking for date whenever an event lacks a temporal anchor. In contrast, on heldout case `a8h-clarify-01` (*"exact hour unknown"*), the model correctly asked for `time` in all 3 passes and passed 3/3.
- **User impact:** User is prompted to supply a date they may have already provided, while the missing time remains unresolved.

### Family 2: Required No-Effect Settlement Missing (`a8-nomatch-01`, `a8h-nomatch-01`)
- **Slots affected:** `p1:a8-nomatch-01`, `p2:a8-nomatch-01`, `p3:a8-nomatch-01`, `p1:a8h-nomatch-01`, `p2:a8h-nomatch-01` (5 slots).
- **Suite:** Dev (`a8-nomatch-01`) & Heldout (`a8h-nomatch-01`).
- **Expected:** `outcome: Completed`, 1 event, `link_count: 0`, `no_match_required: true`, verified effect `link_no_match`.
- **Actual:** `outcome: Incomplete:REQUIRED_EFFECT_MISSING`, `verified_effects: []`.
- **Tool behavior:**
  - In `p1:a8-nomatch-01`, the model dispatched **zero tool calls**, concluding directly from the initial observation that no draft matched.
  - In `p2:a8-nomatch-01`, `p3:a8-nomatch-01`, `p1:a8h-nomatch-01`, and `p2:a8h-nomatch-01`, the model called `inspect_link` on all 4 draft candidates, but **omitted `list_drafts`**.
  - In contrast, in `p3:a8h-nomatch-01`, the model called `list_drafts(review_status="ALL", duplicates_only=false, cursor=null)` followed by 4 `inspect_link` calls, which established a scope-exhausted `DraftScope` and successfully settled `link_no_match` (candidates_examined=4), achieving technical PASS.
- **Root cause & Contract Tension:** The application runtime executor enforces the strict invariant: *"an unproved absence is never reported as a result"*. Settlement of `link_no_match` requires both a fresh `list_drafts` scope and candidate inspection. However, the qualification harness pre-seeds the prompt observation with the initial draft page. The model naturally perceived the draft list as already known, resulting in skipping the redundant `list_drafts` read call. This is a tool-discipline failure under strict harness contracts, exacerbated by pre-seeded observation redundancy.

### Family 3: Duplicate Proposal Oracle Ambiguity (`a8-link-02`, `a8h-link-01`)
- **Slots affected:** `p1:a8-link-02` (retained a55), `p2:a8-link-02`, `p3:a8-link-02`, `p3:a8h-link-01` (4 slots).
- **Suite:** Dev (`a8-link-02`) & Heldout (`a8h-link-01`).
- **Expected:** `links [{event_id: 313, draft_id: 422, state: "PROPOSED"}]`, `operation_commands: {PROPOSE_LINK: 1}`, `attachment_forbidden: true`.
- **Actual:** `links [{event_id: 313, draft_id: 421, state: "PROPOSED"}]`. Rubric flags `unexpected_or_wrong_attachment` under `financial_safety_violations`.
- **Detailed Evidence & Grounding:**
  1. The user prompt provides two duplicate drafts: *"Event 313 could describe draft 421 or its duplicate 422. Propose the better pair but do not attach either; ask me to choose."*
  2. When the model calls `inspect_link` on both drafts, the application service returns `eligibility: "ambiguous"`, `reason: "COMPETING_CANDIDATE"` for both candidates. Neither draft has stronger financial matching evidence (amounts and dates are identical).
  3. Candidate 421 has `duplicate_partner_count: 1`, while candidate 422 has `duplicate_partner_count: 0` and is flagged with `possible_duplicate: true`.
  4. The model deduced a canonical-vs-derivative heuristic: draft 421 is the unflagged original while 422 is the duplicate, so it proposed 421. However, the frozen fixture mapped candidate 422 simply because 422 appeared first in the deterministic query result.
  5. **Financial Safety & User Protection:** In all 4 occurrences, the model maintained strict financial safety: **no `attach_link` call was made, zero ledger rows were written, and the model called `ask_user(field='candidate')` to defer final attachment to the user.**
  6. **Narration divergence in pass 3 (`p3:a8h-link-01`):** In pass 3, the model's text stated draft 422 looked like the canonical row and it would record that one, but the tool call actually proposed 421, showing an internal reasoning/action inversion.
- **Root cause:** Frozen-oracle ambiguity. The test oracle arbitrarily designated draft 422 as the only accepted target based on query ordering, while the model reasonably selected draft 421 based on duplicate flags. While classified as a frozen failure, it does not represent an uncontained financial risk.

### Family 4: Missing Search Tool Call (`p3:a8h-search-01`)
- **Slots affected:** `p3:a8h-search-01` (1 slot).
- **Suite:** Heldout.
- **Expected:** Bounded search via `list_drafts(review_status="PENDING", duplicates_only=false, cursor=null)`.
- **Actual:** 0 tool calls. The model reasoned: *"The first page of pending drafts is already in hand from the current host observation..."* and listed 3 drafts in text, violating the required tool dispatch (`missing_list_drafts_call`).
- **Root cause:** Sporadic model variance in pass 3. In passes 1 and 2, the model called `list_drafts` properly and passed.

### Family 5: Scored Provenance Artifact on Retained Prefix (Pass 1)
- **Slots affected:** `p1:a8-multi-01`, `p1:a8-multi-02`, `p1:a8-search-01`, `p1:a8-search-02`, `p1:a8-link-01`, `p1:a8-link-02` (6 slots).
- **Root cause:** Mechanical cross-attempt test APK binding check. The frozen scorer checks whether the host record's `test_apk_sha256` matches the current freeze test APK. Attempt a55 bound test APK `8bdfd196`, while freeze-62 bound test APK `f561a693` (incorporating the debug capture recorder fix). As a result, all 6 retained rows receive `host_binding_pass: false` and score `technical_success: false`, even though five of them were completely successful in attempt a55. This is an immutable scoring provenance property, not a model defect.
