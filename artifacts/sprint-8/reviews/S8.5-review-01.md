## 3. Substantive Verification Audit

### 3.1 Three Native Protocol Wire Implementations

The implementation in `app/src/main/java/io/github/triet4p/aegisf/provider/` delivers provider-neutral generation with three distinct native protocol adapters without shared abstraction leakage:

1. **Gemini API `generateContent` (`GeminiGenerateContentAdapter.kt`):**
   - Configured with `{model}` placeholder substitution (`endpointForModel()`).
   - Declarations lowered via `ProviderJson.geminiSchema`: `$defs`, `additionalProperties`, and schema references materialized; types mapped to OpenAPI uppercase (`OBJECT`, `STRING`, etc.).
   - Model turns parsed for `functionCall` parts with structured `args` and `thoughtSignature` retained verbatim for continuation.
   - Continuation: sends tool results in a `user` role turn containing `functionResponse` parts (with echoed `id` and `response` object). Note: the frozen S8.4 contract draft specified a `tool` role, which the live Google endpoint rejected (`Role 'tool' is not supported`); the adapter implements the verified `user` role encoding and records the correction in `docs/sprint-8-provider-adapters.md`.
2. **OpenAI Chat Completions (`OpenAiChatCompletionsAdapter.kt`):**
   - Encodes `messages`, `tools` in `{type: "function", function: ...}`, `tool_choice: "auto"`.
   - Assembles native `tool_calls` from choices; extracts `arguments` JSON strings.
   - Continuation: retains the assistant message with `tool_calls` and appends one `role: "tool"` message per call id with `tool_call_id`.
   - Privacy boundary: `reasoning_content` returned by models (e.g. DeepSeek via OpenCode Go) is deliberately excluded from conversation continuation so hidden reasoning never enters durable conversation state.
3. **OpenAI Responses (`OpenAiResponsesAdapter.kt`):**
   - Encodes typed `input` items, flat `tools`, and `tool_choice: "auto"`.
   - Parses typed `output` items: `message` (extracting `output_text`), `function_call` (extracting `call_id`, `name`, `arguments`), and opaque `reasoning` items.
   - Continuation: implements stateless item chaining, appending `function_call_output` items with matching `call_id` and string `output`.
   - Truncated function calls (`item.status == "incomplete"`) or response-level `incomplete` statuses force `ToolCallDisposition.TRUNCATED_TURN`.

### 3.3 Argument Assembly & Strict Dispatch Gate

The gate between LLM output and tool dispatch was verified in `ProviderWireSupport.kt` and `ProviderJson.kt`:

- **Complete JSONTokener Parsing:** `ProviderJson.strictObject` parses the JSON text and asserts `tokener.nextClean() == 0.toChar()`. Trailing characters, truncated closing braces (`{"value":`), or bare literals return `null` and are classified as `ToolCallDisposition.MALFORMED_ARGUMENTS`.
- **Schema Constraint Validation:** `ProviderJson.validateArguments` materializes local references (`$ref`) and verifies:
  - Required properties presence (rejects `{}` when `value` is required).
  - Prohibition of undeclared properties when `additionalProperties: false`.
  - Type checking (`integer`, `number`, `string`, `boolean`, `array`, `object`). Integers check for whole numbers within safe integer range.
  - Number bounds (`minimum`, `maximum`).
  - String constraints (`minLength`, `pattern` regex evaluation).
  - Enum constraint matching.
- **Dispatch Invariant:** `HostedToolCall.dispatchable` is a single derived boolean: `disposition == ToolCallDisposition.READY`. Calls with `MALFORMED_ARGUMENTS`, `SCHEMA_INVALID`, `UNKNOWN_TOOL`, `TRUNCATED_TURN`, or `FILTERED_TURN` have `dispatchable = false` and `arguments = null`. Adapters do not execute tools.
- **Mandatory Result Pairing:** `ToolCallAssembly.answerEveryPendingCall` enforces that every call ID in `pendingCallIds` is answered exactly once. Duplicate, missing, or extraneous tool results throw an immediate exception.

### 3.4 Per-Model Generation Budgets & Finish Semantics

- **No Shared 2048 Cap:** `HostedGenerationBudget.maxOutputTokens` is an explicit required parameter per model. Configured values in tests and live runs: 8192 (Gemini), 8192 (DeepSeek Chat), 4096 (GPT-6 Luna Responses). Codebase search confirmed 0 occurrences of a hardcoded 2048 constant in `io.github.triet4p.aegisf.provider`.
- **Explicit Capabilities Declaration:** `HostedProviderCapabilities` declares support for tool calls, parallel tool calls, reasoning budgets, and temperature. Requesting an undeclared feature (e.g. reasoning effort on a model that declares `supportsReasoningBudget = false`) throws `HostedConfigurationException` at configuration time.
- **Budget Finish Semantics:** Provider finish reasons indicating budget exhaustion (`MAX_TOKENS`, `length`, `status: incomplete`) are mapped to `HostedTurnFinish.Incomplete(reason)`. All calls within an incomplete turn receive `ToolCallDisposition.TRUNCATED_TURN` and cannot execute.

### 3.5 Classified Failure Vocabulary & Transport Safety

`ProviderFailures` and `UrlConnectionHttpTransport` isolate transport and remote errors:

- **Classified Failures:**
  - Transport errors (connection refused, timeouts) -> `HostedProviderFailure.Transport`.
  - 401/403 -> `HostedProviderFailure.Authentication`.
  - 402 -> `HostedProviderFailure.Account`.
  - 429 -> `HostedProviderFailure.RateLimited` (extracts `Retry-After` seconds).
  - 400/404/409/422 -> `HostedProviderFailure.Rejected`.
  - 5xx -> `HostedProviderFailure.Unavailable`.
  - 3xx -> `HostedProviderFailure.Redirected` (HTTP redirects are explicitly disabled via `instanceFollowRedirects = false` to prevent credential leakage to foreign hosts).
  - Model mismatch -> `HostedProviderFailure.ModelMismatch` (rejects hidden model substitutions).
  - Unparseable / non-conforming responses -> `HostedProviderFailure.InvalidResponse`.
- **Diagnostic Sanitization:** All provider failure details are bounded to 400 characters and sanitized via `authentication.redact()`.
