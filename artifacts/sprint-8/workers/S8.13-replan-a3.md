## Root-cause summary

The bounded read-only diagnosis is `artifacts/sprint-8/evidence/S8.13-replan-a3/diagnosis.md`. Proven issues include:

1. The adapter attaches the trusted timezone to date-only anchors, while the event validator rejects a timezone without a time. B2 date-only tasks consequently received “A stated time zone needs the time it anchors” and no event was stored.
2. Distinct event updates in one workflow use one session operation key; the command service correctly conflicts on the same key with a different request. B2 multi-event case stored the first event and conflicted on the second.
3. Both repair/replay repeats were not actually dispatched in B1/B2; the model described a hypothetical no-change instead. Frozen service replay is safe for an identical same-key/same-request call, while the frozen skill does not clearly separate requested idempotent replay from a corrected retry.
4. Frozen prompts and data contain contradictions: heldout `bus fare` versus stored draft `coffee at noon`, and link prompts/expected IDs versus contradictory amounts/duplicate candidates. These were preserved, not fixed. The expected “yesterday” date in `a8-multi-02` also lacks an absolute reference date in the actual prompt; that under-specification is labeled as a hypothesis in the diagnosis.

The diagnosis proposes minimal owner-approved follow-up options and discriminating **non-API** tests. None was implemented or run under the read-only stop decision.
