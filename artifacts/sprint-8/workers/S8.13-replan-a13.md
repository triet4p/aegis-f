## Implemented boundary

The response guard now receives a value-free policy built from each adapter's own validated
configuration. Three things can be treated as technical metadata after schema validation: the
selected protocol's documented root fields (opaque provider-assigned id as bounded nonempty
printable ASCII, the configured model echo, the fixed object discriminator, a nonnegative integer
creation timestamp), the protocol's exact usage-counter paths with nonnegative integer JSON numbers,
and — only when the configured endpoint is exactly the OpenCode Go Zen route — the two
`usage.opencode` USD amounts as finite nonnegative JSON numbers. Unknown fields, arbitrary nested
`id`/`model`/`usage` lookalikes, model content, reasoning, tool arguments and sensitive keys stay in
the decoded scan. Malformed metadata is a safe `INVALID_PROTOCOL_METADATA` protocol error; duplicate
and invalid JSON keep failing closed. Outbound masking and the bare-digit ACCOUNT detector are
unchanged.
