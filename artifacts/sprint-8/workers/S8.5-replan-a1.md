## Acceptance Criterion Mapping

1. **Live calls through each protocol complete a bounded multi-turn tool-result exchange.** All three ran through the real adapters and transport: one function-call turn, the native result item, then a result-fed complete answer. Evidence: `artifacts/sprint-8/evidence/S8.5/a1/live/`.
2. **Malformed/partial calls execute nothing.** The adapter is the only gate: `HostedToolCall.dispatchable` is true only for `READY`; partial JSON, missing/extra/wrong-typed members, bounds, patterns, unknown tools, truncated turns and provider-truncated items are separate non-executable dispositions. Adapters never execute tools. Tests: `ToolArgumentValidationTest` plus each adapter's malformed/truncation cases.
3. **Configured endpoint/model identity is truthful.** Endpoint/model/credential/capabilities are explicit and validated; the model id is sent verbatim; the provider's echo must match or the result is `ModelMismatch`/`InvalidResponse`. Live evidence shows the configured model echoed on both turns for all three protocols.
4. **Native function calls/results, multiple calls, complete assembly, finish/incomplete/error states, required continuation.** Gemini `functionCall`/`functionResponse` with `thoughtSignature` retention; Chat `tool_calls` plus one `tool` message per call id; Responses typed `function_call`/`function_call_output` with retained items. Multi-call turns are tested; every pending id must be answered exactly once.
5. **Explicit capabilities and adequate per-model budgets; no shared 2048 cap.** `maxOutputTokens` is required and per model (live: 8192 Gemini, 8192 chat, 4096 Responses); reasoning effort/temperature/parallel settings are sent only when declared. A requested undeclared feature is a configuration error. No 2048 constant exists in the provider code.
6. **Provider errors distinct from model/tool failures.** `HostedProviderFailure` separates transport, authentication, account, rate limit, rejection, server, redirect, provider state, model mismatch and invalid payload; failure details are bounded and credential-redacted. Per-call model problems are dispositions, not provider failures.
7. **Compatible live Responses endpoint identified and authorized, not mocked or silently replaced.** Primary OpenCode Go documentation lists the Go Responses route (`https://opencode.ai/inference/go/openai/v1/responses`, legacy alias `/zen/go/v1/responses`). Discovery with the existing Go key confirmed the route serves `gpt-6-luna` with `billing_source: go`, and the live exchange used `https://opencode.ai/zen/go/v1/responses` — the Go product, not Console `/inference`, not a vendor endpoint, no invented authorization, no protocol/model substitution.

### Observed contract correction

The frozen S8.4 contract says Gemini tool results travel under a `tool` role. The live endpoint rejects that role (`Role 'tool' is not supported. Please use a valid role: … MODEL, USER`) and accepts the `functionResponse` part in a **user** turn, which is what the adapter implements; the live exchange proves the working encoding. The checkpointed contract text was not edited; the correction is recorded in `docs/sprint-8-provider-adapters.md`.

### Limitations

- Live smoke is synthetic and gated; it is not model qualification, reliability sampling, Android-runtime evidence or a production privacy claim.
- No streaming, retry/backoff, prompt caching, masking, executor policy, tool adapter, persistence or settings UI in this task.
- Closing a conversation after a completed (non-tool-call) answer is not part of the current continuation API; the runtime only needs tool-result continuation for S8.5.
